# 微信资料采集与任务编排（2026-10-25）

## 目标与页面职责

沿用原上岸鸭工作台和原任务数据，不重建任务系统、不清空任务、不改写四象限和清单。将工作流按职责串联：

1. **收集任务**：本机授权的微信历史目录/群消息；按群名、关键词检索，保留群名、发送者、时间和原文。历史数据范围只覆盖本机当前授权且已同步保留的记录。
2. **资料与链接解析**：从微信分享消息提取标题、描述、链接；链接交给现有资料解析入口逐条读取，展示成功/失败，不把标题预览冒充正文。
3. **任务关联与执行**：将选中的原文交给原 AI 卡点助手；结合原有任务、Obsidian 笔记、飞书文档、来源链接和精力/截止日期给出候选任务与排期。新任务须由用户确认后写入，不覆盖旧任务。

## 本次修复

- 本机 8877/8892 页面请求同源 `/api/wechat-private`；移除失效的 8901 转发。
- 历史目录初始化返回 `initializing` 时，前端轮询状态；错误状态不伪装成连接成功。
- 历史消息支持多选，最多 20 条一批交给现有 AI 助手分析。
- 分享消息尝试解析 XML 中的标题、描述、URL；图片/视频/语音仍明确标注为未转写。
- 公网页面不能直接读取用户电脑的微信或 Obsidian。本机读取须在本机页面和本机桥接中进行；公网访问本机功能时应提示边界，而不是跨越到 localhost 或显示假成功。
- 读取和分析只读，不发送微信、不删除记录；新任务和截止日期由用户确认。

## 任务编排建议

1. **资料核验**：先读活动规则、群消息、示例链接；记录每条证据的来源与读取状态。
2. **创作准备**：按用户原计划的两个抖音账号分别建立任务；每日每账号最多 3 条，不能把上限当成必须完成量。先确认作品实际属于单品服装搭配，再确定口播/实拍/对比/关键帧等表现形式。
3. **制作与质检**：把群里明确的调色、口播、素材替换、教程要求作为待核验的制作步骤；不将零散聊天推断成官方要求。完成后检查核心玩法、视频/字幕、发布文案与活动入口。
4. **发布与回填**：发布后记录时间和链接；在 3 日观察窗内查看抖音主端官方播放数据；满足 >500 后按活动入口回填。未满足或未到观察期的任务保持待跟踪。
5. **精力排期**：先安排资料阅读和脚本/素材准备，再制作、审核、发布，最后安排 3 日结果复查；具体时段根据现有任务截止日期、用户实际精力和历史耗时调整。
6. **结束时间**：活动截止日期保持「待群通知」；收到新通知后更新任务，不预设结束日。
