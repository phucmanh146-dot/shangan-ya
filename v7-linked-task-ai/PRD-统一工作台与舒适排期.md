# 上岸鸭统一工作台与舒适排期 PRD
版本：2026-10-27 · 状态：实现版需求与验收清单

## 1. 产品目标
将主工作台与 V9 工作台的高频能力整理为一套一致的导航、视觉和任务上下文。主页聚焦“今天要做什么”；“舒适排期”成为左侧一级功能，不再把完整精力分析面板铺在主页。用户可通过明确的文字链接在任务、资料、AI 解卡、历史复盘之间跳转，减少重复输入与迷路。

## 2. 用户问题
- 重任务、卡壳与任务切换消耗精力，理想化计划容易挤掉后续任务和休息。
- 排期功能塞在主页，信息密度过高；两套工作台入口和交互不统一。
- 任务、资料和 AI 解卡之间跳转成本高，容易重复查资料或重新描述问题。
- 不能把没有真实读取的本机笔记、没有发生的完成记录或未验证的模型连接显示为成功。

## 3. 信息架构
左侧导航固定，主页面按同一 SPA 视图切换：
- 每日清单：任务创建、状态、日期与实际执行记录。
- 舒适排期（新增一级入口）：状态估算、真实任务选择、可用时间、休息/娱乐/缓冲、排期预览、个人规律。
- 四象限、截止清单、收集任务、番茄钟、习惯、历史与复盘。
- AI 工作区：任务解释、拆解、生成下一步动作。
- 资料中心 / 知识库：来源搜索、原文核对、关联任务与笔记。
页面导航按钮、面包屑式文字链接和“返回任务清单”入口统一；跨视图跳转复用现有 switchAppView，不再为每个功能另造导航。

## 4. 本次 UI 改动
- 移除主页上的“今日节奏与弹性排期”展开卡片；旧模块保留隐藏兼容，避免破坏历史脚本依赖。
- 在主工作台与 V9 左侧导航加入“舒适排期”。
- 新增独立舒适排期视图：标题与状态、主行动按钮、四个能力入口卡片，以及指向每日清单、资料中心、AI 工作区、历史复盘的文字链接。
- 复用深绿色、暖白、鼠尾草绿的视觉系统；保持左侧导航结构，不重做已有任务页。
- 复杂排期仍以分步对话框完成，避免首次进入就展示过多字段。

## 5. 核心用户流程
1. 用户从左侧“舒适排期”进入专属视图。
2. 点击“开始舒适排期”，进入五步流程：状态 → 真实任务 → 时间窗口 → 预览 → 个人规律。
3. 状态步骤读取可用的计时、卡壳、疲惫与最近反馈；用户可快速反馈“清醒 / 有点慢 / 读不进去 / 被抽干”。
4. 任务步骤只从原有未完成任务选择，并显示任务复杂度、优先级和估时依据。
5. 时间步骤设置开始/结束、固定事项、缓冲、放空/娱乐与短休间隔。
6. 预览展示工作段、短休、发呆、娱乐、弹性缓冲，以及未安排任务和原因。
7. 用户确认保存排期草案后，才写入计划记录；不得自动完成或删除任务。
8. 可从流程中的文字链接返回任务清单，或前往资料中心和 AI 工作区继续解卡。

## 6. 排期与状态规则
- 状态是启发式估算，不是脑电检测、医学判断或精确的生理测量。
- 优先级依据真实任务数据、历史实际耗时、连续用脑、卡壳和最近反馈；数据不足时标记低置信度并采用保守估时。
- 重任务拆成工作段；在工作段之间安排短休。恢复时长不保证对每个人同样有效。
- 每天为发呆、娱乐、固定事项和突发情况预留时间；不以压缩休息来补齐任务。
- 低精力时优先恢复或安排低负荷任务，高负荷任务可暂缓；暂缓不等于放弃。
- 个人规律必须由用户真实记录积累得出；样本不足时显示“待校准”，禁止编造精力曲线。

## 7. 资料与 AI 的边界
- 资料中心负责搜索、来源与原文核对；AI 工作区负责解释和生成下一步动作。
- 任务名称、选中任务和真实笔记正文可作为上下文，但只在用户主动发起后带入 AI 输入框；不擅自发送。
- 本机 Obsidian 读取依赖本机后端接口。未连接、路径缺失或正文为空时，必须显示具体失败原因，不得伪造“已读取”。
- API Key 和模型配置不在 PRD 展示中明文回显；任何外部请求需遵循用户现有授权。

## 8. 数据与状态
沿用当前账号/任务存储和已有历史字段，不另建一份互不相通的任务数据库。排期草案应记录日期、选中任务 ID、时间窗口、各时段、缓冲与娱乐分钟、被暂缓任务及原因、算法版本、估算置信度。实际完成与耗时必须来自真实操作记录，不能由排期生成自动推断。

## 9. 验收标准
- [ ] 主工作台和 V9 的左侧导航均出现“舒适排期”一级入口。
- [ ] 主页不再显示完整的舒适排期展开面板或重复入口卡。
- [ ] 点击左侧入口后进入独立视图；返回每日清单、资料中心、AI 工作区、历史复盘的链接均可切换到对应视图。
- [ ] 点击“开始舒适排期”可打开现有五步交互；关闭后仍停留在舒适排期视图。
- [ ] 任务选择只显示原有待办；没有任务时提供去每日清单的明确链接。
- [ ] 保存排期不会自动将任务标记完成或删除。
- [ ] 手机宽度下卡片单列，按钮和链接可触达，不出现横向溢出。
- [ ] 本机资料读取失败时明确显示错误；不得假装连接成功。
- [ ] 缺少精力历史时标记低置信度，不生成虚假的个人曲线。
- [ ] JavaScript 语法检查通过；部署后需对两个页面做实际点击验收。

## 10. 本次范围与非目标
范围：统一导航入口、独立舒适排期视图、跨页面文字链接、保留现有五步排期流程、PRD 和验收清单。
非目标：重写整个任务引擎；声称实时检测脑电/情绪；自动访问本机文件系统；自动发送 AI 请求；在未经真实验证的情况下声称 Obsidian 或外部模型已连接。

## 11. 风险与后续
- 当前 UI 与路由改动不等于所有交互已完成浏览器验收；部署后仍需逐项点击验证。
- 个人精力模型需要真实记录持续校准，不能仅凭一次主观反馈得出长期结论。
- 若后续希望把排期从对话框改成整页分步流程，应保留任务上下文、返回路径与草案状态，避免关闭页面丢失选择。
