# 上岸鸭 AI 工作区改造记录（2026-10-22）

## 1. 飞书《上岸鸭技术改进》逐条理解

原文要点：
- 模型 API 需要真实接通，问答时不应强制关联 Obsidian。
- 用户上传视频、图片、语音、Word 等材料后，AI 要给出答案，并能用通俗语言解释。
- 视频内容要能解析；目标体验接近通用聊天助手，而不只是静态演示。
- 微信本机接入目前存在困难。

对应产品方案：
1. **独立 AI 对话**：普通问题默认不读取 Obsidian/微信/任务数据；只有用户明确选择或主动提交材料时才读取。
2. **模型接入**：服务商下拉选择、API 文档直达、实时读取模型列表、用户选择模型、真实请求验证后才显示已连接。
3. **多模态 SOP**：Word/PDF/文本、图片、视频关键帧、音频转写；对未成功读取的材料明确提示，不能声称已看过或听过。
4. **语音答疑**：浏览器语音输入转文字、回答朗读；音频文件转写依赖已配置的本机识别或语音 API。
5. **卡点救援 SOP**：复述目标和卡点 → 区分事实/推测/缺失信息 → 一次执行一步 → 用户反馈 → 验收 → 复盘并沉淀。
6. **外部来源**：允许用户主动粘贴网页/飞书/视频链接，说明读取状态与来源；登录态或权限受限时不假装读取成功。
7. **微信**：公网服务无法凭“电脑已登录微信”自动获得本机聊天内容。必须通过用户授权的本机代理/接口读取；公网端与本机端要有真实配对状态，不能用假状态代替。

## 6. 2026-10-22 晚间：多模型 AI 团队接入

本轮按“不同模型承担不同任务、失败时尝试备用模型、结果必须如实显示”的要求增量改造，未删除原有工作台或对话功能。

新增/修改：
- `ai-p2.html`：模型 API 设置中新增可展开的多模型分工配置，包含深度推理、联网研究与证据综合、图片/视频画面理解、代码分析与修复四个角色；每个角色可填自己的 API 地址、模型 ID、API Key 和接口类型，也可通过真实 API 读取模型列表。
- `p2-config.js`：读取角色配置（不回显密钥）；独立角色保存前逐个实际调用 API 测试；显示每个角色的成功/失败原因；支持清除独立角色但保留主模型。
- `p2-chat.css`：多模型配置的响应式网格、可滚动对话框样式。
- `rescue_service.py`：新增按角色保存的模型配置、公开状态（不含密钥）、真实连通测试；未验证的角色不会被路由使用；专家模型配置失败时保留之前可用配置。
- `p2_chat_backend.py`：图片/视频画面优先路由视觉角色；代码、API、报错和部署问题优先代码角色；联网搜索优先研究角色；其他复杂问题优先推理角色；普通问题走主模型。专家模型失败后最多尝试主模型一次，并把实际角色/是否回退返回给前端。
- `p2-chat.js`：显示实际使用的模型角色与是否回退；顶部连接状态显示已验证的专家模型数量。
- `local_server.py`：本机启动时自动尝试连接已运行的 Hermes 网关；公网 worker 不会自动接入用户电脑的 loopback 网关，并明确禁止公网 worker 访问本机回环模型地址，避免把远程服务变成 SSRF 代理。
