## 我们想解决什么

团队往往已经有目标、有成员，也做了一部分工作，却仍然说不清：现在完成了多少，距离要求还差什么，今天每个人应该做哪一步。

上岸鸭的目标是把这些问题连起来：先理解项目，再理解参与项目的人，最后生成可执行、可验收、可调整的行动安排。具体比赛、岗位和任务由真实材料决定。

## Agent 的含义与工作原理

这里的 Agent 是围绕目标持续工作的智能体。它需要读取材料、调用检索等工具、生成行动方案、记录执行证据，再根据反馈调整下一步。

1. **判断项目现状。** 收集现有作品、完成记录、适用规则与优秀案例，核对来源，形成“现状—差距—目标结果”。完成度必须对应明确的验收项和证据，缺少材料时说明无法判断。
2. **理解每一个成员。** 了解他负责什么、认为应该怎么做、已经会什么、缺什么、已经完成什么，以及愿意投入多少时间。
3. **生成个人任务和技能补齐路线。** 将项目缺口与成员能力、时间匹配，给出要做的事、必要资料、第一步操作、预计时间和完成标准。
4. **陪伴执行并更新。** 成员自己选择今天的任务；遇到卡点时补充描述、截图或录屏；系统依据进度与反馈调整尚未完成的安排。

优秀案例用于帮助理解质量标准，正式要求以比赛主办方当届材料为准。以上是产品设计，不代表所有模块已经完成。

## 当前代码做到哪里

当前开发基线包含 `learning-agent/` 本机模块，覆盖目标拆解、用户自选任务、空档排程、逐动作完成记录、临时重排，以及截图和录屏卡点输入流程。

代码及验收边界见 [模块说明](learning-agent/README.md) 和 [验收记录](learning-agent/VERIFICATION.md)。真实模型生成、视觉理解和正式搜索接口仍需完成联调；竞赛诊断与多人能力匹配是后续开发目标。两个网页链接是作品展示入口，其上线版本与本仓库开发分支应分别核实。
