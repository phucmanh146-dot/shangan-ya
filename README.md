## 我们要解决的问题

一个人或团队已经有目标，却可能不知道从哪里学、现有成果缺什么、今天先做哪一步。开始之后，又可能因为报错、临时安排或时间不够停下来。

我们希望把这个过程连起来：**理解材料与人 → 找出差距 → 生成行动 → 用户选择今日任务 → 执行与求助 → 核验成果 → 根据变化调整。**

比赛是应用场景之一。比赛名称、职责、能力、可用时间和交付物均由真实输入决定，不写成固定模板。

## 三个人分别交付什么

| 负责人 | 负责的能力 | 交给下一环节的结果 | 工作分支 |
| --- | --- | --- | --- |
| 队友 A | 诊断与资料研究：要求核对、材料分析、案例检索、成员能力访谈 | 带来源的现状、差距、目标结果和成员档案 | `feature/diagnosis-research-agent` |

两位队友的真实 GitHub 账号与 A/B 认领情况另行核对。分支以职责命名，建立分支不等于已经邀请成员。

## Agent 怎样工作

Agent 需要依据目标和当前状态选择下一步工具，并检查工具结果、保存执行状态，再决定继续、追问、求助或调整。

1. A 读取目标、PRD、已有成果与适用规则，保留出处和未知项。
2. A 理解成员的想法、能力与已有证据，生成差距包。
3. B 把差距变成有产物和验收标准的任务，安排必要的学习与练习。
4. 用户选择今天做什么；B 检查依赖和时间容量，返回日程或排不下的原因。
5. 队长负责的总控保存执行记录，接收截图、录屏、成果与临时安排。
6. A 复核新成果，B 按变化重排；用户确认后保存新版本。

失败、资料不可读和时间不够都必须如实显示。点击“做完”应进入待验收，有对应证据后才算完成。
