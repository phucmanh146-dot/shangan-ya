# 原工作台增量优化：资料池与微信远程

目标站点：https://shanganya-focus-hanyi.phucmanh146.chatgpt.site/

这份改动基于原 `workbench-extension`，保留原导航、清单、专注功能和历史数据。它不是新网站，也不是已经发布到原网址的证明。

## 本次代码变化

| 原有部分 | 新增行为 |
| --- | --- |
| 资料 → 行动 | 蓝色资料池：存正文、来源、时间和选择状态；按原本机资料空间保存、去重；关闭再打开可继续选择 |
| 微信关键词搜索 | 搜索只生成真实候选列表；默认不勾选；用户选择后才进入资料池；搜索刷新时保留勾选 |
| 微信窗口跟随 / 框选 | 保留现有共享窗口、跟随和框选能力；选中内容回到同一资料池；保留正在填写的目标和问题；切换资料账号后拒绝旧窗口回传 |
| Obsidian | 新增桌面 Bridge；单次配对、实际 file-open 最近笔记、双击读取 Markdown 正文；PRD 创建新文件后打开，不覆盖旧笔记 |
| 网页链接 | 已读取正文可进入统一资料池；空正文和只有链接的内容不能冒充全文 |
| AI 产品经理 | 后端按选中的资料 ID 读取实际正文；输出当前问题、产品优化、技术方案、下一步任务；保留来源 ID 和任务优先级 / 验收条件 |
| 模型设置 | 沿用原后端的真实推理测试；增加当前模型重测与耗时；区分 AUTH / BILLING / MODEL_NOT_FOUND / PERMISSION / RATE_LIMIT / NETWORK / SERVER / BAD_REQUEST |

## 安装到原电脑工程

先使用原安装器更新包含 `index.html`、`local_server.py` 的完整工程。安装器备份旧文件，不清空任务或数据库。

```powershell
python install_workbench.py "<原工作台目录>"
python install_obsidian_bridge.py "<实际 Obsidian 知识库目录>"
```

Obsidian 的第三方插件中启用“上岸鸭 Bridge”。启动原工程的“启动资料行动.cmd”，默认端口为 8877，再点“打开我的 Obsidian”。以后无需反复选择目录。当前 Bridge 固定连接本机 8877，不连接任意外部服务器。

微信沿用电脑已登录的客户端。主流程是关键词搜索、列表核对、勾选导入；共享窗口和框选需用户在系统选择器中选中微信窗口。没有发送消息的操作。

## 验证结果与边界

- 26 个 Python 合约 / 单元测试通过：资料去重、正文持久化、选择隔离、服务端资料取回、配对单次使用与凭证、路径限制、跨库结果校验、HTTP 来源和令牌、模型错误处理、原资料处理流水线。
- 3 组 Node 测试通过：资料池页面交互、Obsidian 插件读写合约、原微信选择状态。
- JS 语法检查、Python 编译、`git diff --check` 通过。
- 测试使用受控 API / HTTP / Obsidian 对象，不代表真实微信、真实 Obsidian 和真实模型账号已连接。
- 完整旧测试发现环境缺少原工程的 `document_outline` / `source_support`、浏览器自动化依赖，且 Windows 窗口测试不能在 Linux 运行。没有把这些失败标成通过。新 HTTP 测试使用最小 legacy-host fixture，未代替完整原工程验收。
- 原公开页面目前是静态发布，现有 `hosting-support.js` 会拒绝本机 API。不能仅复制这些文件到静态站点就宣称远程功能已上线。线上接入需要原 Site 的可编辑工程、用户身份 / 授权连接，以及受控的远程服务路径；本次未放宽 localhost 的来源限制，也未把某一台电脑开放给所有访客。
- 当前 Sites 连接未列出这个原项目，只有另一个 AI PM 项目。原域名尚未发布本次改动。Desktop Commander 最后探测返回设备离线，尚未在用户电脑安装或实机验收。

## 在原电脑和原站点恢复访问后继续

1. 取得原 Site 的编辑项目和源码，保留项目 ID、原地址和受众，不新建替代站点。
2. 核对原工程版本，备份并安装此分支，启用 Obsidian Bridge。
3. 实机验证：双击笔记 → 资料池 → 选中正文进入模型请求 → PRD 写回当前库。
4. 实机验证：微信关键词 → 候选 → 勾选 / 窗口框选 → 资料池；核对未选内容没有导入。
5. 在原 Site 上使用每个访问者自己的授权连接；验证访问隔离后再部署原网址。
