上岸鸭工作台
全功能交互 PRD

围绕「目标 → 执行 → 卡点求助 → 精力调整 → 完成 → 复盘」设计个人工作台。本文将每个功能拆成独立需求，写清楚用户目的、交互步骤、输入输出、异常状态、业务规则与验收标准，供产品设计、开发和测试直接使用。

版本 V1.1日期 2026-10-28优先交互简洁桌面端 / 移动端不替代现有线上页面

文档说明

功能级规格，而非只有功能名称的概览。

产品宗旨：计划不是拿来逼自己完成的，而是帮助用户在真实精力、真实耗时和真实困难下，完成更多重要的事。默认先让任务跑起来，复杂能力按需展开；任何 AI 或连接器失败，都不能阻断用户继续工作。

目标用户

同时推进学习、内容运营、比赛、个人项目和 Agent 实践的个人用户。

核心问题

计划过满、估时不准、遇到困难耗尽精力、任务资料分散、休息无处安排。

设计原则

少步骤、少打断、状态真实、可撤销、先建议后调整、手动流程永远可用。

核心用户流程

所有功能围绕一条主线协作，不让用户在模块之间迷路。

01 · 规划确定今日重点

选目标、时间预算和精力状态。

02 · 执行开始一个任务

自动计时，任务资料就近可见。

03 · 干预处理卡点或疲惫

拆小步骤、求助 AI、休息或顺延。

04 · 学习完成并复盘

记录实际耗时，优化后续估算。

01 · 今日工作台

首页只回答三个问题：现在做什么、做了多久、下一步怎么办。

P0
功能目标与页面组成

目标：用户进入页面后无需浏览大量图表或设置，即可开始最重要的任务。

  • 顶部：日期、今日精力状态、可用时间摘要。
  • 主卡片：当前任务名称、预计时长、已用时长、关联资料、当前状态。
  • 今日清单：按“优先完成 / 有空再做 / 休息与缓冲”分组，已完成默认折叠。
  • 快捷操作：开始/继续、我卡住了、完成、添加任务。
  • 高级入口：四象限、时间表、模型配置、外部连接器收纳在次级入口。
交互规则与状态
  1. 无当前任务时，显示今日优先级最高且未完成的任务，并提供“开始任务”。
  2. 有进行中任务时，该任务置顶；不允许多个任务同时处于真实计时状态，若切换任务须先暂停或确认结束当前任务。
  3. 任务完成后，首页推荐一个下一动作：开始下一项、休息一下或今天先到这里。
  4. 无任务时展示空状态：“先添加一件今天最重要的事”，而不是空白页面。
  5. 网络/AI不可用时，首页的任务、计时和手动录入仍可工作。

验收：用户进入首页 10 秒内可以开始任务；核心动作不超过一个主按钮加两个次按钮。

02 · 任务管理

统一管理多条主线，避免为每个项目重复建一套工具。

P0
新建 / 编辑任务

必填字段：任务名称。其余字段采用合理默认值并允许稍后编辑。

字段规则示例
任务名称必填，建议清楚描述动作或产出完成一个 AI 产品案例拆解
所属主线可选；用户可新增主线AI PM 学习 / 运营 / 比赛 / Agent
优先级高、中、低；默认中高
预计时长分钟；允许稍后修正25 分钟
截止时间可选；无截止时间不阻止保存今天 18:00
关联资料可多选，也可暂不关联课程链接、文档、截图

交互：点击添加任务 → 输入名称 → 可选选择主线和预计时长 → 保存。保存后立即出现在清单中，不强迫用户填写全部字段。

异常：名称为空时就地提示；重复名称允许创建但提醒用户确认；保存失败时保留表单内容。

任务状态、排序和归档

统一状态：未开始、进行中、已暂停、已完成、已顺延。用户可手动调整优先级与顺序。已完成任务默认折叠，可查看详情、重新打开或归档。顺延时必须保留原计划和顺延原因（原因可跳过），不得静默删除任务。

验收：创建、编辑、完成、顺延、恢复和归档后，页面状态一致；刷新后数据仍在。

主线管理

允许创建、重命名、排序和归档主线。删除主线时先让用户选择将关联任务迁移到其他主线或保留为未分类，不级联删除任务。预置主线只作为初始建议，不限制用户创建自己的类别。

03 · 动态排期与时间预算

排期是建议，不是不可更改的承诺。

P0
生成今日安排

输入：今日最重要目标、可用时间（可跳过）、当前精力（低/中/高）。

处理规则：先安排 1–3 项重要任务，再放入次要任务；按可用时间预留默认 15%–25% 缓冲。若预计总时长超过可用时间，明确提示并建议缩减，不把任务全部塞满。

输出：优先完成、有空再做、休息与缓冲三组任务。每项显示预计时长和推荐原因。用户点击“应用安排”后才写入日程。

空输入：用户可以跳过时间或精力问题，直接使用当前任务列表，不强迫填写问卷。

超时检测与重新排期
  1. 当实际用时达到预计时长的 80%、100% 和 150% 时，允许采用轻量提示；频率需避免反复打断。
  2. 超时后展示“继续 / 拆小任务 / 暂停并稍后 / 重新排期”。
  3. 重新排期时展示受影响的后续任务及原因。
  4. 用户确认前不覆盖原安排；提供撤销上次调整。
  5. 系统不得把超时自动标记为失败，也不得自动删除低优先级任务。

验收：排期建议可解释、可确认、可撤销；无用户确认时原安排不变。

视图模式

默认列表视图；四象限视图按重要/紧急分类；时间表视图展示任务与休息的时间段。视图切换不改变任务数据。移动端优先使用列表，避免横向拥挤。

04 · 精力反馈、休息与缓冲

用最轻量的方式了解用户状态，不强迫用户持续自我量化。

P0
精力快捷反馈

提供三个快捷选项：“精力够用”“有点累”“已经耗尽”。允许用户随时修改，不要求每天固定时间填写。

  • 精力够用：建议继续当前重要任务，避免同时启动多项。
  • 有点累：建议短休息、喝水或把任务拆成更小步骤。
  • 已经耗尽：优先建议休息，并提出顺延低优先级任务。

系统结合用户反馈、当前任务耗时和剩余任务给建议，但不将主观反馈当成医学结论。

休息和放松时间

休息是正式的计划项目，可选择短休息、发呆、散步或娱乐放松。休息有预计时长但允许延长。休息结束后给出温和提示，用户可继续休息、开始下一项或结束当天计划。休息不会被统计为未完成任务。

摄像头与自动状态识别边界

默认不打开摄像头，不默认推断情绪或心理状态。未来如加入摄像头/传感器能力，必须单独征得明确授权、说明处理方式、提供关闭开关，并以用户确认作为排期调整的最终依据。核心功能不得依赖摄像头。

05 · 计时与任务执行

计时必须可信；页面刷新不能导致时间归零或重复累计。

P0
开始、暂停、恢复、完成
  • 开始任务：记录开始时间并进入进行中状态。
  • 暂停任务：累计当前有效执行时间，暂停期间不计时。
  • 恢复任务：创建新的执行区间，继续累计有效时间。
  • 完成任务：停止计时，记录总有效耗时，状态改为已完成。
  • 顺延任务：停止当前计时并记录顺延状态，不丢失已累计时间。

计时实现应基于持久化的开始时间与累计时长计算，而不是仅依赖页面每秒加一。刷新后按真实时间差恢复，防止浏览器后台节流造成偏差。

计时异常与多任务冲突

若发现多个任务同时计时，提示用户选择保留哪个任务为当前任务，其他任务暂停。系统重启或网络断开后显示可核验的计时状态；无法确定时明确提示“计时状态需要确认”，不猜测、不静默补时。

验收：开始后时间持续更新；暂停时间不计入；刷新后正确恢复；同一执行区间只累计一次；完成后实际耗时可在复盘中查看。

06 · 卡点记录与 AI 求助

遇到困难时，系统帮用户走出下一步，而不是增加一套复杂配置流程。

P0 / AI 增强
求助流程
  1. 用户点击“我卡住了”。
  2. 出现轻量面板：一句话描述卡点（可选），附加截图/文档/链接（可选）。
  3. 点击“帮我拆解”后，系统基于当前任务目标和用户明确提供的资料生成帮助。
  4. 回答先给一句通俗解释，再给最多 3 个可执行步骤，附相关资料来源。
  5. 用户选择“完成这一步”“继续问”“降低难度”“暂停稍后处理”或“继续手动做”。
AI 输出格式与安全降级

回答必须关联当前任务，不泛泛讲解。优先给最小可执行动作；引用资料应提供真实来源链接，无法验证时明确说明。若模型超时、无 API Key 或资料解析失败，保留用户输入和附件状态，显示失败原因与重试选项，仍可保存卡点、暂停或继续计时。

不得声称已读取未授权的微信、飞书、Obsidian 或本地文件；不得把推测内容标为已验证结果。

07 · 资料中心与任务关联

资料不是孤立收藏夹，而是任务执行时可直接使用的上下文。

P0 基础 / P1 解析
资料新增与管理

支持类型：网页链接、文档、图片、视频链接、文字笔记。每条资料至少记录标题、类型、来源、创建时间、关联任务和读取状态。

交互：点击添加资料 → 粘贴链接或选择文件 → 可选选择关联任务（可搜索下拉）→ 保存。也可在任务详情中直接添加资料，自动带入当前任务关联关系。

管理：搜索、筛选类型、修改标题、变更关联任务、取消关联和删除。删除资料前提醒是否仅解除关联或永久删除。

读取、解析与检索

资料可用状态应区分：待处理、可读取、解析中、解析失败、需要权限。只有实际读取成功后才显示可读取。解析文档或图片后，AI 回答应能指向资料来源；链接无法访问时提示登录/权限/网络问题，并提供手动粘贴正文或上传文件的替代方案。

验收：任务卡片可看到关联资料；资料可在任务内打开；连接器读取失败不伪装成功。

08 · 复盘与个性化估时

积累少量但可信的数据，逐步改善计划质量。

P1
任务完成后的轻量复盘

任务完成后自动记录预计时长、实际有效时长、开始/结束时间和所属主线。用户可选填写“遇到什么卡点”和“一句话经验”，均可跳过。避免强制长表单。

统计与个性化建议
  • 本周完成任务数与完成率。
  • 预计耗时和实际耗时的差异。
  • 不同类型任务的历史平均耗时。
  • 常见卡点与解决方法。
  • 低精力状态下更适合的任务类型。

只有样本足够时才展示平均值或趋势。样本不足时显示“数据还不够，继续记录几次后再估算”。建议应能解释依据，不将相关性说成确定因果。

09 · AI 能力、模型选择与 API

AI 是任务的辅助能力，不是使用工作台的门槛。

P1 / P2
AI 助手入口与能力边界

AI 助手应在任务详情和卡点面板中按需出现。支持解释概念、拆解步骤、总结用户提供的资料、生成学习提纲和辅助复盘。默认将当前任务名称、目标和用户主动关联的资料作为上下文，允许用户查看并移除发送给模型的内容。

模型和 API 配置

设置页集中管理供应商、模型名称、API 地址（如适用）、密钥和连接测试。供应商采用下拉列表；选择供应商后提供对应官方文档入口。API Key 默认掩码显示，提供显示/隐藏与删除操作。不要把密钥硬编码在前端、提交到公开仓库或写入日志。

连接测试必须真实调用并返回成功/失败及可理解原因。未配置模型时，任务管理、计时、资料保存和手动复盘仍可用。

回答的增强形式

先给简洁文字结论；需要时再展开步骤、思维导图结构、参考资料或视频讲解。视频生成属于后续增强能力，不应在没有真实生成服务时展示“已生成”。所有生成结果提供复制、保存或重新生成入口，失败时保留提示词和输入材料。

10 · 外部平台连接器

连接器必须可验证、可撤销、可解释，不以界面状态冒充真实接通。

P2
微信、飞书、Obsidian 与本地文件

每个平台显示独立状态：未连接、待授权、已连接、读取成功、读取失败、权限不足。连接状态和读取状态必须分开。

  • 微信：仅处理用户明确授权且实际可访问的聊天导出或接口数据；不得绕过登录或加密保护。
  • 飞书：显示授权账号、可访问文档范围、最后成功读取时间和错误信息。
  • Obsidian：用户选择具体知识库或文件夹；连接失败时允许手动上传或粘贴笔记。
  • 本地文件：由用户主动选择或上传，显示文件名、大小和解析状态。

每条检索结果应注明来源和读取时间。未成功取得内容时，禁止生成“已读取”或假装引用真实内容。

权限、隐私和断开连接

连接器仅请求完成当前任务所需的权限；提供断开连接、清除已缓存内容和重新授权入口。用户可以查看哪些资料被关联到任务。敏感内容发送给 AI 前应提示数据范围，尽可能支持用户选择具体文件或文本。

11 · 快速录入、语音与内容捕获

降低新增任务和资料的成本，但不让自动识别干扰主流程。

P2
快速添加任务与资料

支持从首页快速添加任务、粘贴网址、上传文件和保存文字片段。识别到标题或任务名称后先展示预览，由用户确认再保存。不得未经确认自动创建大量重复任务。

语音输入与截图识别

用户主动点击麦克风后才开始录音；界面清楚显示录音中、识别中和失败状态，并提供停止/取消。截图识别先显示识别文本，允许编辑后再转换成任务或资料。浏览器不支持权限或用户拒绝时，手动输入仍可用。

12 · 设置、数据管理与系统状态

把低频配置集中管理，避免它们挤占首页空间。

P1
偏好设置

可设置每日可用时间、默认缓冲比例、提醒频率、默认任务时长、休息选项、首页默认视图和主题。任何默认值均可调整，修改后给出明确反馈。

数据保存、导出与删除

任务、计时区间、资料元数据和复盘分别持久化。提供导出与删除入口；删除重要数据前二次确认。保存失败时明确提示，避免让用户误以为已保存。刷新页面后应恢复任务和计时状态。

错误提示与系统健康状态

错误提示应包含发生了什么、影响哪些功能、用户能做什么。区分网络异常、权限不足、模型配置错误、解析失败和服务暂不可用。避免只显示“未知错误”，也不要让系统错误清空用户正在编辑的内容。

开发优先级与范围

按核心闭环拆版本，避免一次性实现所有连接器。

P0 · 核心可用

先把任务跑通

  • 今日首页与任务清单
  • 新建/编辑/完成/顺延
  • 稳定计时和刷新恢复
  • 精力反馈与休息缓冲
  • 卡点记录与手动降级
  • 资料与任务基础关联
  • 基础持久化和错误提示
P1 · 体验增强

更懂用户的计划

  • 动态排期建议
  • 四象限与时间表视图
  • AI 任务拆解
  • 文档/图片解析
  • 实际耗时统计
  • 历史估时与周复盘
  • 偏好设置与数据导出
P2 · 高级能力

连接外部生态

  • 多模型供应商配置
  • 视频讲解/生成
  • 微信、飞书、Obsidian
  • 语音与截图识别
  • 快捷捕获与 Agent 自动化
  • 更细粒度的权限和同步
