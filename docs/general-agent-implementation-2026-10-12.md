## 可以立即执行的接入顺序

1. 用当前优化分支启动新服务，避免占用旧8921。模型连接通过后创建“真实项目”，不要选示例模式。
2. 保存本次条件：项目名称/类型、目标产物、可核对的条件、真实截止、已知赛道。未知的规则写入待确认，不填模拟日期。
3. 每人写本人的具体交付、理解、准备怎样做、实际工具、能力自述。不要只写“负责技术/运营”。
4. 选择或拖入可读文件：官方条件、本人作品、参考作品分别声明来源。读取原文，核对提取是否完整及位置；来源分类是用户声明，不是官方认证。
5. 继续总调度：A读真实文件并生成诊断，B给出候选行动；未知项和受保护任务变化须核对。确认后采用预览。
6. 未知能力先执行最小试做；将试做产物以“能力试做”保存并提交任务，逐条件验收后登记能力结果与原文证据。未通过就补具体方法并复试。保存能力记录会重新要求A核对，旧执行成果仍保留。
7. 进入制作后实改文件。上传时选择“实改成果”，同一材料选择保存新版；它不重置正在执行的计划。提交任务时选择这个真实文件版本。
8. 调用A复核，查看对应新版和逐条件证据。未通过退回修改；通过仍需人对照实际作品确认。
9. 点击“确认复核后更新剩余计划”。关闭gap需要成果条件通过；试做/学习不会关成果gap。预览只新增剩余动作，确认后采用。
10. 填本人真实空档、其他任务占用、排满日期、日投入上限及机动时间，再预览周期安排。阶段通过后留存全部模型输入/返回/校验记录和作品版本，重复上述循环。

### 启动与依赖

```bash
cd learning-agent
python -m pip install -r requirements.txt
python learning_agent_server.py --port 8922 --with-team-ai --open-team
```

打开 `http://127.0.0.1:8922/team.html`。在学习导航页的“AI连接”配置已有服务，或使用既有后端环境变量。模型需遵循JSON；图片求助另需支持视觉。双击 `启动三人总控.cmd` 会显式尝试连接本机Hermes再打开页面；本机没有网关就手动配置，不会换成示例答案。密钥只从已有本机来源加载到内存，不进入仓库、浏览器返回或执行记录。

Python 3.10+；TXT/MD/CSV/JSON/DOCX/PPTX解析使用标准库，文本PDF需 `pypdf`。每个文件2 MB，正文200000字/4000个位置；单次模型读取合计60000字，超过则拒收并要求拆分，不静默裁切。DOCX是段落/表格位置，不能假称页面；PPTX按演示关系顺序编号；CSV按逻辑记录编号。扫描图、音频、DOCX分页和版式未解析。

默认仅绑定回环地址。此版本是本机服务，尚未完成多人公网账号与部署验证。新总调度使用实际文件和有限的可核查课程目录；原学习导航保留联网功能，但不宣称新A已自动爬取全部竞赛/私有飞书/平台视频。

### GitHub接入步骤

1. 两位同学各用本人GitHub账号登录；验证码/两步验证由账号本人完成，不共用队长账号。
2. 队长核对A/B的GitHub用户名与认领。需要直接推送时，在仓库设置邀请正确账号；仅有分支不能证明邀请已接受。尚缺两个实际用户名，本轮不代填、不发送未知人的邀请。
3. 各人从共同联调分支取代码，在自己的职责分支修改，提PR，写触发问题、实际行为和验证记录。优化分支以原联调候选为基线，先审阅依赖再合并；不要各自整库覆盖。
4. 队长收A的材料/诊断/复核交付和B的规则/日程交付，运行共同验收。A/B接口字段要使用当前材料/诊断/计划版本；旧版拒收后刷新再交。
5. Git操作使用GitHub插件或本人已授权的CLI，不把token/密码写入文档或源代码。共同分支及main的合并/发布仍需团队审阅；本轮只发布独立优化分支和草稿PR。
