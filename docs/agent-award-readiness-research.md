# 获奖与岗位研究：上岸鸭 Agent 应怎样改

检索/核验日期：2026-10-11。研究范围覆盖中国本赛事公开获奖项目、Google 与 Microsoft 公开比赛获奖应用/Agent、相邻产品、开源项目、官方工程实践和真实招聘页面。
这是一份有来源的定向研究，未穷尽全网；不是获奖保证、薪酬预测或原创性/专利检索。宣传功能、官方认可和本队实测效果在下文分别处理。

实施任务与有条件排期见 [实现路线 v3](implementation-roadmap-v3.md)，质量验证见 [验收与评测表](agent-v3-acceptance-checklist.md)。

## 1. 赛事定位与仍需核实的门槛

本队前文提及“人工智能应用创新挑战赛”。优先研究同名官方赛事，并通过 2026 年高校通知核验当前节点：
- 官方网站：[中国人工智能应用创新大赛/挑战赛入口](https://www.ai-race.com.cn/)。
- 北京工商大学 2026-09-28 通知 [S1]：介绍 2026 年人工智能应用创新挑战赛，1–3 人队伍，报名缴费/作品上传截止列为 2026-10-20 24:00；赛程和具体提交要求以官方平台为准。
- 西北大学经管学院 2026-09-30 通知 [S2]：同样列出 10 月 20 日节点，并有选择赛道、在指定平台开发作品的校赛要求。

两条高校通知可以提示紧迫性，不能代替本队所选赛道的报名页、平台要求和评分附件。当前缺：确切比赛/赛道、学校安排、适用评审权重、提交格式/长度、平台开发要求和现成作品能否作为参赛提交。应由队长 C0 收齐并写成门槛清单。

## 3. 修改重点：从功能清单变成三个可验证假设

主要假设：把要求、成果位置、证据、差距、动作与新成果关联起来，会让成员更快完成符合目标的修改。

| 原表述 | 修改后的可验证行为 | 怎样证伪 |
| --- | --- | --- |
| 帮你把比赛任务拆细 | 指出当前成果哪个位置不满足哪项条件，给一张能留下具体成果的操作卡 | 用户仍需重新想“改哪里/交什么”，就没有完成 |
| 学习优秀作品 | 抽取参考具体位置和做法，说明适用条件，再对照本次规则与自己基础 | 不适用的参考被照搬，就失败 |
| 发现能力差距 | 依据本人解释、已有成果与小样试做选择指导深度 | 初学者仍看不懂、熟练者被迫重复课程，说明策略不好 |
| 自动动态调整 | 新材料能追到改变的结论和步骤；只重排影响项并解释 | 无关工作被改、旧数据仍被称新、已锁定安排被覆盖，就失败 |
| 提高获奖率 | 证明成果更符合有来源的要求、可复现且用户能执行 | 无对照和成果证据就不能宣称提升获奖率 |

最有价值的方向是“有证据的成果改进与执行反馈”，而非比谁生成更多任务。能力适配与容量安排是支撑机制。它们的组合是否有显著优势仍需测试；不主张全国首创、世界首创或可申请专利。

## 4. 现有项目该增加和削减什么

增加：
- 材料版本和对象位置；关键结论可点回原文。
- 可检验的目标条件，区分官方要求/个人目标/参考/建议。
- 一张卡明确输入、动作、原因、变化、输出、自检、失败下一步。
- 上传后复核与二次指导，不能以勾选代替成果验收。
- 新数据影响分析，包括不同统计口径和“只换数字但标题失效”。
- 动作可执行性、成果达标、成本/延迟与失败恢复的评测。
- 真实用户的理解、试做与卡点记录，保护已验收历史并提示新证据失效。

削减首轮范围：
“全网所有比赛”“全格式自动编辑”“所有应用远程控制”“长期全能个人工作台”“自动能力打分”“模型微调”。
先完成一个真实交付物的闭环，再用第二类成果验证数据结构通用。早期直接用模型 API 与规则校验，复杂 Agent 框架或向量库要有可测理由才引入。这个选择参考 Anthropic 的简洁工作流、环境反馈和可观察评测建议 [S16/S17]，不是厂商选型结论。

## 5. 产品经理岗位实际要求如何变成作品集

查看的是公开在招岗位，而不是薪资排名。岗位更新日与要求必须区分页面分类标签；腾讯 Craft 分类标签写一年以上，但具体岗位要求写 3–5 年，不按标签误认应届岗位。

| 官方岗位 | 可核验信息 | 本队怎样提供对应证据 |
| --- | --- | --- |
| 腾讯 Craft 高级 AI 产品经理 [S18] | 更新 2026-09-14；要求完整生产体验、不同能力用户引导、执行可控、质量题库/跨版比较、结果指标、技术验证；具体要求含 3–5 年经验 | 产品闭环录像、分层指导对照、采用/撤销与复核、固定评测集、失败迭代、本人可讲解的技术取舍 |
| 腾讯 AI 平台产品经理 [S19] | 更新 2026-08-26；Agent 平台需求/设计/推进/数据分析，API/MCP 等技术产品协作；有经验要求，未公开薪资 | 接口契约、跨模块交接、版本冲突处理、迭代优先级与真实指标 |
| OpenAI Product Manager, API Agents [S20] | 美国旧金山岗位，要求 5 年以上相关产品经验；发布薪资范围为基础年薪 USD 293,000–325,000，另有股权 | 开发者体验、工具/模型边界、技术决策、需求优先级和用户结果；该薪资不代表中国市场或本队毕业后水平 |

一个获奖项目不能替代岗位要求的经验；研究不能承诺高薪。本队可以争取积累能被审查的能力证据：
1. 需求判断：5–8 个试用者在真实任务中的行为和卡点，去除标识信息，写出哪项需求被证据否定。
2. 范围决策：为什么先支持 PDF/文本/CSV，为什么先实现成果回传，哪些延期。
3. 技术产品能力：说清模型做什么、程序做什么、人确认什么；自己能复现和修改一个关键环节。
4. 质量评估：固定输入、明确标准、同条件基线、真实失败和跨版差异。
5. 数据结果：首个可检查成果耗时、动作执行成功、成果符合目标、人工介入次数、每成功任务成本。
6. 推进与复盘：谁交什么、何时交接、阻塞怎样处理、一次不符合预期后具体改了什么。

“自己具备什么能力”只能根据本人讲解、独立试做与负责的真实交付判断，不能将仓库里的 AI 生成代码自动转换为本人能力等级。

## 6. 可交给评委/面试官的证据包

- 真实问题与用户角色；一版需求/范围取舍记录。
- 规则、当前成果、参考、新资料的可公开演示样本（授权、来源清楚）。
- 同一个成果的 v1/v2、操作卡、复核结果及局部更新理由。
- 无辅助复现说明、代码与运行记录；实际调用与示例明确区分。
- 固定评测题、人工标准、基线与本产品结果，包括失败项。
- 使用量、成本与耗时的真实记录；没有结果时填“待测”。
- 可复现的短演示与官方格式提交材料。内部可用 3 分钟讲解脚本，但正式视频时长/格式应按本队赛道核实。
- 个人贡献清单和一次独立讲解，说明自己做出的决策与验证。

不以星标数、任务数量、提示词长度、三 Agent 数量、虚构用户或示例截图作为有效性证据。
