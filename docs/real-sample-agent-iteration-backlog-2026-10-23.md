# 真实样品驱动的 Agent 功能迭代清单（2026-10-23）

## 本轮目的
把 `D:\上半年参加的创赛` 中的 8 个真实项目作为 Agent 回归测试集，把 `D:\学校优秀作品` 作为“目标质量参考库”，逐项测试“解析 → 证据定位 → 目标差距 → 私人定制行动卡 → 真人执行 → V2 复核 → 只重排剩余问题 → 中断接续”。

**禁止把参考库整体宣称为省一等奖作品。** 已发现奖项标签混杂（例如丝科新材文件名标“国铜”、万物互融材料出现“省三”标签）；每个样本的奖项须单独用官方公示/证书核验。优秀作品用于提取方法，不用于复制文字，也不代替本届官方评分标准。

## 已发现的关键功能缺口（优先修复）
1. 当前被测试 runtime 的 `artifact_store.py` 仍限制单文件 2 MB；14 份主要原件曾被阻断。
2. 图片型 PPT/PDF 不做视觉解析；旧 `.doc` 与普通 ZIP 不支持。
3. 即使放宽单文件大小，`team_ai.py` 的 60,000 字上下文限制仍可能阻断大材料；必须采用按页/段落切片、索引和按需检索，不能只抬高上传限制。
4. 在线模型诊断记录出现 `CONFIG_REQUIRED`，因此当前不能宣称真实模型诊断成功。
5. action_planner 缺少 grounded `micro_steps` 时可能退回通用三步；必须进入 `blocked/unscheduled`。
6. 分支工程测试不等于集成/部署/真人效果：PR #21、#22 曾为 open/draft；需重新核验当前状态及实际 runtime。
7. 真实 V1→V2 及独立复核仍未形成完整证据链。

|---|---|---|---|
| A | 嘉农芯生 | 专利数量口径、1200株/小时与96%成活率是否绑定原始试验批次 | 专利状态表 + 指标试验台账 |
| A | 滴水润疆 | 同一批次投放、回收、称重、质检、成本是否可追溯 | 批次追踪表 |
| A | 菌润乡土 | 旧 DOC 解析阻断；单品订单、损耗、复购、农户结算证据 | 可解析材料包 + 单品批次账 |
| B | 文玩玉米 | 亩产值、销售收入、农户净收益口径区分 | 单品损益表与订单证据 |
| B | 本草云联 | 区分已实现/原型/规划；效果百分比来源与非临床测试边界 | 模块状态表 + 非临床测试日志 |
| B | 湘匠织秀/湘秀未来 | 需求、纹样授权、报价、制作、质检、交付、结算、反馈是否形成真实闭环 | 一款产品订单台账 + 访谈/授权证据 |

| C | 无界智泊 | 计划试点与已使用时间线核验；预约冲突、结算、退款异常路径 | 端到端测试日志 + 试点证据清单 |

以上分工是主责，不表示其他人可以跳过跨角色验收：A 负责证据与原判据；B 负责行动卡与剩余项重排；C 负责集成、状态保护、试验设计和总验收。

## 必须先做的两样本私人定制测试
### 样本 1：数智助老
首个 5 分钟动作：把“15 分钟响应”“办事时间缩短 65%”分别放进 claim-evidence 表，填原始证据、基线、样本和 locator。缺证填 `unknown`，只能标“目标/待验证”，不准补造数字。产物：`elder_claim_evidence_v0`。

### 样本 2：湘匠织秀/湘秀未来
首个 5 分钟动作：只选一款产品，建立“需求方—用途—预算—纹样来源—授权—报价—制作—质检—结算”台账；已知项填事实，未知项写 `unknown`。产物：`embroidery_order_loop_v0`。若找不到真实需求方，下一步是需求访谈，不是增加商城、AI 或区块链功能。

**判定私人定制失败的条件：** 两个不同项目都得到“加强调研→优化方案→完善 PPT”这类同样的通用卡；或行动卡没有版本、精确位置、来源、预期变化、产物、自检和失败后路径。

## 测试状态必须分四级
- `ENGINEERING_PASS`：单元/集成测试通过，只证明程序规则。
- `SIMULATED_MODEL_PASS`：mock/固定夹具通过，不证明模型判断质量。
- `LIVE_MODEL_PASS`：真实配置模型运行并保留 trace、输入、输出、引用。
- `HUMAN_LOOP_PASS`：非作者真人照卡执行，产生真实 V2，并由另一人按冻结的原判据复核。

不允许跨级推断。无真实 V2、无独立复核，不得标完整闭环通过。

## 每个项目的强制证据包
1. 当前 V1 文件及 hash、目标标准和样本来源（locator）。
2. 原件解析覆盖率、失败/未解析页列表。
3. 3–5 条有证据的 gap；每条区分事实、推断、unknown。
4. 项目专属 micro_steps 与 5 分钟首步。
5. 非作者执行日志、实际耗时、卡点原话、真实 V2 文件/hash。
6. 按冻结的原判据逐条 pass/fail/unknown 的复核表。
7. 只针对 fail/unknown 的剩余项计划；不得覆盖已完成/锁定任务。
8. 修改 commit、修复前测试、修复后同用例结果和回归结果。

## 本轮优化顺序
P0：修复大文件/图片/旧 DOC/ZIP 入口或明确分块转换路径；解决 runtime 与分支代码不一致；配置真实模型运行；禁用通用三步 fallback。
P1：跑通数智助老与湘匠织秀两种不同项目的真实 V1→V2；测试精确中断恢复与复核门。
P2：将同样测试扩展到另外六个项目；进行 5–8 位用户、同一任务、通用助手对照试用。
P3：按证据决定每个创新假设 go/revise/stop，禁止为了“显得创新”强行证明全部功能有效。

## 外部评测方法参考
公开的证据驱动 Agent 评测项目也采用官方来源、可定位证据、透明评分、可重复数据集和修复后测试的方式；可借鉴评测结构，不复制其内容或分数：https://github.com/SeanJ1ang/design-judge-skills

## 完成定义
完成不是“报告写完”或“Agent 生成计划”，而是至少一个样本经历真实 V1 → 有来源的差距 → 专属行动卡 → 非作者执行 → 真实 V2 → 独立复核 → 剩余项重排，并且失败问题已转成代码/流程修改，复测能显示是否改善。
