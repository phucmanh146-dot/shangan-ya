## 1. 不可改变的产品宗旨

上岸鸭不是普通 ToDo、提醒器或代写工具。它帮助第一次做竞赛/科研的学生：

`真实作品 V1 → 目标质量标准 → 原文证据诊断 → 个性化可执行微动作 → 真人执行 → 真实 V2 → 非执行者独立复核 → 只重排未通过/未知项`

同时保留过程闭环：

`卡住/中断 → 保存现场、尝试、卡点与上下文 → 针对当前卡点提供帮助 → 用户确认恢复 → 接回原任务准确位置`

必须区分：
- 代码存在 ≠ 实际函数调用；
- 单元测试 ≠ 真实浏览器操作；
- 接口 HTTP 200 ≠ 模型语义正确；
- 模型有返回 ≠ 行动卡可执行；
- 生成草稿 ≠ 真人 V2；
- V2 上传 ≠ 独立复核通过；
- 一次样本通过 ≠ 用户效果或获奖水平得到证明。

## 4. 本轮已实际修复的工程问题

1. `team_ai.prepare_output_contract` 原先把同一份材料的第一条 quote/locator 注入每一个 gap 示例。模型容易照抄同一证据，导致多条 gap 引用错误或互相污染。现改为只提供 schema 形状和空字段，要求模型从当前材料 catalog 中为每条 gap 独立选择 quote_id；不再把第一条真实引用预填到所有 gap。
2. 增加回归测试：多 gap 不会共享被预填的第一条引用；空 schema 被照抄仍会被原有严格校验拒绝。
3. 修复两处测试环境缺陷：跨进程子测试显式设置 `PYTHONPATH`；HTML/JS 测试 fixture 显式使用 UTF-8，避免 Windows GBK 默认编码导致假失败。

这三项修复只改善提示契约和测试可靠性，不代表八项目 LIVE 质量已经通过。
