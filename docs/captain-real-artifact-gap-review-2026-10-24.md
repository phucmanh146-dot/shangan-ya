## 3. 队长 C 负责的差异与交接关系

### C → A：先冻结输入和验收标准
- 记录项目 ID、原件路径、SHA/version、可读覆盖率、赛事/赛道、官方目标与硬性判据。
- 官方标准与学校优秀作品参考库分开；参考作品的奖项需官方公示核验。
- 第一轮优先选两类差异最大的样本：数智助老（服务流程/效果基线）与湘匠织秀（需求/授权/订单交付）。
- 只有原件 locator 和当前证据可回查的 gap 才能交给 B；缺证标 `UNKNOWN/BLOCKED`。

### A → B：诊断必须具体到作品
每条 gap 必须含：`artifact_id/version/hash`、`current_locator`、`current_evidence`、`target_criterion/source_locator`、`reference_locator`、`extract_pattern`、适用条件、事实/推断/unknown、影响与补证动作。首轮每个样本至少 3 条 grounded gap，随机抽查必须能定位回原件。

### B → 执行人：不能用万能三步
每个 micro-step 至少含：`input_version`、`target_locator`、`action`、`reason`、`expected_change`、`output`、`self_check`、`failure_next`、`capability_basis`、`source_refs`、负责人、依赖、预计/实际耗时。
- 数智助老首步：建立两行 claim-evidence 表，找不到基线/日志就写 unknown，不补造数字。
- 湘匠织秀首步：找到一份真实访谈原件，建需求—产品—授权—报价—制作—质检—交付—结算台账；没有真实需求方或授权证据则先补证。
- 若两类作品都得到“加强调研→优化方案→检查”同构计划，私人定制测试失败。

### 执行人 → A/第三人 → B → C
- 未参与诊断/编卡的人只看行动卡独立执行；保存实际开始时间、求助次数、卡点原话、耗时、真实 V2 路径/hash。
- V2 上传后只能进入 `pending_review`；A/第三人按冻结原标准逐条给 `PASS/FAIL/UNKNOWN`。
- B 只重排 `FAIL/UNKNOWN`；不得覆盖 `in_progress/pending_review/completed/locked`。
- C 核验 trace、版本、复核记录、剩余项与同输入回归。
