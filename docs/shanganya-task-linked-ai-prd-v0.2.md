# 上岸鸭任务关联 AI 工作台 PRD（前后端统一版）

- 版本：0.2
- 日期：2026-10-28
- 目标：作为前端、后端、测试和后续 Agent 的统一功能基准，减少上下文串线、重复实现、假连接和假读取。
- 适用范围：原有工作台、每日清单、任务详情、资料读取、AI 模型/API 配置、Bug 解卡、行动回写、思维导图、复盘和视频讲解。

## 0. 不可变产品约束

1. 保留原工作台结构和现有任务数据，不重置导航、任务、截止日期、优先级、完成状态、资料和历史记录。
2. 当前任务是唯一主线；资料必须关联任务；AI 请求必须绑定稳定 taskId，不得混入其他任务资料。
3. 真实性优先：链接已保存不等于正文已读取；模型出现在目录不等于当前账号可调用；视频脚本不等于视频文件；配置按钮不等于连接成功。
4. AI 建议先预览，用户确认后才写回；默认只新增子任务/行动，修改截止日期、优先级和完成状态须分别确认。
5. 不使用 CC Switch。用户直接选择服务商、填写 Endpoint / API Key、读取真实模型目录并测试实际请求。
6. 失败可恢复：错误显示原因，保留用户输入和已成功处理的资料；单条资料失败不能丢失整批结果。
7. API Key 不写进前端源码、仓库、URL、普通日志或不安全的 localStorage；后端密钥与用户自行配置的密钥要区分。
8. 微信、飞书、Obsidian、桌面桥接、摄像头和视频生成等集成，必须显示真实授权、连接和读取状态，不得只展示按钮。

## 1. 产品定义与问题

把“每日清单任务 → 关联资料 → AI 分析/排错 → 用户确认行动 → 写回原任务 → 导图/复盘/视频讲解”连成可验证闭环。AI 不是孤立聊天页，而是任务遇到困难时可调用的解卡能力。

用户资料分散在网页、飞书、Obsidian、PDF、Word、图片、视频和公开链接中。当前主要风险是资料正文未必真的读取、AI 可能不知道当前任务、模型/API 看似配置成功但未验证、回答无法写回原任务、重复描述上下文，以及视频脚本被误认为真实视频。

## 2. 页面与信息架构

### 2.1 原工作台（保留）
- 保留原导航、每日清单、任务列表与任务详情。
- 任务详情显示任务名称、分类、截止日期/时间、优先级、状态、阶段、备注、子任务、关联资料和最近执行记录。
- 增加“遇到 Bug / 卡点？AI 解卡”入口；左侧提供“配置 AI API”入口。
- 所有入口必须由当前生产入口页真实加载，不能只存在于未被引用的 HTML/JS 文件。

### 2.2 AI 工作区
- 顶部：服务商、模型、连接状态、官方 API 文档链接。
- 当前任务条：任务标题、taskId、截止时间、阶段；未关联任务时明确显示“自由提问/尚未关联任务”。
- 资料区：只显示当前任务资料；显示来源、读取状态、更新时间和可查看的提取文本。
- 对话区：用户问题、AI 回答、依据、错误状态、重试。
- 结果区：问题摘要、原因、排查步骤、修复建议、验收标准、风险/回滚、建议行动、思维导图、复盘模板、视频脚本/视频任务状态。
- “写回任务”先预览差异；确认后写回同一条任务。

### 2.3 资料入口
资料管理放在当前任务详情内部，不再建设脱离任务的资料孤岛。支持公开 URL、用户有权访问的文件/笔记和已有授权集成。批量资料逐条处理、逐条显示状态。

## 3. 核心用户流程

### A. 任务解卡
1. 用户在每日清单选择任务。
2. 点击“遇到 Bug / 卡点？AI 解卡”。
3. URL 可以传入 taskId，但 AI 页必须重新读取该任务最新数据，不能只依赖旧参数或过期缓存。
4. 按 taskId 读取资料并检查每份资料的 parseStatus。
5. 只将当前任务的有效字段、用户问题和真实读取正文注入模型；未读取资料只能作为状态元数据，不得把空文本当正文。
6. 执行真实模型请求。
7. 返回问题摘要、按证据强弱排序的可能原因、分步排查、修复建议、验收标准、风险/回滚。
8. 用户预览建议；确认后仅更新原任务。
9. 记录 requestId、taskId、provider、model、状态、耗时和错误码；不记录 API Key 和不必要的敏感正文。

### B. 模型/API 配置
1. 用户选择服务商并打开对应官方 API 文档。
2. 填写 Endpoint、API Key 和协议配置。
3. “读取可用模型列表”必须真实请求服务商模型目录接口，不能用硬编码清单冒充实时模型。
4. 用户选模型并执行真实测试请求。
5. 只有真实测试成功才显示“已验证”。模型目录可读与聊天调用成功要分开呈现。
6. 顶部切换模型前执行真实验证；失败则保留上一个可用配置。
7. API Key 不回显，不进入 URL、前端源码、GitHub 或日志。

### C. 资料读取
1. 每份资料归属一个 taskId。
2. 状态语义：queued / reading / read / partial / failed / needs_auth（可映射为现有代码枚举，但语义不可混淆）。
3. 区分“已保存链接”和“正文已读取”。
4. URL 读取前校验协议、重定向、DNS/IP 和内网地址，防止 SSRF；登录受限资料通过官方授权接口或用户导出文件读取。
5. PDF/Word 走文本提取，图片走 OCR；视频只有在字幕/音轨/视频服务真实可用时才能声明已解析。
6. 一条失败不影响其他资料；重试只重试失败项，保留已成功结果。
7. AI 回答应可查看本次实际使用的资料及读取状态。

### D. 行动回写
1. AI 生成行动/子任务、估时、依赖和验收标准。
2. 先显示差异预览，默认只新增子任务/行动。
3. 改截止日期、优先级、完成状态必须分别确认。
4. 取消不写入；确认后写回原 taskId，不创建重复任务。
5. 写回失败保留建议并提示重试，不得显示假成功。

### E. 视频讲解
1. 先生成可编辑标题、口播稿、分镜、字幕和提示词。
2. 无视频服务配置时只显示脚本/分镜，明确“尚未生成视频”。
3. 接入真实服务后创建 VideoJob，展示 jobId、排队/处理中/成功/失败状态。
4. 只有服务返回有效且可访问的 outputUrl 后才标记视频完成。
5. 视频失败不能影响原 AI 答案和任务资料。

## 4. 前端功能需求

### FR-01 任务上下文一致性
- 切换任务时更新任务条、资料列表、对话关联与写回目标。
- AI 页按 taskId 恢复任务，并重新读取最新数据。
- 无效 taskId 显示错误与返回任务列表操作。
- 账号 A 的任务、资料、对话不能混入账号 B。

### FR-02 资料关联与读取状态
每份 Material 至少包含：id、accountId、taskId、title、source、url/fileName、mimeType、size、parseStatus、extractedText、addedAt、readAt、errorCode/errorMessage。
- 正文为空不能标记为已读或注入正文上下文。
- 任务切换清空旧任务的可视选中项，但不删除旧任务资料。

### FR-03 模型配置 UI
- 服务商、模型 ID、Endpoint、API Key、协议、官方文档链接、模型列表读取、真实测试和状态。
- 模型 ID 来源于真实目录接口；文档链接不代表账号有权限。
- 不把模型列表称为“所有模型”，而应标明“当前服务商返回且账号可见的模型”。

### FR-04 AI 解卡结果
- 输出：问题重述、已知证据、未知信息、可能原因、操作步骤、修复建议、验收步骤、风险/回滚、建议行动。
- 语言通俗，支持继续追问。
- 失败时保留输入和资料选择，支持重试和复制错误详情。

### FR-05 结果写回
- 预览后确认；默认只新增行动/子任务。
- 写回携带 taskId 和幂等标识，避免重复提交。
- 取消不改数据；确认后仅更新目标任务。

### FR-06 导图/复盘/视频
- Mermaid 导图可复制且与当前任务一致。
- 复盘模板可编辑。
- 视频脚本与视频文件状态分开；无服务凭证时不显示视频生成成功。

### FR-07 数据保全
- 保留原任务 ID、截止日期、优先级、完成状态、子任务、资料与历史记录。
- 部署前记录当前部署 commit 并确认回滚方式。
- 更新静态资源缓存版本，避免旧 JS 继续运行。
- 关键操作显示真实成功/失败状态。

## 5. 后端职责与接口契约

当前 public_server.py 对 /api/* 请求进行入口校验并转发到后端服务。保留已有接口兼容，增量统一，不要一次性破坏现有生产前端。

### 5.1 当前 UI 已使用的接口（兼容要求）
- GET /api/ai-providers：服务商目录和官方文档元数据。
- GET /api/ai-config：返回非敏感配置状态（configured、hasKey、base、model、protocol）；禁止返回密钥。
- POST /api/ai-models：按当前配置真实读取模型目录。
- POST /api/pm/config：保存/验证模型配置；verified=true 只能来自真实验证成功。
- POST /api/sources/read：读取用户有权访问的资料，返回正文、来源元数据和解析状态。
- 现有 /api/vault、/api/vault-search、/api/vault-read：保持知识库/Obsidian 桥接和授权边界。
- 若现有 /api/pm/ask、/api/video/generate 等接口已被页面使用，须保持兼容；变更前先核实实际调用和后端实现。

### 5.2 建议逐步统一的语义 API
- POST /api/tasks/{taskId}/ai-requests：创建任务关联 AI 请求。
- GET /api/ai-requests/{requestId}：查询请求状态/结果。
- POST /api/materials/extract-url：抽取可访问 URL 正文。
- POST /api/materials/extract-file：文件解析/OCR。
- POST /api/tasks/{taskId}/actions/preview：预览建议行动。
- POST /api/tasks/{taskId}/actions/commit：确认后幂等写回。
- POST /api/video/jobs：创建真实视频任务。
- GET /api/video/jobs/{jobId}：查询状态、错误与产物 URL。
- GET /api/health/ai：只返回不含秘密的健康/配置状态。

建议统一返回结构：{ ok, requestId, taskId, status, data, error: { code, message, retryable } }。迁移前继续兼容旧结构。

### 5.3 后端模块边界
- Provider Adapter：处理供应商模型目录、聊天请求、认证、超时和错误格式，不能只靠前端替换域名。
- Context Builder：按 taskId 读取最新任务、子任务、备注、阶段、关联资料及明确选中的当前任务对话。
- Material Reader：记录来源、状态、错误、正文长度和时间；限制 URL、文件类型、大小、超时和重定向。
- Task Writer：验证账号和 taskId；写回前校验用户确认和版本号；支持幂等和审计。
- Video Adapter：异步状态管理、轮询、超时、失败和产物链接验证。
- Observability：记录 requestId、taskId、provider、model、status、latency、errorCode；不记录 API Key。

## 6. 上下文检索规则（重点）

1. **单一事实源**：任务数据从现有任务存储读取。不要把过期 localStorage、旧 URL 参数和旧对话副本拼接后当作最新状态。
2. **稳定 taskId**：每个关联 AIRequest 必须有 taskId。没有 taskId 时进入明确标注的自由提问模式，不假装关联任务。
3. **先任务后资料**：先按账号权限读取 taskId，再只查询该任务所属资料。
4. **正文门禁**：只有 parseStatus=read/partial 的实际提取文本可进入正文上下文。failed/needs_auth/queued 仅作为状态元数据。
5. **历史范围**：只带当前任务会话必要的最近消息；跨任务历史、其他账号和无关笔记不得自动混入。
6. **请求可解释**：UI 可展开“本次 AI 使用了什么”，列出 taskId、材料标题、读取状态、提取时间和 contextVersion。
7. **来源可追踪**：回答引用资料时关联 Material ID 和来源链接；无来源结论标记为推断。
8. **检索失败不伪装**：明确显示“链接已保存但未读取正文”“需要登录授权”“读取超时”“格式暂不支持”等状态。
9. **上下文长度管理**：按当前任务相关性、用户勾选和时间排序；摘要必须保留来源映射，不能静默截断关键证据。
10. **写回二次校验**：不能信任模型返回的 taskId；服务端以当前账号和用户确认目标再校验。
11. **可自动测试**：覆盖任务 A/B 隔离、附件归属、空正文拦截、任务切换刷新、账号隔离和版本冲突。
12. **失败可恢复**：失败后保留用户输入和已读取资料；重试不得重复写回已确认行动。

## 7. 数据模型

- Task：id, accountId, title, category, deadline, priority, status, phase, note, subtasks, materials, updatedAt, version
- Material：id, accountId, taskId, title, source, url, fileName, mimeType, size, extractedText, parseStatus, errorCode, errorMessage, addedAt, readAt, contentHash
- AIRequest：requestId, accountId, taskId, provider, model, prompt, materialIds, contextVersion, createdAt, status, errorCode, errorMessage, latencyMs
- AIResult：resultId, requestId, taskId, summary, evidence, unknowns, steps, verification, risks, suggestedActions, mindmap, videoScript
- VideoJob：jobId, accountId, taskId, requestId, provider, status, outputUrl, errorCode, createdAt, updatedAt

## 8. 安全、权限和性能
- HTTPS；服务端验证 Origin、会话/账号与 taskId 归属。
- URL 校验协议、DNS/IP、重定向与内网地址，避免 SSRF。
- 限制请求体、文件大小、并发、超时、频率和模型费用。
- API Key 不回显、不记录、不提交仓库；前端只拿到 configured/hasKey 等状态。
- 飞书、微信、Obsidian 仅通过授权 API、用户授权本机桥接或用户导出文件读取；不能访问就明确失败。
- 用户确认前不修改任务关键字段。
- AI 输出不能声称已自动修复代码/电脑，除非实际执行并完成验收。
- 桌面与移动端布局可用；控件标签、键盘操作和错误状态清晰。

## 10. 发布与回滚流程

1. 核对 Railway 仓库、分支、Root Directory、启动命令、环境变量名和最新部署 commit。
2. 先部署到预览服务，验证静态资源和健康接口，再测试模型目录、真实模型连接、任务上下文、资料读取、行动预览与视频状态。
3. 没有供应商凭证时，UI 可以验收，但真实模型调用标记 BLOCKED，不得声称 AI 全链路可用。
4. 生产部署前确认目标分支与当前生产基线一致；不可把基于另一分支的 PR 直接覆盖生产。
5. 记录部署 commit、健康检查、smoke test 与已知限制。
6. 失败时回滚到上一个 SUCCESS 部署；不删除或覆盖任务数据和持久卷。

## 12. 界面状态文案

- 入口：遇到 Bug / 卡点？AI 解卡
- 配置：配置 AI API
- 模型：正在读取模型 / 已读取 N 个模型 / 读取失败 / 请先测试连接
- 资料：仅保存链接 / 正在读取 / 正文已读取 / 部分读取 / 读取失败 / 需要授权
- AI：准备上下文 / 正在分析 / 成功 / 失败，可重试
- 视频：脚本已生成 / 等待生成服务 / 排队中 / 生成中 / 视频已生成 / 生成失败
- 不得用“已连接”“已完成”掩盖只保存配置、只返回脚本或未读取正文的事实。
