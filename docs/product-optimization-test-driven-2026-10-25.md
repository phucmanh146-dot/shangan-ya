# 上岸鸭原有功能优化方案｜以真实试用为驱动，不重做产品

更新：2026-10-25
基线参考：PR #42（`captain/real-artifact-gap-review-20261024`）、当前 `feature/orchestrator-agent` 分支的 `team_orchestrator.py` / `action_planner.py` / `learning-agent/README.md`，以及队长提供的 2026-10-18 至 2026-11-10 试用计划截图。

## 0. 产品决策

**沿用原有上岸鸭，不另起一套“验收系统”。** 优化只加在既有导航路线、竞赛模式、任务/动作卡、队长总控、卡点救援、日程重排、版本/证据与复核流程之上。旧入口和旧数据必须继续可用；不把“省奖验收”做成所有用户都必须走的强制流程。

当前可见的实现边界：
- 已有：目标到路线、来源/依赖/交付物、任务拆动作、时间容量/依赖排程、预览后采用、执行反馈、任务锁定与版本保护、提交待验收、卡点图片/视频、跨会话保存、求助关联动作。
- 已有但需集成回归：A/B/C 交接、版本化计划、周期/突发占用调整、逐条件人工复核。
- 关键缺口：A 的真实材料诊断模块尚无可调用交付；B 的行动卡仍可能退回通用三步；真实模型未配置时容易只有规则草案；主工作台与导航路线仍分别保存；成员认证/权限隔离尚待集成；缺少完整的独立执行 V2 → 复核 → 剩余项重排真人证据。
- 不应再花主要精力堆验收文档或增加测试计数。接下来每项改进都必须改善队友的实际使用，并保留功能回归证据。

## 1. 按截图计划反推：当前没优化到位的功能

## 2. 功能完整性：要保留的旧能力及其防退化测试

以下是回归保护清单，不允许为新增省奖流程而删除或重命名旧功能：

1. 原有学习导航/竞赛路线入口仍可用；竞赛要求来自用户指定的真实赛事，不硬编码单一比赛。
2. 公开网页搜索、读取、来源引用、工具轮数上限和搜索失败提示仍保留。
3. 任务拆动作：首步 ≤5 分钟、普通动作 ≤25 分钟；每步有成果/成功标志/失败方向。
4. 用户选任务和空档后才排程；每日容量、依赖、缓冲、已完成任务、锁定时段和突发占用保护有效。
5. 排程修改先预览再采用；支持撤销/恢复，不能覆盖 in_progress、pending_review、completed、locked。
6. 截图/视频卡点救援、指定视频秒数、继续补图追问、失败信息与来源缺失提示保留。
7. SQLite 持久化、刷新/重启恢复、中断状态显式化；不得把请求中断标成完成。
8. 执行证据、实际用时、复核包导出/接收、逐条件人工验收与失败项重排保留。
9. 样例、模拟、真实模型、真实作品、真人试用分开标识；mock/fixture 不得显示成 live pass。
10. 旧工作台和导航路线当前分别保存；集成时应做迁移兼容，不允许静默丢弃历史任务。

## 3. 建议交互结构（不另起应用）

- **首页/继续上次**：继续进行中的任务；明显显示“模型是否可用”和未保存变更。
- **快速试做**：3 分钟 demo，完成后可选择清空样例或“转为我的项目”。
- **我的项目**：真实材料、赛事/目标、原件版本、A 诊断和缺口。
- **今日行动**：最多显示一张“下一步”主卡；其他步骤折叠，突出 5 分钟起步。
- **卡住了**：图片/视频、指定秒数、补充上下文；返回同一行动卡而不是新开孤立对话。
- **队友交接**：只读行动卡→独立执行→上传 V2→A 复核→剩余项重排。
- **进度与对比**：完成证据、耗时、求助/返工、V1/V2；不把完成勾选等同于质量通过。
- **提交前**：隐私、来源/授权、AI 使用披露、测试链接/账号、视频和回执清单。

## 4. 实施顺序（按依赖，不按“功能看起来多”）

### Sprint 0：保功能与基线（先做）
- 冻结当前集成分支 SHA、现有未提交修改清单和数据库备份。
- 列出 PR #21/#22/#25/#35/#39 的 base/head、重叠文件、CI 与合并依赖。
- 生成旧功能回归表；在同一分支记录 Python + 浏览器全套测试结果。
- 任何冲突先拆成小 PR，不直接覆盖队友修改。

### Sprint 1：可用的核心闭环（最高优先级）
1. A 真实材料入口和 grounded gap 输出（含文件 hash、页/段 locator、解析覆盖率）。
2. B 任务卡强制字段：`target_locator/action/reason/expected_change/output/self_check/failure_next/source_refs/owner/dependencies/estimate`。缺任一核心字段时标 BLOCKED，不退回通用“完成目标并检查”文案。
3. 五态任务 UI 与后端状态机一致；版本冲突/旧计划/重复提交有可理解的提示。
4. 非作者交接、真实 V2 上传、A 独立复核、B 只重排 FAIL/UNKNOWN。
5. 每个节点有恢复点；模型失败时可手动继续，不丢原件/行动卡/证据。

### Sprint 2：3 分钟冷启动与使用体验
1. 样例 + 半填空模板 + 一张行动卡。
2. 解释阶梯、休息接续卡、可关闭的轻提示。
3. 手机窄屏、弱网、上传失败、返回任务后的恢复。
4. 确认旧工作台/导航数据不会因新流程迁移丢失。

### Sprint 3：真实试用与成果输出
1. 5–8 名同学完成试用（同意、去敏、任务难度记录）。
2. 上岸鸭与豆包/ChatGPT 进行同类任务对照；平衡任务顺序，避免只让熟练用户用某一组。
3. 记录四个指标的原始分母与个体记录：完成耗时、求助次数、首次验收通过/返工次数、独立盲评质量。
4. 自动生成结果页/PPT 草稿和 CSV，数字可回溯到原始记录。
5. 录屏自测 3 次、修复高频问题、保存提交回执；任何隐私/授权/学术诚信硬性项未确认则不标“可提交”。

## 5. 技术验收门（工程门与用户门分开）

### 工程门
- 原有测试全过；新增功能单测/浏览器测试全过；无旧功能回归。
- 同一任务跨刷新、跨服务重启可恢复；过期版本和非法状态转移被拒绝。
- 没有真实模型配置时，UI 清楚显示未配置，不能伪装成 AI 已调用。
- 文件上传对大文件、图像、表格、解析失败提供明确覆盖率和失败定位。
- 导出数据去敏、只导出用户授权范围；不把密钥或敏感原文写入日志。

### 用户门
- 新用户在 3 分钟内完成第一张卡。
- 非作者执行人可独立完成一张卡并提交 V2。
- A 能按原件 locator 复核；B 只重排 FAIL/UNKNOWN；C 能追溯版本/证据。
- 对照试用至少有原始数据、相同任务难度说明、明确分母和匿名化记录。
- 用户能关闭轻提示、休息后续接，并且不会丢失任务。
- 用户可在不知道术语“诊断版本/计划版本”的情况下理解状态、下一步和阻塞原因。

## 6. 不能做的优化
- 不删原有导航、卡点救援、排程、证据、版本保护功能来换一个新首页。
- 不用“93/93 测试通过”或浏览器 fixture 数量证明模型效果或用户价值。
- 不把规则生成草案说成模型输出；不把 V2 批注说成真实作品 V2。
- 不把“省奖质量门槛”硬编码成某一赛事官方评分。
- 不默认把用户原始材料发送到外部模型；导入前显示数据去向/是否联网，敏感材料先脱敏。
- 不自动改写用户原稿或覆盖旧版本；修改先预览、确认、留存版本与差异。
- 不让玩笑、休息提示、演示样例打断正在提交/复核的严肃流程。

## 7. 当前优先决策

先做 **Sprint 0 + Sprint 1 的前四项**，而不是同时铺开所有体验功能。它们直接修复截图中“接通、五态、交接 V2、A 复核、对照测试”的核心风险，也最能保护原有产品。等真实闭环跑通，再做冷启动、解释阶梯和结果页。
