# 总调度新版任务分配｜用真实作品测试私人定制方案，按失败原因迭代 Agent（2026-10-23）

## 这轮测试的目的（请三人先统一认知）

**不是让 Agent 给每个项目生成一份方案就算完成，也不是证明我们已经达到省一。测试的目的，是用真实的“当前作品 V1 + 对应赛事目标/官方评分标准”找出 Agent 哪个环节做不好，再针对失败原因优化代码/工作流/提示词，复测同一案例，确认问题真的改善。**

每个样本都要回答：
1. Agent 是否识别了当前作品和真实目标之间的具体差距？
2. 是否只使用可回查的原件证据与官方标准，不编造？
3. 是否能生成适合这个项目、这个人的下一步，而不是通用三步？
4. 另一个人只看行动卡，能否独立做出真实修改？
5. 真实 V2 是否通过原标准复核？
6. 中断、材料缺失、解析失败、步骤无效时，Agent 是否正确恢复/换法/阻塞？
7. 测试失败后，我们改了什么，复测是否改善？若没有改善，是否缩小或停止该功能？

## 一、每人负责几个项目

采用“**主责项目 + 全队交叉验收**”。A 主责 3 个、B 主责 3 个、C/队长主责 2 个；每个项目仍必须经过 A 证据诊断、B 行动卡、真人执行、A 独立复核、C 记录与重排，主责不等于可以跳过其他角色。

| 主责 | 项目 | 为什么这样分 | 主责交付 |
|---|---|---|---|
| A：材料/证据主责 | 嘉农芯生 | 技术指标、专利/效率主张，适合检查证据和计算口径 | 原件/标准登记、差距表、证据定位与未知项 |
| A：材料/证据主责 | 滴水润疆 | PPT/PDF 图文覆盖和数据对照风险，适合测解析完整性 | 页覆盖清单、OCR/视觉复核、指标证据表 |
| A：材料/证据主责 | 菌润乡土 | 旧 DOC 解析阻塞、技术和损耗/收益数据 | 文件可读性验证、原件 locator、缺证清单 |
| B：行动卡/真人执行主责 | 文玩玉米《小玉米也有大乾坤》 | 收入、成本、利润、亩产值需要转成可复算的具体动作 | 私人定制行动卡、单位经济表、真人执行日志 |
| B：行动卡/真人执行主责 | 本草云联 | 接口现状、计划对接、服务责任需要拆成流程核验动作 | 现状/证据/阻塞表、服务链行动卡和 V2 |
| B：行动卡/真人执行主责 | 湘秀未来（湘匠织秀） | 用户需求、纹样授权、工艺、报价、交付、收益分配需要项目专属验证 | 产品验证卡、真实修改 V2、订单/工时/返工证据状态 |
| C/队长：集成与验收主责 | 数智助老·泉城护航 | 需核对服务流程日志、基线和效果指标，验证真实闭环 | 端到端 trace、真实任务记录、独立验收和问题单 |
| C/队长：集成与验收主责 | 无界智泊 | 需严格区分项目自有试点、第三方案例和模拟数据 | 证据来源隔离、真实流程/授权状态、模拟与真实测试分开记录 |

**所有项目原件链接尚待核验。** 表格是任务分配，不表示原件已经打开或 Agent 已经测过。先登记真实文件名、版本/hash、可访问链接、赛事年份/赛道及官方评分标准；任何一项缺失，状态标 `blocked`，不得假称已运行。

## 二、每个项目都按同一套测试协议跑，但方案内容必须个性化

### 阶段 0｜建立基线（A 主责）
- 保存 V1 原件及版本/hash；登记官方目标、赛道/年份、评分项。
- 选 3 条有原件定位的关键差距；区分事实、推断、未知。
- 没有标准或材料时，记录缺什么以及如何补，不生成猜测。

### 阶段 1｜测试 Agent 初诊（A + C）
- 保存完整输入、Agent 输出、模型/代码版本、调用与来源 trace。
- 对照人工基准逐条评估：差距是否真实、证据是否存在且支持结论、是否混淆版本/项目。
- 失败分类：材料读取、上下文串项、引用/证据、目标理解、差距诊断。

### 阶段 2｜测试私人定制方案（B 主责）
每条 gap 变成行动卡，必须包含：
`project_id / input_version / target_locator / action / reason / expected_change / output / self_check / failure_next / capability_basis / source_refs`。
还必须有 1–5 分钟首动作、依赖、预计时间、实际时间、求助条件。没有证据支持的 gap 不得生成具体修改要求。

### 阶段 3｜盲执行（非行动卡作者）
- 执行人只看行动卡，不听作者口头补充。
- 记录是否在 5 分钟内开始、是否知道改哪里、是否产出可检查的小成果、卡点和用时。
- 不能独立开始或产物不符合验收，就标失败并记录原话/具体卡点。

### 阶段 4｜真实 V2 和独立复核（A + C）
- 保存真实修改后的 V2 文件和版本/hash；截图仅作辅助，不能替代原件。
- A 按冻结的原标准逐条判 `pass/fail/unknown`，标出 V2 的精确位置。
- B 只针对 fail/unknown 项重排；已完成/进行中/锁定任务及依赖不得被覆盖。

### 阶段 5｜按失败原因优化 Agent（C 总控）
每次迭代只针对证据定位的根因改相应模块：
- gap 泛化、证据乱引 → 改 A 诊断/locator 校验；
- 仍回退到“打开材料→完成目标→检查” → 改 action_planner 的通用三步 fallback，无 grounded micro_steps 时必须 blocked/unscheduled；
- 任务恢复串项目/串版本 → 改状态寄存器、项目确认和版本冲突保护；
- 一直重复无效方法 → 改循环的换法/求助/停止条件；
- 把不相关材料塞进上下文 → 改 context assembly 和来源隔离；
- 工具失败却输出成功 → 改工具调用结果状态与证据门；
- V2 未复核却显示完成 → 改 completed/pending_review 状态门。
每次改动记录 commit、测试用例、失败前结果、修复后结果；复测同一失败样本和相关回归样本。不得因为重写提示词就直接宣称创新成立。

## 三、创新点怎么验证

五项机制都要有可观察的测试，不以“界面有按钮”作为通过：

1. **任务状态寄存器**：刷新/重启后是否恢复同项目、同版本、同 locator、已完成项和下一动作。
2. **循环机制**：同类帮助两轮无效后能否换策略、求助或停止；不会无限重试；V2 未过只返回未过项。
3. **上下文管理**：不同项目/版本的材料是否隔离；“看不懂”与“累了”是否触发不同路径；来源可回查。
4. **工具调用**：实际工具结果、失败码、链接、文件版本可追踪；工具失败不伪装成功。
5. **跨对话记忆**：新对话说“继续昨天那个”时先确认项目，再恢复正确存档；不确定时询问，不串项目。

每个机制至少记录一条成功、一条失败/边界案例；如果未发生，标未测，不能填通过。

## 四、首轮顺序与每人任务数量

### 第 1 轮：三个不同格式/问题类型的代表样本
1. A 先完成嘉农芯生的输入登记和 3 条证据差距。
2. B 选择文玩玉米，测试从差距到可复算行动卡并让非作者盲执行。
3. C 选择数智助老，检查工具 trace、服务日志证据、V2 状态门与复核。
4. 三人互换检查记录，定位 Agent 失败根因；C 选一项最有证据的根因做代码/工作流修复并复测。

### 第 2 轮：其余五个样本
- A：滴水润疆、菌润乡土。
- B：本草云联、湘秀未来。
- C：无界智泊，并复核所有项目的版本/证据状态。
- 以上项目仍需跨角色执行盲测和独立复核，主责只负责推动交付，不自己给自己判通过。

### 第 3 轮：跨项目回归与对照
- 对同一真实任务比较通用助手与 Agent，使用相同材料、相同标准、相近时间/工具预算。
- 记录：证据可核对率、行动卡独立执行率、首个可检查产物耗时、V2 原标准通过率、恢复正确率、错误项目/版本次数、人工介入、成本。
- 样本少时只报告案例和描述统计；不得声称统计显著、普遍提升或提高省一概率。

## 五、每个项目提交的统一证据包

- `00_manifest.md`：原件链接、版本/hash、赛事标准、项目主责。
- `01_v1_snapshot`：测试前原件与关键 locator。
- `02_agent_trace`：输入/输出、模型与代码版本、工具调用和错误。
- `03_gap_review.md`：A 的 3 条差距及来源。
- `04_action_cards.md`：B 的行动卡。
- `05_blind_execution.md`：执行人、用时、卡点、实际产物。
- `06_v2_artifact`：真实修改后的文件。
- `07_review.md`：A 的 pass/fail/unknown 及证据。
- `08_replan.md`：B 只重排未通过项的差异。
- `09_iteration.md`：C 记录根因、修改 commit、修复前后对照。
- `10_decision.md`：go/revise/stop 与未解决问题。

## 六、停止/验收门槛

一个项目只有同时满足以下条件，才叫“该轮闭环通过”：
- 原件和官方标准真实可访问；
- 3 条关键差距可回查；
- 至少一张行动卡由非作者独立执行；
- 有真实 V2 原件和版本记录；
- A 按原标准独立复核；
- 剩余任务重排不破坏已完成项；
- Agent 的失败根因和修复复测记录可复现。

“闭环通过”只表示本轮 Agent 测试闭环通过，不代表项目达到省一等奖。省一目标是否接近，要看具体赛事官方评分项和项目证据逐条达成。
