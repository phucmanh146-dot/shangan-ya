## 二、总目标与验收原则

本轮目标不是再堆功能，而是证明上岸鸭能把真实资料转化为可执行的改进，并且不靠口头解释也能完成复核：

`目标标准 → 原作品V1 → A证据差距(gap) → B微行动卡 → 执行者修改 → 真实V2 → A独立复核 → B只重排剩余问题`

必须同时满足：
1. 证据可追溯：每个判断都能定位到材料/版本/段落或代码位置。
2. 动作可执行：每一步说明改哪里、怎么改、产出什么、如何自检。
3. 结果真实：有真实文件、调用日志和版本差异，不以模板、mock 或口头汇报代替。
4. 复核独立：复核者按原始判据看新版，不只看作者的“已完成”描述。
5. 失败可见：资料缺失、模型失败、版本冲突应标为 unknown/blocked/failed，不伪造成功。
6. 对标有边界：省一作品的公开资料只能支持公开可见的做法；没有原始评分表或内部数据时，不推断其真实技术架构或分数。

### 省一对照判定表（每个样本必须逐项打分并附证据）

| 维度 | 通过标准 | 不通过/阻断条件 |
|---|---|---|
| 真实问题 | 有真实任务目标、使用者和输入材料 | 只有抽象痛点或虚构业务背景 |
| 创新差异 | 明确说明与普通大模型直接回答相比，哪一步有独立价值 | 只是换提示词、换界面或增加 Agent 数量 |
| 证据链 | 每个gap都能回到V1具体位置，参考方法也有来源和locator | 只有模型总结、无定位引用或引用不支持结论 |
| 可执行性 | 未参与编写的人只看行动卡就能操作并交付产物 | 依赖口头解释；“优化一下/继续完善”等空泛指令 |
| 真实验证 | 有实际V2、独立复核、失败记录和同条件对照 | 只有截图、静态Demo、模拟响应或作者自评 |
| 稳定性与恢复 | 错误清楚暴露；不会假成功、静默换模型或覆盖已完成结果 | 错误被吞掉，旧结果被冒充新结果 |
| 可复现与合规 | 固定代码/数据版本；来源和授权清楚；密钥脱敏 | 无法复现、素材授权不明、密钥或敏感请求泄漏 |

每个样本按 `pass / fail / unknown / blocked` 标记。不能用总分掩盖任何关键阻断项；“省一差距”报告必须说明证据来源，未取到的材料明确写“待取证”。

**交接规则：**
- A每交付一个gap，B才可生成对应行动卡；A未提供证据时，B任务保持 `blocked/unscheduled`。
- B完成行动卡不等于任务完成；必须有真人执行的产物及版本差异。
- V2提交后进入 `pending_review`，由A按原标准复核。
- A复核完成后，B只重排未通过/未解决项；不得覆盖已完成、进行中或待复核任务。
- 队长抽查不代替A的独立内容复核，也不代替真实用户测试。
