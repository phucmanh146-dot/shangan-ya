# 科研陪伴Agent：第一期产品宗旨、PRD与本轮Demo交付
日期：2026-10-31。沿用上岸鸭工程；只以湘秀未来作本轮材料案例。小程序备案已按用户澄清排除。

## 第一部分：产品到底服务谁、解决什么
目标用户是已有科研/创新任务、但目标表达、材料整理、方法与工具能力不同的学生。现象是“想成为高手，却讲不清今天做什么；反复拖延，直到截止才发现来不及”。这是待真实用户验证的问题，不能根据一次对话诊断人的心理或意志力。
价值主张：帮助用户把模糊愿望变成今天能开始、能检查的小产物；不替用户完成科研、不承诺论文录用或获奖。
三大边界：不代写可提交论文段落或虚构数据/引文/访谈；做陪伴与澄清；按当前能力分步解释并核对真实产物。
第一期成功不看聊天次数，而看用户能否说清当前产物、是否实际开始、留下什么、卡住后是否恢复以及结果是否通过复核。目前这些用户效果尚未实测。

## 必查三件事
1. 你现在最想交什么？谁会看，什么时候交？如果只说“成为高手”，保留愿望，再确认今天的一行/一处产物。
2. 手里有什么？文件、页码、数据、已做进度；没有材料也可明确说没有，不能凭自述推断读过材料。
3. 卡在哪里？术语、方法、资料、环境、范围太大或疲惫；再问实际可用时间和工具，不要求一次填完复杂PRD。
系统复述“我理解你要在X前完成Y，现在有Z，卡在W，先做这一小步”，由用户纠正或确认后再安排；对话式多轮澄清仍是下一轮要补的能力，本轮实现为结构化三问与规则提示。

## 第二部分：已实现的第一期路径
现有工作台新增“今天先迈出哪一步”窗口：
三问澄清 → 用户确认今日小产物/第一动作/可用分钟/带时区截止时间 → 保存后端 → 页面打开时每15秒检查 → 剩10分钟询问进度 → 选择继续、求助、拆小、暂停或提交待复核 → 保存现场。
今日任务不会静默修改原计划、延长原DDL或把用户自述完成变成质量通过。修改今日任务形成新版，保留旧进度事件。已回复不会对同版到点反复弹窗；提前回复进度不会吞掉后续10分钟提醒，改截止后重新提示。
提醒是询问“现在做到哪、能交什么、哪里卡住”，不是机械催促。缺资料先保存求助卡；环境错误先保存报错及已试方法；疲惫先保存现场、休息或主动缩小范围；不懂只讲当前术语/操作。所有帮助目前为规则建议，不冒充模型已准确理解每个人。
关闭页面、后台限流、电脑休眠或断网时不保证定时通知；本轮未实现微信订阅消息、系统后台推送、短信或持续监控。

## 湘秀未来的一个专属首步
已有材料显示访谈与机构联系，不能再写“完全没有调研”。用户若有访谈附件且能力未知：打开一份现有访谈，只摘录一条用途或预算原话，填写“原话—原文位置—需求—对应产品—未知项”，得到一行需求卡。
若已证明会提取需求，跳过摘录练习，检查该需求与一款产品/样品的对应关系；若没有附件，第一步改成列明缺哪份附件与向谁求助，不编访谈。
上面的卡是待真人确认的产品设计示例，不冒充本轮模型成功输出。前序湘秀真实摘录调用有引用失败；当前仍不能宣称模型诊断稳定通过，更不能宣称业务成交或真人V2已验收。

## Agent架构：每层各自负责
输入层：当前材料版本/定位、三问答案、任务与判据；自述不作能力认证。
对话与诊断层：模型接收澄清后的今日条件；科研陪伴边界写入系统约束；读取原文、提出差距、保留unknown，仍受引用校验。
行动层：根据当前微动作、能力证据、工具与时间分流；未知先试做、失败补当前方法、已验证才跳过。目标是一个可见小产物，不是完整课程或一串泛泛建议。
调度层：研究陪伴状态保存在既有项目数据库，按project/version和卡revision避免旧页覆盖；正式计划/执行/复核仍沿用原链。
支持层：前台10分钟进度询问、主动求助、拆小与暂停；两轮无产物升级求助等原机制保留。
成果层：提交真实V2→非执行者复核→只重排剩余；日常check-in不越过独立验收门。
本轮没有强制增加框架、向量库或新Agent数量；也没有证据证明全学科专业知识库已经接通。

## 本轮验证与还缺什么
新增9项陪伴模块用例：精确10分钟边界/逾期、时区拒收、早回复不吞提醒、求助不改正式计划、无产物不得提交且提交待复核、旧卡旧版本拒收、项目隔离、改截止重启提醒并保留历史、后端重读持久化。
HTTP实际工程演练：创建显式标注的模拟项目，保存9分钟后截止→today返回due_soon和show_checkin=true→求助后不再同版提示，DDL不变、正式计划未改。它是工程测试，不是用户行为数据，也没有真的等待10分钟。
JS语法检查通过。完整回归结果随日志交付；模型日常条件投影与原引用约束的相关回归通过。可视浏览器插件缺少browser-service.mjs组件，本轮无法做前端点击和真实弹窗截图验收。
豆包参考地址本轮web读取失败，浏览器也未连通，因此未声称读取它的concepts内容。当前设计依据用户这轮文字及既有PRD，不猜测对方demo的功能。
还缺三项：真正多轮对话式需求澄清；一名真实学生从三问走到小产物和复核；前端可视点击及后台提醒能力分别验收。第一期不代写的语义边界也需要真实模型反例评测，不能凭一条系统提示声称绝对保证。

## 一页Demo演示顺序
1. 从专属链接打开湘秀未来项目，看到原材料与今日窗口。
2. 用自己的话写“想交什么/现在有什么/卡在哪”，选一个可检查产物和截止。
3. 保存后刷新，确认任务仍在；可以主动点“报告进度/我卡住了”。
4. 用单独的工程验收模拟项目演示9分钟后截止时提示，不把测试时间伪装真实用户DDL。
5. 选择缺附件求助或暂停，确认现场保留、截止不变。
6. 真实学生之后交一行产物；正式质量仍由非执行者复核。
