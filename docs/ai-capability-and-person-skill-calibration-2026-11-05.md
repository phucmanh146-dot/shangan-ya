# 上岸鸭 vs 执法文书智能生成审核系统：AI 能力与个人能力校准（2026-11-05）

## 结论

执法文书系统是“专业文书任务的 AI 自动处理与审核”路线；上岸鸭不能只追求把它的技术栈照搬过来。上岸鸭的差异化目标是：

`真实 V1 → 证据诊断 → 个性化行动卡 → 真人执行 → 真实 V2 → 非执行者独立复核 → 只重排未通过/未知项`

技术必须提升这条闭环的证据质量、行动可执行性与人的真实能力，而不是用模型调用次数、自动化测试数或模型自评代替成果。

## 一、与执法文书对标

| 维度 | 执法文书系统常见强项 | 上岸鸭当前实现/边界 | 本轮结论 |
|---|---|---|---|
| Agent 编排 | LangGraph 多阶段状态图、条件路由、专家节点/审核 Gate | `research_graph.py` 已有读取→混合检索→模型诊断→证据校验→计划预览→人工确认；节点带 checkpoint/lease | 主流程相近；上岸鸭还需验证复杂分支、重试与真实工具执行 |
| 混合检索 | BGE-M3 dense + Qdrant、BM25 sparse、RRF、Cross-Encoder rerank | BM25/metadata + 可选 Ollama/BGE-M3/Qdrant + 可选 Cross-Encoder；未配置会明确 fallback | 架构方向达到对标；生产服务配置与真实检索集尚未证明 |
| 文档解析/OCR | PDF/DOCX 解析、OCR 回退、领域结构切块 | 原件/版本/SHA/locator 与 OCR 评测脚本存在；OCR 实际准确率仍需扫描件标注集 | 证据版本管理更贴合上岸鸭；解析覆盖率需补实测 |
| 结果审核 | 规则校验、专家并行审查、人工 Gate | A 证据 Gate、B micro_steps 校验、C 版本保护、V2 独立复核、remaining-only 重排 | 上岸鸭在“真人执行后验收”上有更鲜明差异 |
| 数据与运行工程 | FastAPI、PostgreSQL、Redis、对象存储、权限、队列、可观测 | 当前仓库同时有本地 SQLite/平台存储与 event kernel；云端 Hub 分支需独立审查，不能把方案写成生产部署 | 生产级多租户、持久队列/对象存储和部署健康度仍是差距 |
| AI 质量评测 | 检索 Recall@K、MRR、RAGAS、OCR/规则命中、延迟、压测 | 已有 reranker/OCR 评测脚本、模型对照实验、调用成本估算；本轮新增逐技能 AI 能力评测 | 从“能跑”推进到“有独立评测”；需真实案例和盲审数据 |

**关键判断：** 对标系统的强项是专业领域的文书生成审核、并行专家审查和成熟检索/评测栈；上岸鸭的创新点不应是再做一个文书 Agent，而是把 AI 的诊断/行动能力和人的技能水平分别测量，再把真人 V2 与独立复核闭环。当前上岸鸭在流程设计和证据版本方面有基础，生产级 RAG、OCR 准确率、服务部署和真实业务效果尚不能判定超过对标系统。

## 二、AI 能力和个人能力必须分成两条量尺

### 1. AI 能力：按技能、按真实案例评测

新增 `learning-agent/ai_capability_evaluation.py`。它只评估可确定性核验的项目：
- 输出结构是否完整；
- 诊断 Gap 与人工标注答案的匹配；
- 引用是否精确命中当前材料的 artifact/version/locator/quote；
- 必须标记的 UNKNOWN 是否被如实保留；
- 行动步骤是否具备输入版本、目标位置、动作、理由、预期变化、产物、自检、失败下一步和能力依据；
- 是否存在真实 LIVE 模型 ID 与 trace ID。

任何错版本/伪引用/缺失必须 UNKNOWN 的案例都会触发 hard fail，最高分封顶 49。Mock、SYNTHETIC 或缺少真实 trace 的运行不计入 AI 真实能力认证。

### 2. AI 逐技能能力等级

| 等级 | 门槛 | 系统可做什么 |
|---|---|---|
| unverified | 少于 5 个不同 LIVE 案例，或没有独立人工复核 | 仅测试/草稿，不得自动放行 |
| blocked | 至少 5 个盲审案例，均分低于 70 或存在硬失败 | 停止该技能的自动生成，先修复 |
| draft_only | 5 个以上盲审案例，均分 70–79 | 仅生成候选，人工逐项检查 |
| supervised | 5 个以上盲审案例，均分 80–89 | 可辅助执行，关键步骤需人工确认 |
| validated_assisted | 5 个以上盲审案例，均分至少 90 | 可按授权范围辅助执行，仍保留抽查与复核 |
| validated_bounded | 至少 10 个不同盲审案例、覆盖至少 3 种任务类型、均分至少 95、无硬失败 | 只在已验证的任务边界内提高自动化；高风险仍需人工确认 |

每个技能单独计算，例如“材料证据定位”“论文结构诊断”“PPT 证据表达”“代码调试”“研究方法设计”。不允许把一个技能的高分扩展成“模型什么都会”。

### 3. 个人能力等级：按成员、按技能、按真实产物

复用 `research_personalization.py` 的证据规则：
- 无已确认产物：unverified，先给最小试做；
- 最近一次真实验收未通过：needs_support，只补当前缺口；
- 1 个有效通过成果：guided，给清单和反馈；
- 2 个不同任务的有效通过成果：independent，减少讲解；
- 3 个不同任务的通过成果且有迁移验证：transfer，给跨场景挑战。

必须绑定成员确认、判据、真实 artifact_id/version 和通过结果。自我汇报、AI 推断、看完课程、点击完成不能升级能力。

### 4. 双边匹配：谁强不等于谁都强

`match_support()` 同时读取 AI 的技能等级和成员的该项技能等级：
- AI 未验证/blocked/draft_only：人主导，AI 只给建议；
- AI 已验证但成员未知：先做带人工检查的最小练习，不能跳过教学；
- 成员 guided：逐步执行并反馈；
- 成员 independent：独立执行并抽查；
- 成员 transfer：跨场景任务并由同伴复核；
- 高风险/关键动作始终要求人工复核。

AI 能力分数不计入个人能力；个人技能分数也不证明 AI 输出正确。系统必须显示两个等级及各自证据来源。

## 三、AI 测试的标准实验

同一份真实 V1、同一目标标准、同一问题，建立四组：
1. 人工基线：不调用 AI，记录完成时间、错误和成果质量。
2. 普通 LLM：只给同一份材料和任务，不接 RAG/Agent。
3. 上岸鸭 Agent：检索、诊断、校验、行动卡。
4. 人 + 上岸鸭：按个人技能等级提供适当指导，产出真实 V2。

每组由不知道组别的独立复核者按同一冻结判据评分。必须记录：
- Gap precision/recall、引用精确率、错引率、UNKNOWN 召回；
- 行动卡一次可执行率、首步启动时间、失败恢复成功率；
- V2 通过率、返工率、独立复核一致率；
- 人工耗时、AI 耗时、模型调用次数、估算/供应商真实 Token 与费用；
- 每个真实复核 PASS 的 AI 成本、节省的人工时间；
- 失败、未通过和 UNKNOWN 必须进入分母。

字符数除以 4 只能作为 Token 估算；没有供应商 usage/账单就显示 actual_cost=null。没有人工基线和盲审 V2，不得声称 AI ROI 为正或“能力超过个人”。

## 四、A / B 交互评述（阶段性工程交付评分）

> 评分对象是本轮角色交付与可验证工程证据，不是对同学人格、智力或长期能力的评价。真实个人能力仍须按上面的冷启动试做与 V2 证据单独建立画像。

### A｜证据诊断与独立复核：83/100（阶段性）

| 项目 | 得分 | 评述 |
|---|---:|---|
| 原件/版本/引用追溯 | 23/25 | 已有 artifact/version/locator、原文 quote catalog 和引用回查边界 |
| Gap 诊断结构 | 17/20 | 有结构化诊断和 A→B handoff；仍需真实案例证明语义 Gap 的准确率 |
| UNKNOWN/证据门 | 14/15 | 材料不足可阻断，不应猜测；需继续用反例检验漏报 |
| 当前作品与参考案例分层 | 13/15 | 方向明确；逐案例双边 locator 和可迁移方法要有真实样本 |
| V2 独立复核 | 8/15 | 接口/状态已有；真人 V2、非执行者盲审证据不足 |
| 测试/可复现性 | 8/10 | 有诊断契约和证据相关测试；不能代替语义质量盲审 |
| **合计** | **83/100** | **工程交付较完整，真实案例诊断和独立复核是主要扣分项** |

A 下一阶段只抓三件事：从真实案例库挑 3 个不同项目；每个至少给出 3 条双边 locator、逐字引用、判据与 UNKNOWN；对一份真人 V2 做非执行者逐项 PASS/FAIL/UNKNOWN。没有这些证据，不把 83 分提升为个人能力等级。

### B｜个性化行动卡与动态排程：84/100（阶段性）

| 项目 | 得分 | 评述 |
|---|---:|---|
| 微动作具体性 | 23/25 | B 规划器强制真实输入版本、目标位置、动作、产物、自检和失败下一步；缺少 grounded steps 时阻断 |
| 按个人技能补齐 | 18/20 | 已有逐技能 evidence-based support path；需用不同水平成员做对照 |
| 依赖/容量/排程 | 14/15 | 已有容量和依赖约束；还需真实多任务冲突下的排程结果 |
| 卡壳/失败恢复 | 13/15 | 有失败反馈和剩余项重排；要验证不会重复无效动作或覆盖锁定任务 |
| 真人 V2 与执行收益 | 6/15 | 当前真实 V2、独立复核和人工耗时对照不足 |
| 测试/可观测性 | 10/10 | 规划器、交接与回归覆盖较好；工程测试仍不等于真人有效 |
| **合计** | **84/100** | **行动设计工程基础较强，个性化效果和真人成果收益尚未证实** |

B 下一阶段只抓三件事：分别给初学/熟练两名执行者同一真实 Gap；比较两张行动卡是否真的不同；记录首步启动、实际耗时、求助次数、V2 差异和复核结果。不能因为 B 规划器生成得漂亮，就认定执行者已经掌握该技能。
