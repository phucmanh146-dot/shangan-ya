# B 同学独立测试计划｜私人定制行动卡与真实 V1→V2

日期：2026-10-23
目的：**测试上岸鸭能否把有证据的差距转成用户真正能独立执行的微动作，并通过失败案例优化行动卡功能。** 不能把生成一份计划等同于完成任务。

## 1. 当前证据与判断
根据《上岸鸭竞品拆解与过程干预方案》（2026-10-23 上传版）第 1、3–4、8–10、12 页及仓库 Issue #7：
- 行动卡已有版本、位置、动作、来源等工程要求，但“第一步不超过 5 分钟”和“另一人只看卡就能改出 V2”尚未得到真人验证。
- 仓库现有 action_planner 在缺少 A 提供的 grounded micro_steps 时，仍可能回退到“打开材料→完成目标→逐条检查”的通用三步，这是必须优先测试和修复的风险。
- 人做、模型验的成果闭环是候选创新点，但必须拿真实 V1、行动卡、真实 V2 和原标准复核记录证明。

## 2. 主责测试范围
1. 从 A 已验证的 gap 生成项目专属行动卡。
2. 检查每一步是否包含明确的文件/段落定位、动作、原因、预期变化、产物、验收方法、失败后路径和来源。
3. 由未编写行动卡的人盲执行，不允许作者口头补充。
4. 保存实际 V2，与 V1 做差异对照。
5. 将执行失败分类，提交给 C 作为功能优化输入；不得自己给自己的卡判通过。

## 3. 必跑测试用例
| 编号 | 测试输入/操作 | 预期结果 | 失败说明 |
|---|---|---|---|
| B01 | 提供有证据 gap，生成行动卡 | 每一步绑定版本、精确位置、来源和验收点 | 卡片泛化 |
| B02 | 检查首动作耗时 | 首动作预计 ≤5 分钟，执行者可马上开始 | 首步太大 |
| B03 | A 不提供 grounded micro_steps | 生产计划进入 blocked/unscheduled，不能生成通用三步冒充个性化 | action_planner 错误 fallback |
| B04 | 非作者只看卡独立执行 | 不靠口头解释，产出可检查的小成果 | 卡片不可独立执行 |
| B05 | 完成真实 V1→V2 修改 | 保存真实文件、版本/hash 和差异 | 只有截图/描述，无 V2 |
| B06 | A 按冻结的原标准复核 V2 | 每项 pass/fail/unknown，有位置与理由 | 自评代替独立复核 |
| B07 | V2 有未通过项 | 只重排 remaining issues，不覆盖已完成/进行中/锁定任务 | 计划破坏状态 |

## 4. 行动卡必填字段
`project_id, input_version, target_locator, action, reason, expected_change, output, self_check, failure_next, capability_basis, source_refs`；另记录首动作、依赖、预计/实际用时、执行人和求助条件。

## 5. 盲执行记录
- 执行人（非卡片作者）、开始时间、是否 5 分钟内开始。
- 是否无需补充说明即可定位目标文件/位置。
- 实际执行步骤、产物路径/版本、耗时、卡点原话。
- 卡片哪一字段缺失或不准确。
- V1/V2 差异、A 的独立复核结果。

## 6. 优化规则
- 卡片抽象：把动作改成可观察操作，必须绑定真实 locator。
- 首步太大：拆成一个 1–5 分钟可完成的动作并指定产物。
- 缺少失败路径：补充换法、求助、跳过或 blocked 条件。
- 无 grounded micro_steps 仍生成计划：要求代码层拒绝通用 fallback，写回归测试。
- V2 未复核就标完成：状态必须停在 pending_review，直到 A 独立验收。

## 7. 验收门槛
至少完成一条由非作者盲执行的真实 V1→V2；行动卡字段齐全；V2 有版本记录；A 独立按原标准复核；失败案例已转成修复任务并复测。没有真人执行的卡只能标“工程/文案测试”，不能标“可执行性通过”。

**边界：** 一条闭环只能证明该样本成功，不足以宣称普遍优于通用助手；后续需要多位同学、同任务对照数据。
