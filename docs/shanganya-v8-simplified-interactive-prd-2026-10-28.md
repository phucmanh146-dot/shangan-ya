# 上岸鸭工作台 PRD（简化交互版）
版本：V1.0｜日期：2026-10-28

## 1. 产品定位
上岸鸭不是功能堆叠的效率工具，而是一个会根据“今天要做什么、实际花了多久、此刻还有多少精力”动态调整计划的个人工作台。帮助用户在 AI 产品经理学习、内容运营、比赛和 Agent 实践等多条主线之间完成重要任务，同时保留休息与缓冲时间。

**产品宗旨：计划不是拿来逼自己完成的，而是帮助自己在真实精力下完成更多重要的事。**

## 2. 用户问题与设计原则
- 计划按理想状态排满，任务一旦超时，后续安排全部崩盘。
- 遇到难题耗尽精力，缺少及时求助和降级方案。
- 任务、资料、链接和复盘分散，执行时反复切换。
- 休息被当成没完成任务，没有被正式安排进计划。

设计原则：先让用户开始做，再逐步提供帮助；默认简单，复杂功能按需展开；AI、连接器或模型不可用时，不阻断任务记录和手动执行。

## 3. 产品结构：四个主入口
1. **今天**：今日任务、当前任务、精力状态、休息安排。
2. **任务**：按主线管理任务、优先级、预计时长和状态。
3. **资料**：链接、文档、图片、视频笔记，可关联任务。
4. **复盘**：实际耗时、卡点、精力变化和可复用经验。

模型/API、平台连接、详细统计、四象限和时间表放在设置、更多或相关任务的按需入口，不再与主流程并列堆满侧栏。保留现有工作台整体结构与数据，渐进式简化，不要求用户重新学习整套系统。

## 4. 核心交互流程
### 4.1 每日开始
页面只问三个问题：今天最重要的一件事是什么？今天大约有多少可用时间（可跳过）？现在精力如何（低/中/高）？点击“生成今日安排”后，系统给出“优先完成”（最多 1–3 项）、“有空再做”和“休息与缓冲”三组内容。用户可直接开始第一项，也可调整顺序和时长；信息不完整也允许继续。

### 4.2 执行任务
任务卡片只显示任务名、预计时间、状态、关联资料和一个主要按钮。未开始显示“开始任务”；进行中显示“暂停”“我卡住了”“完成”；暂停后显示“继续”“改到稍后”。开始后持续计时，页面切换或刷新不丢失状态。明确区分正在计时、已暂停、计时异常，不以页面初始化时间冒充实时数据。

### 4.3 遇到困难
点击“我卡住了”后出现轻量面板：一句话描述卡点（可选）、添加截图/文档/链接（可选）、“帮我拆解”。AI 优先输出通俗解释、最多 3 步的下一步动作、可打开的参考资料，以及“降低难度 / 暂停稍后处理 / 继续手动做”选项。AI 不可用时，保留输入并允许保存卡点、添加资料、继续计时或暂停。不得伪装读取微信、飞书、Obsidian 或本地文件。

### 4.4 精力变化与动态排期
通过用户快捷反馈获取精力，不默认开启摄像头或推断心理状态。快捷反馈为“精力够用 / 有点累 / 已经耗尽”。系统结合反馈、已耗时和剩余任务提出建议：精力够用则继续；有点累则短休息并缩小下一步；已经耗尽则先休息并顺延低优先级任务。系统先提出建议，用户确认后才改动排期；不自动删除任务，不把休息记为失败。

### 4.5 完成任务
点击“完成”后自动记录实际耗时，并可选填写卡点和一句话复盘。随后只给出一个清晰建议：“开始下一项”“休息一下”或“今天先到这里”，不强迫填写长复盘。

### 4.6 资料关联
资料页支持添加链接、上传文档/图片、保存视频链接，并通过下拉搜索选择关联任务，也可暂不关联。任务卡片直接展示相关资料。进入任务后即可检索资料，不必跳到独立复杂 AI 页面。连接失败时说明原因和权限要求，并提供手动上传或粘贴链接的替代方式。

## 5. 页面需求
### A. 今天
从上到下为：精力快捷反馈、当前任务卡片、今日任务清单（已完成默认折叠）、休息/缓冲提示、添加任务入口。首页不展示大量图表、模型参数或连接器状态；进入后 10 秒内应能开始任务。

### B. 任务
按主线分组，例如 AI 产品经理学习、运营、比赛、Agent/个人项目，用户可自定义。任务基础字段仅包含名称、主线、优先级、预计时长、截止时间（可选）和状态。默认列表视图；四象限和时间表为可选视图。新建任务用短表单，高级字段折叠。

### C. 资料
提供搜索框和添加资料按钮。资料类型包括链接、文档、图片、视频/笔记。每条显示标题、来源、关联任务和可用状态；支持从任务中直接添加资料。

### D. 复盘
只呈现可行动的信息：本周完成任务数、预计与实际耗时对比、常见卡点、低精力时适合的任务类型。数据不足时显示“样本还不够”，不制造精确结论。

## 6. 关键业务规则
- 预计时长由用户设置或系统建议，后续根据同类任务的实际耗时逐步修正。
- 排期必须预留缓冲，不填满每一分钟；默认从可用时间中预留 15%–25%，用户可调整。
- 低精力时优先推荐低认知负荷任务或休息，而不是继续塞入高难度任务。
- 超时只触发提醒和重排建议，不自动判定失败。
- 任务状态统一为：未开始、进行中、已暂停、已完成、已顺延。
- 用户确认前，不得擅自覆盖原排期；任务、计时和复盘数据须可查看、修改和删除。

## 7. AI 与连接器边界
- 模型配置仅在需要时出现；普通任务功能不要求先配置 API。
- API Key 仅在设置页配置，默认掩码显示，不得写入公开仓库或日志。
- 模型不可用时明确显示“AI 暂不可用”，但任务、计时、资料保存仍可继续。
- 微信、飞书、Obsidian 等连接必须真实验证权限和读取结果；未成功读取时如实提示。
- 视频讲解、复杂检索、自动化 Agent 属于增强能力，按需展开，不放进默认主流程。

## 8. MVP 优先级
### P0：必须可用
新建/编辑/完成/顺延任务；今日清单与当前任务；稳定计时、暂停和恢复；精力反馈；休息与缓冲；任务关联资料；卡点记录及 AI 失败降级；持久化保存。

### P1：增强体验
根据历史耗时调整预计时间；列表/四象限/时间表切换；资料检索与文档解析；周复盘和卡点归类。

### P2：按需扩展
多模型选择与 API 文档跳转；视频讲解/生成；微信、飞书、Obsidian 连接器；语音输入、快捷识别和 Agent 自动化。

## 9. 验收标准
1. 不配置模型、不连接平台，也能创建任务、计时、暂停、完成和复盘。
2. 计时持续更新；切换页面或刷新后正确恢复，不重复累计。
3. 卡点文字和附件可保存；AI 失败不会清空输入或阻断工作。
4. 用户反馈疲惫后系统提出休息/降级建议；未经确认不改变其他任务排期。
5. 资料可以关联或取消关联任务，并能从任务卡片进入。
6. 首页只有一个视觉主行动，不同时突出多个互相竞争的按钮。
7. 外部连接失败时展示真实状态和替代操作，不显示虚假的“已连接/已读取”。
8. 桌面与手机均可完成核心流程，按钮、计时状态和错误提示清晰。

## 10. 体验原则
- 一个页面只突出一个主要动作。
- 先做事，再配置工具。
- 默认展示必要信息，复杂能力按需展开。
- 把休息当作计划的一部分。
- 让系统适应人的真实状态，而不是要求人适应理想化计划。
