# 全作品真实样本回归测试与 Agent 创新迭代计划（2026-10-23）

目标：以真实参赛作品、当前版本和对应官方评分标准为输入，验证“证据诊断 → 私人定制微行动 → 真实执行 → 中断恢复 → V2 复核 → 只重排未解决项”的闭环。不是重新做通用学习路线，也不是只测单个项目。

**边界：** 不承诺省一。最终验收以对应赛事官方规则、赛道评分表、提交要求为准。参考作品的获奖级别必须独立核验；目录名、文件名和截图标签不是官方获奖证明。

## 1. 要验证的创新主张

1. **真实作品差距诊断**：每个差距绑定原件、版本、页/段/代码位置、原文证据和标准来源。无证据输出“未知 + 补证路径”，不得编造。
2. **私人定制第一步**：按用户现有能力、可投入时间、截止日期、任务依赖和材料条件生成 1–5 分钟可开始的动作；每张行动卡都有可提交小产物、完成定义和自检办法。
3. **失败后换路径**：记录尝试、失败原因和用时；方法不清、操作报错、材料缺失、中断遗忘分别走不同分支。重复无效两轮后生成求助卡。
4. **精确中断接续**：保存任务 ID、作品版本、材料锚点、已完成产物、已尝试方法、下一动作和恢复条件。
5. **人做、Agent 按原标准验**：用户提交真实 V2 后，逐项判定通过/未通过/未知；缺证不能放行，旧版本复核不能覆盖新版本。
6. **只重排剩余项**：依据 V2 未通过项、真实用时和依赖生成预览；保护已完成、进行中、待验收、锁定任务及其依赖，用户确认后再采用。
7. **低打扰状态分流**：由用户主动选择看不懂、走神、疲惫、做不动、遇到困难；验证干预后是否回到原任务，不做未经同意的状态推断。

这些是待验证的产品假设。代码存在、界面展示或单测通过，都不能单独证明创新成立。

### 参考作品库的使用方式

现有登记包括万物“互”融计划书、丝科新材、榴金烁果、百年崂山消费者研究、微桥慧测、小桔灯、文案+排版作品、省奖财务作品，以及 PPT 截图/ZIP。按作品类型提炼机制，不复制表面包装：
- 技术/研究：问题—机制—实验/标准—结果—局限；区分实测、引用、计划与预测。
- 商业/产品：用户痛点—差异化—验证—渠道/合作—成本收益；计划不能写成真实订单。
- 市场/传播：样本、问卷/访谈方法、受众、内容证据、传播数据与转化。
- 财务：假设、计算口径、现金流、敏感性分析与可复算结果。
- 图片型 PPT、旧 DOC、低文字提取 PDF：标记覆盖缺口，完成 OCR/视觉复核后才能做内容判断。
- 奖项标签必须核验官方赛事、年份、赛道、级别和公示，不凭文件名声称省一。

## 3. 三人分工与单独批注任务

### A｜真实材料与目标标准诊断
- 登记作品 ID、原件路径/链接、版本标识、可读覆盖率、官方规则链接、赛道/年份、提交物与评分维度。
- 输出逐条差距：目标标准、原件位置、原文证据、证据等级（已核实/待核/未知）、影响和补证动作。
- 说明参考作品中可迁移的机制及不能迁移的条件。
- **验收：** 随机抽查至少 10 条诊断，另一人能回到正确原件和版本；错引、错版、无证据断言被拒绝；覆盖缺口清晰列出。

### B｜私人定制行动卡与独立执行
- 将 A 的差距转成绑定作品版本和位置的行动卡。
- 每卡含首动作（1–5 分钟）、依赖、工具/资料、可交付小产物、完成定义、自检方式、预计/实际耗时、失败替代路径和求助条件。
- 按技术、商业、传播、财务等类型采用不同验收；不以看完教程、生成卡片或点击完成代替成果。
- **验收：** 至少选 2 个不同类型的真实作品，由非卡片编写者独立执行；记录首步耗时、是否需要口头解释、卡点、产物和 V1→V2 差异。

### C／队长｜仓库集成、闭环和证据总控
- 核查 PR #21/#22 的合并状态、分支差异、CI 与未提交修改；先备份，禁止覆盖队友修改。
- P0 修复完成证据门：无真实 V2、逐项复核和必要人工确认时，不得标为 completed。
- 打通真实作品诊断、行动卡、执行日志、中断恢复、V2 复核与剩余项重排。
- 维护 go/revise/stop 决策；工程测试、模型测试、真人测试分开统计；未配置真实模型时明确阻塞，不用 Mock 冒充效果。
- **验收：** 正常流程与关键失败流程可复跑；无证据完成、错误版本、跨项目数据、错误锚点被拦截；只重排未通过项，用户确认后才应用。

## 4. 端到端回归用例

| ID | 情境 | 预期行为 | 通过条件 |
| --- | --- | --- | --- |
| T01 | 真实 V1 + 官方评分标准 | 诊断绑定原件位置与标准 | 每条可回查，缺证标未知 |
| T02 | 首次用户、时间有限 | 生成 1–5 分钟首动作 | 有具体产物和验收办法 |
| T03 | 图片/PDF/旧 DOC | 显示覆盖率和解析失败 | 不把不完整解析当全文 |
| T04 | 方法不清/操作报错 | 记录尝试并给替代路径 | 不重复同一无效建议 |
| T05 | 材料缺失 | 生成补证/求助卡 | 不编造数据或引用 |
| T06 | 任务中断后恢复 | 回到正确任务、版本、位置 | 不重复收集已保存背景 |
| T07 | 无 V2 强行完成 | 拒绝 completed | 返回缺失证据与下一步 |
| T08 | 旧版本/旧回调提交 | 拒收或标冲突 | 新版本状态不被覆盖 |
| T09 | V2 部分未通过 | 逐项通过/未通过/未知 | 每项绑定 V2 证据和原标准 |
| T10 | V2 后重新排程 | 只重排未通过项 | 已完成/锁定项与依赖受保护 |
| T11 | 用户选择疲惫/走神 | 低打扰、可退出分流 | 不自动改变成果状态 |
| T12 | API/模型不可用 | 明示阻塞并提供离线路径 | 不假称已完成模型诊断 |
| T13 | 对比通用助手与 Agent | 同作品、同标准、相近预算 | 留存两组输入、产物、用时、成本、盲评 |
| T14 | 终止检查 | 检查未解决项、证据和复核 | 缺关键证据不得宣布闭环通过 |

## 5. 指标与证据分级

记录 5 分钟启动率、行动卡独立执行率、恢复正确率与耗时、真实 V2 合格率、复核误放行/漏检/未知比例、重排差异、用户负担和调用成本。
- E0 设计假设：尚无测试。
- E1 工程证据：单元/接口测试通过，不代表模型或真人有效。
- E2 模型证据：真实模型、固定输入、可复跑日志。
- E3 真人任务证据：独立执行人、真实产物与用时。
- E4 独立复核/对照证据：原标准盲评、V1/V2 对照和失败样例。

没有测量就写未测量，不得编造提升百分比或获奖概率。

## 6. 实施顺序与依赖

1. A 冻结官方标准与样本登记；C 核对仓库 PR/CI 和测试环境。
2. C 修复证据门（关联 Issue #18）；A 提供原标准与样本证据。
3. B 按 A 的诊断生成微行动卡，先执行两个不同类型的真实项目。
4. A/独立复核者检查 V2；C 验证旧版本拒收与 completed 门槛。
5. B 与 C 检查 Issue #19：只重排未通过项，保留既有成果与依赖。
6. C 汇总 Issue #20、#32 的真实任务/用户测试；失败项按证据定位修改。
7. 更新状态、证据链接、实际结果、失败原因和下一步，再决定 go/revise/stop。
