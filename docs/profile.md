我关心的问题很具体：想学习一个新东西，却不知道从哪里开始；做计划时很有动力，真正执行又被一个困难卡住；团队已经做出了一部分成果，却说不清离目标还差什么。

## 代表项目：从目标到成果的执行 Agent

我们三人参考上岸鸭的产品思路，在已有 PRD 的基础上延续开发，我担任队长。PRD 由原设计者设计；我负责把需求、队友交付和产品验证串起来，推进它成为能实际使用的作品。

产品从用户已有的材料与成果开始，先了解目标、现状和差距，再了解每个成员的想法、能力与可投入时间，生成任务和必要的学习路线。用户自己选择今天做什么；执行中遇到困难可以补充文字、图片或视频，再根据真实反馈调整下一步。

### 我的角色

- **需求与范围：** 依据已有 PRD 整理这一阶段必须完成什么，保留原设计意图，明确哪些还待讨论。
- **总控与集成：** 统一入口、数据和接口，把诊断、排程、执行与求助接成一个流程。
- **团队协作：** 划清三个人的交付边界，通过分支与 PR 查看改动、讨论问题和组织联调。
- **体验与验收：** 检查用户能否看懂第一步，能否判断自己做对了，以及出错后是否知道怎样继续。

### 我们重点解决的产品问题

| 问题 | 设计方向 |
| --- | --- |
| 资料很多，不知道选哪条路线 | 根据目标、已有能力与来源证据筛选必要资料 |
| 知道大目标，却无从下手 | 每个任务写明第一步、交付物、预计时间和完成标准 |
| 同一个计划不适合所有人 | 理解成员职责、自己的思路、基础与可投入时间 |
| 计划中途报错或卡住 | 接收截图与录屏，给出下一步操作和成功标志 |
| 临时有事，原计划失效 | 保留已完成内容和固定安排，解释重排影响 |
| 看起来完成了，实际没有成果 | 将完成状态与可核对的产物证据关联 |

### 当前进展

已有本机学习执行模块和 GitHub 开发基线，覆盖任务、日程、执行记录、重排与图片/视频求助流程。三人接下来分别推进诊断研究、行动排程和总控集成。

目前处于开发与联调阶段。真实模型效果、视觉理解、搜索和完整多人流程仍需验证，进度以[项目说明](../README.md)及[验证记录](../learning-agent/VERIFICATION.md)为准。
