# A/B 两位同学工程评述：对标执法文书与交互验收

日期：2026-11-05。
评审对象：A（证据诊断/独立复核）、B（行动设计/排程）；C 是总控集成，不纳入两人分数。
分数仅评价阶段性工程交付，不评价人格、智力或长期个人能力。

## 对标结论

执法文书系统的强项是专业文书工作流：LangGraph 多阶段编排、OCR/文档解析、BM25+向量混合检索、RRF/Reranker、规则风险检查、模型复审、人工审核、审计与质量评测。它优化单份文书的正确、合规和可追溯。

上岸鸭要借用这些技术，但不能照搬文书业务。目标是多项目、多成员、能力不同、DDL 动态变化下的持续执行：

真实 V1 → 原件读取/Hybrid RAG → A 证据诊断 → C 证据门 → B 个性化行动卡/容量排程 → 真人执行 → 真实 V2 → 非执行者独立复核 → C 锁定版本 → B 只重排 FAIL/UNKNOWN/BLOCKED。

## A｜83/100：证据诊断与独立复核

优点：来源、版本、locator、原文 quote、Gap、UNKNOWN/BLOCKED 边界较清楚；A 的结果能作为 B 的输入契约；八项目有限摘录调用中，2 个引用不一致案例被拒收，没有降低证据门槛。

扣分：6/8 只代表结构/引用门通过，不是语义诊断准确率；“仔细阅读原文”等动作仍空泛；八项真人 V2 和非执行者复核仍 NOT_RUN。A 模块本身不等于 PDF/DOCX 解析器或真实模型调用服务。

下一步：3 个不同真实项目，每项至少 3 条 Gap；提供当前作品与目标标准双边 locator、逐字引用、来源版本、判据、差距原因和 unknowns；由第三人抽查，再对真人 V2 逐条盲审 PASS/FAIL/UNKNOWN。

## B｜84/100：行动设计、动态排程与失败重排

优点：已有规则规划器、依赖、容量、估时、拆分、失败反馈和 remaining-only 重排，不是只有 UI 或提示词；具体 micro_steps 缺失时应 BLOCKED/UNSCHEDULED。

扣分：旧分支曾有缺步骤时回退万能动作，后续总控集成才修正；B 的动作质量依赖 A 的 Gap；尚缺初学者/熟练者同题对照、陌生执行者 5 分钟开工、真人 V2 和执行收益证据。

下一步：同一 Gap 分别给能力未知者与已有独立成果者生成不同指导强度的行动卡，目标/验收标准不变；由非编卡者执行，记录首步时间、实际耗时、求助、失败恢复、V2 hash/diff，并由非执行者盲审。

## AI 能力与个人能力必须分开

AI 每个 skill 单独评级：至少 5 个不同 LIVE 盲审案例才离开 unverified；错版本、伪引用、漏报 required UNKNOWN 等 hard fail 最高分封顶 49；80–89 supervised；90+ validated_assisted；至少 10 个案例、3 种任务类型、95+ 且零 hard fail 才 validated_bounded。必须有 model_id、trace_id、任务类型、prompt/index 版本和独立 reviewer。

个人每个 skill 单独评级：无真实产物 unverified；最近一次真实验收失败 needs_support；1 个有效通过 guided；2 个不同任务通过 independent；3 个任务通过并有迁移验证 transfer。AI 生成答案、课程播放、口头自报、点击完成均不能升级个人等级。

AI 未验证时人主导；AI 已验证但成员未知时带练；成员独立后可独立执行并抽查；高风险始终人工复核。不能因为模型强就认定使用者也会。

同一真实 V1/同一判据，比较人工基线、普通 LLM、上岸鸭 Agent、人+Agent；盲审者不知道组别。记录 Gap P/R、引用精确率、UNKNOWN 召回、行动卡一次可执行率、启动时间、V2 通过率、返工、复核一致率、失败恢复、人工耗时和真实账单。无真实 V2/盲审不得报 ROI。

## 本轮工程核验

统一候选分支在独立 D 盘工作树合并 RAG/评测/事件运行时与云端 Hub/浏览器证据桥。合并时发现并修复：shared_api.py 的 CORS 语法残缺、重复 root/assets 路由、Hub JS 静态资源错误路径；清理 cloud_hub.py 重复 schema 声明；AI 技能认证补充 model_id/trace_id/task_type 必填门槛。统一候选已通过 PR #103 合并到 main（提交 `9538e6c`），CI 的 event-kernel 与 regression 两项均成功；生产服务和真实业务验收仍未完成。

**最新完整回归：415 项 Python 单元/集成测试通过**（独立 D 盘 venv，安装 FastAPI/Pydantic、LangGraph、Qdrant、tzdata 等工程依赖）；compileall、前端 JS 语法检查、git diff --check 通过。Chrome + Playwright 浏览器 E2E 通过：创建、A→B Demo、采用前预览、开始、提交待复核、刷新持久化、带证据复核、API 状态、移动端无横向溢出。该 E2E 使用明确的工程 Demo 夹具，不是 LIVE 模型或真人科研 V2；不能把它计入业务收益。

云端 Hub 是受控任务/证据桥接，不等于它本身会无监督自主执行所有任务；实际 Worker、ChatGPT Action、浏览器扩展配对、Railway 持久化共享和跨会话恢复仍需线上实测。

## 最终结论

A 目前强在“证据诊断的结构与追溯”，短板是语义支持性和真实 V2 独立复核。B 目前强在“规则排程与行动组织”，短板是按真实能力差异生成可执行动作、陌生人执行成功和实际收益。两者不能互相替代：A 的证据不过门，B 不得编计划；B 的行动卡不能被真人照做，A 也不能说项目已改善；最终由 C 保存状态、版本、事件、复核和恢复轨迹。

**不是终止任务**：当前所有 NOT_RUN/blocked/failed 项应保留负责人、下一动作、恢复条件和复测标准；只冻结依赖用户拍板的动作，其他独立任务继续推进。
