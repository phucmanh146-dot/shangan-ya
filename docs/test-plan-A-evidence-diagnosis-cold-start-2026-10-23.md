# A 同学独立测试计划｜资料接入、冷启动与证据诊断

日期：2026-10-23
目的：**通过测试找出上岸鸭资料接入、冷启动、RAG/诊断的缺陷并优化功能**，不是证明已有功能“看起来完整”。

## 1. 当前证据与判断
根据《上岸鸭竞品拆解与过程干预方案》（2026-10-23 上传版）第 1、9–10、12–14 页，以及《上岸鸭新版 PRD 与任务接续和状态调度》（2026-10-17）：
- 已有资料抓取工作，但接入目录、来源、正文、版本和入口仍需交接核验。
- 冷启动要求：样例 + 半填空模板 + 3 分钟试做；用户首次打开 5 分钟内应能产出一个可检查的 V0。
- 诊断与证据链有工程基础，但真实模型诊断历史记录并不稳定；受控模型测试不能代表真实模型效果。
- 论文科普视频、换讲法阶梯等部分仍标待开发，不能当作现成功能。

因此，**创新性目前是“设计方向有差异，尚未被真实用户和真实模型证据充分证明”**。

## 2. 主责测试范围
1. A 已抓取资料能否按项目接入：目录、原始来源链接、正文、版本/日期、准确定位。
2. 新用户没有现成作品时，是否能走样例、半填空模板、3 分钟试做，并在 5 分钟内产出 V0。
3. 有真实 V1 时，Agent 是否给出具体差距，且每条差距绑定 V1 版本、精确 locator、证据和目标标准。
4. 材料不足、来源冲突、旧版本、OCR/解析失败时，是否明确标记 unknown/blocked，而非编造。
5. RAG 资料不足时是否拒答、说明缺什么，并给出可执行的补资料/求助路径。

## 3. 必跑测试用例
| 编号 | 测试输入/操作 | 预期结果 | 失败说明 |
|---|---|---|---|
| A01 | 选一个真实竞赛/科研项目，接入原件与官方标准 | 项目、原件版本、来源、标准均可回查 | 资料孤岛/来源丢失 |
| A02 | 新用户从空白状态启动 | 3 分钟试做；5 分钟内有可检查 V0 | 冷启动仍依赖用户先懂怎么做 |
| A03 | 上传真实 V1，要求诊断 3 个主要差距 | 每条差距带证据、定位、标准、事实/推断/未知分类 | 通用建议、无证据结论 |
| A04 | 删除/缺失关键评分标准或原件段落 | 明确 unknown/blocked，并询问补充材料 | 幻觉或错误放行 |
| A05 | 上传旧版和新版同名文件 | 明确当前版本，不串用旧 locator | 版本串线 |
| A06 | 对 PDF/PPT 中图表、图片文字、表格抽样 | 记录覆盖率与漏读位置，不假装全部读到 | 解析覆盖不完整 |
| A07 | 问知识库中不存在的问题 | 明确查不到、提供求助卡或替代路径 | RAG 编造答案 |

## 4. 每次运行必须保存
- 测试编号、时间、执行人、项目 ID。
- 输入原件、版本/hash、目标标准和来源定位。
- Agent 完整输出、模型/代码版本、工具调用与错误。
- 人工基准答案及逐条 pass/fail/unknown。
- 失败根因、建议修改的模块/提示词/检索策略。
- 修复 commit、同一用例复测结果及回归结果。

## 5. 优化规则
- 定位不准：改 chunk/locator/引用校验，不要只润色输出。
- 旧版串入：改项目与版本过滤。
- 材料不全却生成 gap：加强证据门，缺证就 blocked。
- 冷启动超时：缩小首屏流程，只保留一个下一步和可检查产物。
- 检索无答案却编造：加拒答阈值和求助卡，并把错题加入回归集。

## 6. 验收门槛
A 交付：每个真实样本至少 3 条可回查差距；A01–A07 的运行记录；失败分类；修复前后对照。B 或 C 随机复核 3 条证据定位。没有真实运行记录的项目标“未测”，不得标通过。

**边界：** A 的诊断通过不代表作品达到赛事奖项标准；只说明诊断链条在该测试样本上达到门槛。
