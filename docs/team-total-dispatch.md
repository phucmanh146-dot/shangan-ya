# 三人协作总调度｜队长总控

**当前任务以[国一质量对标v5](first-prize-delivery-v5.md)为准（2026-10-12）。** 本文保留交接主线；每人的具体实现、产物、验收与待补证据在v5。开发分工不限制产品使用者必须三人，比赛只是任务场景之一。

> 目标：把 A 的“差距诊断”、B 的“行动排程”和队长的“总控集成”连成一条真正可执行、可复核、可调整的 Agent 工作流。

## 2. 三个人的区别

| 角色 | 核心问题 | 主要输入 | 主要输出 | 不负责什么 |
| --- | --- | --- | --- | --- |
| A 同学｜诊断与研究 | “具体差在哪里，修改后真解决了吗？” | 任务要求、现有材料与版本、参考、试做和新成果 | 可定位的事实与gap、能力证据、逐条件内容复核、变化影响 | 不负责完整排程，不负责全局状态保存 |
| B 同学｜行动与排程 | “这一小步怎么做，余下时间装得下吗？” | A的gap与能力证据、真实空档、依赖、截止和剩余问题 | 文件位置明确的操作卡、补充练习、产物与自检、日程及重排差异 | 不重新编造诊断，不负责最终总验收 |
| 队长｜总调度与集成 | “实际模块能否连续跑完，收益有什么证据？” | 实际A/B调用、用户选择、执行反馈、成果版本和扰动 | 统一状态、版本保护、失败恢复、完整执行记录、对照与试用证据 | 不重复开发平行诊断器或排程器 |

## 3. A 同学当前已做内容（根据其交付文档纳入总调度）

A同学已交的“差距分析A方案”是人工输入与报告模板：列出任务、标准、现状、试做和扰动等信息。它不等于已经实现自动读取材料、自动生成诊断或自动核对新成果。本轮分支检查未见独立可运行诊断提交；这只说明仓库交付状态，不据此判断线下工作。

A 的报告需要至少包含：

1. 任务总览与目标交付标准；
2. 现有成果客观事实；
3. 先试做样本，用来判断真实能力上限；
4. 差距矩阵：现状、目标、差距、判断依据、P0/P1/P2/P3 优先级；
5. 根因：信息缺失 / 能力短板 / 逻辑结构 / 素材误用；
6. 突发扰动预案，明确不可延期与可延期事项；
7. 给 B 的接口：每个差距必须能继续拆成“改哪里、交什么、怎样算完成、卡住怎么办”；
8. 给总控的接口：保存诊断版本，新成果提交后重新触发 A 复核。

### A 当前边界

A不负责B角色UI或全局排程。v5新增自动读取/定位、证据诊断与内容复核责任；这些是待交付项。人工模板不能算自动诊断，接收review包不能算实际内容复核，更不能把报告生成判成项目已跑通。

## 4. 总调度主流程

### 阶段 0｜接收目标
队长建立项目实例，保存：项目目标、比赛/任务名称、截止日期、成员、现有材料、当前版本。

### 阶段 1｜派给 A：诊断
A 读取规则和材料，先确认事实，再要求最小试做样本，判断当前能力，输出 `Gap Package`。

**A -> 总控必须交付：**
- `task_id`
- `target_rule`
- `current_facts`
- `trial_evidence`
- `gap_items[]`
- `priority`
- `root_cause`
- `risk_rule`
- `source_links[]`

### 阶段 2｜派给 B：行动计划
总控把 A 的每一条 `G-xxx` 差距交给 B。B 不能只写“继续学习/继续优化”，必须拆成原子动作。

**B -> 总控必须交付：**
- 对应 `gap_id`
- 改哪里
- 做什么动作
- 交什么产物
- 预计多久
- 依赖什么
- 怎样算完成
- 卡住怎么办
- 能否延期
- 推荐执行日期

### 阶段 3｜队长总控排队
总控根据 P0/P1/P2/P3、截止日期、成员空闲时间、依赖和突发安排，生成“今天做什么 / 本周做什么 / 暂缓什么”。

原则：P0 不因普通突发随意延期；突发情况只重排受影响部分，不整套推翻。

### 阶段 4｜执行与困难救援
成员执行时上传截图、录屏、文字报错或中间成果。总控先绑定当前 `task_id + gap_id + action_id`，再决定：
- 直接给下一步；
- 退回 B，把动作拆得更小；
- 退回 A，说明原能力判断可能有误；
- 标记外部依赖并局部重排。

### 阶段 5｜成果提交
“做完”不等于“完成”。提交产物后先进入 `待验收` 状态，并保存版本号和证据。

### 阶段 6｜A 复核
A 对照最初目标、差距项和新成果重新判断：
- 差距是否缩小；
- 哪些要求已满足；
- 哪些问题仍存在；
- 是否出现新差距。

v5目标：未通过的条件回到B生成剩余动作；实际A内容复核通过且用户逐条件确认后，才能记录相应验收结果。当前总控接收review包本身不会完成任务或自动关闭gap，不能把上述目标当成已实现的自动行为。

### 阶段 7｜总体验收
所有 P0 关闭、关键 P1 达标、证据完整后，队长总控才把项目标记为“阶段完成 / 可交付”。

## 5. 三人交接协议

总控不接收只有自然语言大段描述、无法定位责任的结果。A/B 的结果必须能落到统一 ID：

`project_id -> task_id -> gap_id -> action_id -> artifact_version`

这样才能知道：
- 这个任务为什么产生；
- 是 A 发现的哪条差距；
- B 为它拆了哪些动作；
- 谁在什么时候执行；
- 上传了哪个成果；
- A 复核结果是什么；
- 下一步是否需要重排。

## 6. 总控页面应该新增的三块

### A 输入卡
显示 A 同学的差距报告：目标、现状、试做证据、差距、优先级、根因、来源、突发规则。

### B 行动卡
按每条差距显示 B 的执行步骤、负责人、预计时间、依赖、完成标准、卡点预案和日程。

### 队长总调度卡
统一显示：
- 当前项目阶段；
- A/B 是否已交付；
- P0/P1 未关闭数量；
- 今日执行项；
- 待验收成果；
- 卡点与突发事件；
- 下一位应该接手的人；
- 最新版本与上一个版本差异。

## 7. 队长与 A/B 最关键的区别

A 的价值是“判断对不对”；B 的价值是“行动能不能做”；队长的价值是“整个系统能不能持续跑通”。

所以队长总调度不是第三份重复的任务清单，而是负责：**接收 A -> 调用 B -> 保存状态 -> 处理执行 -> 触发复核 -> 局部重排 -> 最终验收。**
