# 上岸鸭 V8：精力适配与真实耗时校准方案

> 本文是实现方案与交互原型说明，不代表正式生产站已经接入。当前可交互原型：\`prototypes/fatigue-aware-planner.html\`。生产发布前必须恢复并确认 Railway 当前服务实际使用的源目录。

## 一、要解决的真实问题

用户不是每天都处于相同的认知状态。睡眠不足、持续高负荷、任务模糊、遇到阻塞和情绪压力会让计划偏离；如果系统只按固定时长排任务，就会把一次卡壳放大成整天崩盘。

产品目标不是给每个人套一条“黄金精力曲线”，而是建立**个人数据驱动、每次可修正、允许休息的排程闭环**：

1. 先问睡眠、清醒时长、主观精力、疲劳和当天不可移动的安排。
2. 每个任务先问：是不是第一次做？属于哪个阶段？难度如何？什么算完成？
3. 初始估时明确标注为“用户估计 / 系统初始估算”，有足够个人记录后再用同类型真实用时校准。
4. 自动放入休息、吃饭、固定事项、机动缓冲和可自主使用的放松时间，不把每一分钟塞满。
5. 卡壳时保存进度、困难和“下一步最小动作”，允许切换低负荷任务；不强迫连续死磕。
6. 完成后记录真实专注用时、质量、返工和卡壳情况，持续修正未来估时。
7. AI 回答必须关联到用户选择的任务与资料，明确引用来源；抽象问题可选导图或视频讲解。无真实模型/视频 API 时必须明确显示“未连接”，不能假装成功。

## 二、科学证据如何变成产品逻辑

### 1. 睡眠不足：降低计划负荷，而不是把人判定为懒惰

- 成人睡眠共识建议规律地每晚睡 7 小时或以上。共识指出，睡眠不足与表现下降、错误增加和事故风险相关。来源：[AASM / Sleep Research Society 共识（2015）](https://pmc.ncbi.nlm.nih.gov/articles/PMC4442216/)。
- 61 项研究、71 个样本的荟萃分析发现，睡眠限制对清醒时神经认知表现有显著负面影响，涉及执行功能、持续注意和长期记忆；效应也受到时间段、连续睡眠受限天数等因素影响。来源：[The neurocognitive consequences of sleep restriction: A meta-analytic review](https://pubmed.ncbi.nlm.nih.gov/28757454/)。
- 睡眠不足会影响注意、工作记忆和复杂认知，但个体差异明显，主观“我还行”不能完全代表客观表现。来源：[Sleep disorders affect cognitive function in adults: overview of systematic reviews and meta-analyses](https://pubmed.ncbi.nlm.nih.gov/38469285/)。

**产品转译：**
- 睡眠少于 6 小时，或用户自评精力最低/明显疲惫：进入“恢复优先”模式。高认知负荷任务默认延后或拆成 10–15 分钟的最小下一步；先保护吃饭、休息和睡眠。
- 睡眠 6–7 小时或精力偏低：进入“降低负荷”模式，缩短工作块、增加检查点，优先做边界清晰的任务。
- 其余情况也要持续自评，不预设用户全天高精力。
- 上述阈值是产品的初始启发式规则，不是医学诊断阈值；需要允许用户自定义并用个人数据校准。

### 2. 休息有效，但不能保证短休息就能恢复所有表现

19 项记录、22 个独立样本（N=2,335）的微休息荟萃分析发现，短休息对活力和疲劳有小幅改善，但整体表现提升并不显著；高认知负荷任务的恢复可能需要超过 10 分钟。来源：[Albulescu et al. (2022), systematic review and meta-analysis](https://pmc.ncbi.nlm.nih.gov/articles/PMC9432722/)。

**产品转译：**
- 默认工作块仅作为起点（例如 20–40 分钟），用户可修改。
- 疲劳严重时不能只弹出“休息 5 分钟继续”，而应允许更长恢复、任务缩小、延期或切换任务。
- 休息、吃饭、散步、发呆、看剧等可以作为用户主动保护的时间；不把娱乐一律标记为浪费，也不把刷手机当成唯一恢复方式。
- 不宣称人人都适用固定的 90 分钟周期或一条精确的“黄金精力曲线”。

### 3. 记忆曲线与精力曲线不是同一个东西

艾宾浩斯遗忘曲线讨论的是记忆保持与复习间隔；它不能直接作为每天高/中/低精力的生理时间表。排程模块要分别记录：
- **精力状态**：当日自评、睡眠、清醒时长、任务前后精力变化。
- **任务耗时**：同一阶段的估计用时与实际专注用时。
- **学习保持**：如确有复习任务，再单独安排间隔复习和回忆测试。

## 三、每个任务如何估时

### 初始估算（数据不足时）

创建任务时必须询问：
- 第一次做 / 做过但不熟 / 基本熟练 / 很熟练；
- 任务阶段（选题、脚本、素材、剪辑、学习攻关、沟通零碎、复盘整理等）；
- 难度与完成标准；
- 用户自估基础时长；
- 截止时间、关联资料和卡住时的下一步。

原型初始系数仅用于交互测试：
- 第一次做：基础估时 × 1.65
- 做过但不熟：× 1.25
- 基本熟练：× 1.00
- 很熟练：× 0.80
- 难度再单独调整；一般任务再乘用户选择的 1.2× / 1.3× / 1.5× 缓冲。

这些系数不是科学定律，不得伪装成已经统计出来的个人数据。正式版要可配置，并用用户的实际记录替代默认系数。

### 真实数据校准（正式版推荐）

- 任务要按“任务阶段 + 难度 + 熟练度 + 结果质量”分组，避免拿剪辑时长与写脚本时长直接比较。
- 同一分组至少积累 3 条有效记录后，优先使用中位数作为基础估计；样本更多时显示中位数、P25–P75 区间和样本量。
- 估时分开记录“实际专注时间”和“日历占用时间”。休息、等素材、被打断时间不能混成一个数字。
- 每次完成显示：第几次、上次用时、本次用时、变化百分比、质量是否达到标准、是否返工。
- 如果本次更慢，不直接判定退步；先检查难度、任务范围、资料等待、打断和质量。
- “比上次快了多少”公式：\`(上次有效用时 - 本次有效用时) / 上次有效用时 × 100%\`。只在可比任务之间计算。
- 当任务首次完成后，不把“计划时长”当成“真实时长”；必须由用户提交完成记录才纳入统计。

## 四、动态重排与卡壳流程

### 状态机

1. **开始任务**：记录起始时间、精力自评、任务阶段。
2. **中途检查**：用户可选“继续 / 需要帮助 / 卡住 / 精力下降 / 被打断”。
3. **卡住 10–15 分钟**：这是可配置的提醒，不是硬性科学阈值。系统提示保存现状，并写下“我下一步只做什么”。
4. **重排**：优先把低负荷、明确、短小的任务提前；高负荷任务移到用户自评更清醒的可用时段或缓冲区。
5. **完成 / 部分完成 / 暂停**：分别记录，不把中断当成完成。
6. **复盘**：询问真实用时、结果质量、困难来源和精力变化；用记录更新估时。

### 时间安排规则

- 固定事项、睡眠、吃饭和用户明确保护的休息优先级最高，不可被算法自动挤掉。
- 先安排少量关键任务，再分配零碎任务和机动时间；计划默认不填满 100% 的可用时间。
- 任务预估 = 个体历史估计 × 难度修正 × 当前状态负荷策略；缓冲单独展示，不隐藏在估时里。
- 如果计划超出可用时长，系统必须提出“移到明天 / 缩小范围 / 降低质量目标（经用户确认）/ 使用机动时间”的选择，而不是静默塞入夜间。
- 用户可以手动锁定某项任务、固定事项或休息区间。

## 五、功能拆分，避免资料功能堆叠

1. **今日排期**：状态自评、动态时间线、固定事项、休息/机动区、重排原因。
2. **任务库**：阶段、优先级、熟练度、验收标准、截止时间、资料关联。
3. **专注与中断记录**：开始/暂停/完成/卡壳/精力下降，分别统计专注时长和日历时长。
4. **耗时与学习曲线**：个人估时、真实用时、样本量、质量、返工、每次变化。
5. **资料中心**：独立分类 Obsidian 本地库、飞书、网页、PDF/Word、视频链接；每个来源显示连接状态、权限和最近成功读取时间。
6. **任务关联 AI**：用户明确选择任务和是否关联知识库；回答展示资料引用和不确定点。
7. **导图 / 视频讲解**：作为 AI 回答的可选输出方式，不另堆成多个入口；视频标注生成状态、来源和字幕，不编造内容。
8. **语音收集**：将语音转写为草稿，提取任务、时间、困难和下一步，用户确认后才入库；录屏文件解析需要显式上传并确认权限，不能假装浏览器已读取屏幕。
9. **微信任务收集**：独立收集入口，只接入用户授权的官方接口或可合法导出的记录；显示实际权限和读取范围，不绕过加密、不声称读取了未授权的私聊。
10. **设置与隐私**：睡眠/精力阈值、工作块长度、缓冲倍率、休息偏好、数据导出与删除。

## 六、页面与开发顺序

1. **P0：保护现有结构与数据**。先备份当前生产版本和用户数据；核实 Railway 的实际源目录、构建命令和当前部署 commit。禁止直接用新页面替换旧应用。
2. **P1：任务估时闭环**。任务阶段 + 熟练度 + 估计用时 + 实际用时 + 质量；先做纯本地可验证功能。
3. **P1：疲劳与重排**。状态自评、恢复优先模式、卡壳动作、固定事项和休息保护。
4. **P1：个人曲线**。同类任务分组、中位数、变化率、样本量与异常解释。
5. **P2：语音转任务草稿**。语音权限、转写核对、用户确认后入库。
6. **P2：任务资料关联**。先接入有明确授权和可测试的来源，显示真实连接状态。
7. **P3：AI 引用、导图、视频讲解**。API 可用性、失败重试、超时与降级提示都必须可观测。
8. **P3：微信接入**。先验证官方/用户授权路径与本机桥接的边界，避免网页远程读取本机微信的错误承诺。

## 七、验收标准

- 睡眠不足或自评低精力时，系统会降低认知负荷、建议恢复或最小下一步，而不是继续塞高难度任务。
- 固定事项、吃饭、睡眠和用户锁定的休息不会被自动覆盖。
- 用户可为任务选择“第一次做/不熟/熟练”，预估会显示计算依据与缓冲。
- 未提交真实完成记录的任务不进入真实耗时曲线。
- 真实耗时曲线只比较可比任务，展示样本量和质量；首次数据不足时明确提示“数据不足”。
- 卡壳可以保存下一步并切换任务，稍后可恢复。
- 语音识别不支持或权限失败时有明确提示，不伪装成功。
- AI/知识库/视频 API 未连接时显示未连接，不产生虚构答案或成功状态。
- 手机和桌面布局均可用，现有左侧导航、任务、四象限和宝保清单需保持不变。
- 部署前执行页面回归、数据迁移检查、接口失败测试和移动端测试。
