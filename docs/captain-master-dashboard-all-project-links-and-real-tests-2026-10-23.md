## 三、统一测试闭环（每个项目都要有记录）

1. **登记输入**：原件链接、版本/hash、赛事官方通知、年份/赛道、评分项。
2. **A 诊断**：至少 3 条有证据的 gap，每条绑定当前作品位置、目标标准、来源证据和不确定性。
3. **B 行动卡**：每条 gap 变成具体微动作，含 1–5 分钟首步、产物、完成定义、自检、失败路径。
4. **真人执行**：由非行动卡作者执行，记录开始时间、实际用时、卡点和真实产物。
5. **V2 版本**：保存修改后的实际文件及版本/hash；不能用 AI 生成的示例内容替代真实修改。
6. **A 独立复核**：按原评分项逐条标 pass/fail/unknown，注明 V2 位置和证据。
7. **B 局部重排**：只调整 fail/unknown 项；已完成、进行中、锁定任务及依赖不得被覆盖。
8. **C 总控**：记录模型/代码版本、输入输出、失败记录、对照组、耗时、成本，决定 go/revise/stop。

## 四、如何证明 Agent 有创新，而不只是功能清单

每个优先样本都应在相同作品、同一目标标准、相近工具预算下比较：
- 普通聊天的输出和实际执行；
- 当前 Agent 的输出和实际执行；
- 首步启动耗时、独立执行率、真实 V2 是否符合原标准；
- 中断恢复正确率、无效重复次数、误放行/漏检、用户负担和调用成本。

工程单测、真实模型测试、真人执行、独立复核分别标注证据级别。没有数据时填“未测量”，不预填提升百分比，也不声称已经达到省一。
