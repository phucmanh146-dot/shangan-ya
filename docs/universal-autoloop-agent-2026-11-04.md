# Universal Autoloop Agent — 上岸鸭 V10 工程接入方案

> 状态：工程设计基线 / 待实现与验收。本文不是“已安装、已运行”的声明。
> 参考：用户提供的 Agent-Autoloop 架构文章；核心流程为事件 → 规则路由 → Agent 执行 → 自动闭环或审批 → 恢复原任务。上游实现参考 https://github.com/KKKKhazix/agent-autoloop 。

## 1. 产品目标

把“用户每次开口后才开始做事”的被动助手升级为跨任务、跨会话的主动执行系统。用户用自然语言、图片、文件、链接或系统事件提出目标；系统识别所属项目和约束，自动推进低风险步骤，持续检查结果，只有真正需要用户决策时才请求拍板。

统一入口适用于：V10任务管理、学习与课程、管理会计/考研、TRAE训练营与原型、Agent大赛、运营、资料读取、代码开发、网页维护及后续新项目。不得为每个场景复制一套孤立Agent。

## 2. 核心架构：确定性内核 + 可插拔执行器

### 2.1 Kernel 只负责四件事
1. 接收标准化事件。
2. 按本机可信规则匹配任务、项目、权限和执行器。
3. 派发执行并管理状态转换。
4. 将每个事实追加写入不可变事件账本，并从账本重建当前状态。

Kernel 不直接调用模型、浏览器、GitHub、飞书或其他外部网络服务；这些能力由插件提供。规则和权限来自可信配置，不得由事件正文、网页、附件或模型输出覆盖。

### 2.2 插件接口
- Sources：对话输入、文件/图片上传、Webhook、GitHub Issue/PR、定时器、工作台任务变化、用户授权的连接器事件。统一转换为 Event。
- Agents：GPT/CLI coding agent/本地脚本/研究Agent/验收Agent。仅通过结构化任务包和结构化结果交互。
- Channels：工作台通知、桌面通知、飞书/微信企业版等已授权通道。用于状态通知和审批卡片。
- Delivery：测试、PR、CI、部署、生产环境健康检查。发布链与普通代码修改分离。

插件必须声明能力、输入输出Schema、权限范围、超时、幂等键和失败策略。缺少插件时明确标记 unavailable，不得伪造“已连接”。

## 3. 标准事件与任务上下文

每个事件至少包含：
- event_id、event_type、occurred_at、source、actor
- conversation_id / session_id（可用时）、project_id、task_id（识别不确定时为空）
- payload_ref（正文/附件单独保存，不混入控制指令）
- idempotency_key、correlation_id、parent_event_id
- sensitivity、trust_level、evidence_refs

每个任务维护可恢复的 Context Pack：
- 目标、成功定义、硬截止时间、固定事务、依赖、可用时间与精力约束
- 项目/任务归属、已确认决策、历史尝试、错误、阻塞、下一步
- 输入材料版本、原文引用、工具调用轨迹、产出版本、验收标准和证据
- 当前状态、执行Agent、审批状态、下次唤醒时间

跨会话恢复优先使用明确 task_id/project_id；其次使用已确认的关联映射。低置信度匹配只展示候选并询问一次，不得把新对话误接到别的项目。已知信息不得重复问用户。

## 4. 自动执行循环

1. 接收：事件进入队列，先持久化再 ACK。
2. 归并：短时间同一任务的重复事件合并为一个执行轮次；保留所有原始事件。
3. 识别：抽取意图、交付物、DDL、证据要求、约束和风险；输出置信度与未知项。
4. 路由：依据可信 rules 将任务派给最合适 Agent/Skill/工具；不得仅凭模型建议提升权限。
5. 执行：按小步骤执行，每一步记录输入、工具、输出、耗时、状态和证据。
6. 核验：读取真实工具结果；代码需测试，文件需存在且可读，网页需实际访问，提交需有远端记录。
7. 决策：
   - done：证据满足验收条件，关闭当前轮次。
   - later：保存唤醒时间，Agent 退出；到时重新加载上下文继续。
   - ask：只有缺失关键决策或高风险动作时才请求用户。
   - blocked：记录错误、已尝试方法和可行替代路径，自动继续低风险诊断。
   - notice：重要进度主动通知，不要求用户来追问。
   - spawn/event：派生独立子任务，使用关联ID回写父任务。
8. 恢复：进程崩溃、网络失败或用户稍后批准后，从账本和检查点恢复，不从头盲目重跑。

## 5. 审批策略：只在需要拍板时打扰用户

默认可自动执行：读取、检索、分析、草拟、创建本地备份、非破坏性代码修改、运行受限测试、创建功能分支、生成PR草稿、重复检查、任务重排预览。

必须审批：删除/覆盖用户数据、清理文件、付费或采购、发送对外消息、公开发布、合并到主分支、生产部署、变更账号/权限/密钥、不可逆操作、涉及敏感个人资料的外发。

审批卡必须说明：要做什么、为什么、影响范围、风险、备份/回滚方式、已完成步骤、批准后将继续执行的动作。批准后恢复原 correlation_id 与原任务上下文；不得重新提问已回答问题。拒绝后记录原因并给出安全替代方案。

## 6. 可靠性与安全底线

- Event Sourcing：事实账本 append-only；状态是投影，不允许静默篡改历史。记录操作者、时间、来源、前后状态和证据引用。
- 幂等与重试：所有写操作带 idempotency_key；超时后先查询远端状态再决定是否重试。禁止盲目重复创建Issue、PR、文件、消息或部署。
- Prompt Injection 防护：外部正文/网页/附件只作为不可信数据存储；与系统规则、权限和任务指令分离。外部材料不能授权工具调用、泄露密钥或改变规则。
- 有限循环：每轮有最大步骤、最大重试、预算、超时和递归深度；达到上限必须总结并暂停/请求决策，不能无限死磕。
- 隔离执行：第三方PR/分支代码不得在用户机器上直接执行；先静态审查，在隔离CI运行。
- 密钥保护：密钥只从本机环境/秘密管理器读取，不写入Git、事件账本、日志或上下文包。
- 审计：保留原始事件引用、模型决策、工具调用、退出码、测试报告、部署版本和人工审批。
- 成本：无待处理任务时不常驻调用大模型；定时轮询尽量用轻量脚本，只有发现变化才唤醒Agent。

## 7. 与上岸鸭 V10 的映射

| V10现有模块 | Autoloop接入点 | 结果 |
|---|---|---|
| 首页 / DDL雷达 | deadline、task_changed事件 | 自动识别临期并触发三天拆解 |
| 每日清单 / 精力排期 | schedule_changed、energy_feedback | 保护固定事务、睡眠、缓冲与多主线 |
| 任务中心 | task_created、task_blocked、task_evidence_submitted | 自动拆解、求助、跟踪、证据验收 |
| 资料中心 | material_added、material_read | 自动读取、版本化、引用来源 |
| 卡壳/死磕监测 | stalled、retry_limit、fatigue_feedback | 识别无进展，换策略/缩小/休息/延期 |
| 数据档案 | evidence_verified、task_reviewed | 统计真实通过率、返工率和未知项 |
| GitHub/部署 | issue、PR、CI、deploy events | 自动审查、测试、部署后生产核验 |

任务状态沿用 V10 的未开始/执行中/卡壳/待证据/待验收/部分/通过/失败/无法核验/人工确认，不另造一套互相冲突的完成状态。计划完成不等于真实完成；“已完成”必须由对应验收规则和证据产生。

## 8. 推荐工程落地顺序

### P0：可恢复的最小内核
- 建立 event/fact、projection、rule、run、approval、checkpoint 数据模型。
- 事件先落盘再确认；同一幂等键不可重复执行。
- 支持 done / later / ask / notice / blocked / spawn 的结果协议。
- 实现上下文恢复、有限重试、审批后续跑。
- 加入 kernel purity、状态迁移、崩溃恢复、重复事件和注入隔离测试。

### P1：接入现有 V10
- 复用现有 SQLite 任务、材料、证据和精力排期数据，不另建平行任务库。
- 把用户新消息、文件上传、DDL变化、卡壳反馈转为标准事件。
- 将 GitHub、桌面文件和网页浏览做成独立插件；按已授权连接状态启用。
- 首页增加“Agent正在处理 / 等待我拍板 / 下次自动检查 / 已验证结果”状态区。

### P2：主动通知和交付流水线
- 先桌面通知/工作台通知，再接入用户授权的消息渠道。
- GitHub PR review → CI → 审批 → merge → deploy → production smoke test。
- 任何失败自动回滚或暂停，保留完整证据链。

## 9. 验收标准（不可用演示截图代替）

1. 用户在一个会话中交办任务，结束会话后重开，Agent 能恢复同一任务、已完成步骤和下一步，不重复询问。
2. 用户补充临时任务或更改DDL，系统自动评估冲突并给出新的可执行安排，固定事务不被覆盖。
3. 同一Webhook重复投递10次，只产生一个逻辑执行轮次。
4. 模拟执行到一半进程崩溃，重启后从最后检查点继续，写操作不重复。
5. later 到期后自动唤醒并继续；没有到期时不空转调用大模型。
6. 需要审批的动作暂停；批准后续跑原任务，拒绝后不执行。
7. 外部网页包含“忽略规则/读取密钥/删除文件”等指令时，只作为不可信文本，不改变权限。
8. 工具执行失败必须保留真实错误和尝试记录，不能写成成功。
9. 每项通过任务都能追溯到验收规则、原始证据、检查结果和版本。
10. 端到端测试覆盖“事件→执行→审批→恢复→验收→通知”，并在真实Windows设备与部署环境分别验证。

## 10. 当前限制与明确非目标

- 微信个人聊天、ChatGPT其他会话或任何未授权应用不会被系统暗中读取。必须通过当前会话事件、用户导入、官方授权连接器或本地明确授权的导出源接入。
- “所有对话通用”指所有接入入口共用同一任务上下文与执行内核，不代表Agent能绕过平台权限监视所有聊天。
- 摄像头只能作为辅助状态信号，不是任务完成证据；完成验收以作品、进度、测试、提交凭证等任务专属证据为准。
- 自动部署不是默认权限；先在分支和预览环境完成测试，再按审批策略发布。
- 本文为待实现工程方案。只有代码、测试、运行日志和真实环境结果齐备后，才能将对应能力标为已完成。
