## 运行与实际交付流程

在 `learning-agent` 目录运行：

```bash
python learning_agent_server.py --port 8920 --with-b-planner
```

打开 `http://127.0.0.1:8920/team.html`。参数将已交付的 B 规则规划器绑定到总调度；没有参数也可用页面“调用 B 规划器并预览”按钮。A 的生成和复核模块仍待服务端配置，页面不会假装自动调用 A。

1. 创建真实项目。导入 A 的完整 JSON，先检查、再保存。DOCX/Markdown 空模板不能直接充当 Diagnosis。
2. 点击 B 规划器，核对任务、步骤、估时、负责人和依赖；确认后采用。缺少精细 `micro_steps` 时仍明确提示待补。
3. 开始任务。遇到困难，选择对应 gap 和动作，输入尝试过程，可上传截图或短录屏；需先配置现有 AI 连接。
4. 读取求助结果，成员判断是否适用。求助结束不代表任务完成，不自动修改 Diagnosis 或排程。
5. 提交新成果，进入待验收。导出给 A 的复核包，A 对照实际文件、原差距和验收条件给出结果。
6. 接收 A 复核 JSON；逐项核对并保留证据，通过才验收任务。仍有差距的记录继续保留，A 如更新 Diagnosis，再让 B 生成局部预览。

服务端预留 `team_dispatch.RESEARCHER` 和 `REVIEWER` 可信 Python 函数；复核函数接收项目快照和单任务交付包，返回复核对象。浏览器不能配置任意函数、代码或远程端点。缺少函数时显示待接入，回调期间版本变化不能写回旧结果。

具体接口和复核字段见 [P1 第 8–9 节](p1-contract.md#8-实际-b-规划接线与-a-复核交付)。成员 ID 是本机记录，不代表多人身份验证；`live_verified` 仍为 false。
