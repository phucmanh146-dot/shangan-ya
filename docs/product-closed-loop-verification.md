# 产品闭环实测与技术取舍

## 本轮真实发现并修复

共享工作台的op请求没有传expected_plan_version，导致保存卡点/返回任务被后端拒绝。现统一随请求传入当前计划版本。任务卡增加前置任务及状态、能力试做要求、阻塞原因；前置未验收的任务不提供可点击的开始按钮。没有降低版本保护或依赖验收门槛。

## 完整工程闭环

新增test_complete_authenticated_v1_v2_review_recovery_loop，使用合成材料、模拟模型、两个测试账号，经真实FastAPI/SQLite/LangGraph及领域校验完成：项目建立→目标与本人任务→V1导入→检索诊断→计划预览确认→采用→开始→中断→恢复→V2导入提交→拒绝自我复核→另一账号逐项引用复核→验收→剩余计划更新。最后核对V1未被覆盖。不是由助手假扮真人验收。

全量317项回归通过。新增用例不是单纯调用内部函数，而是测试共享工作台实际使用的受鉴权API。

## 真实模型复跑

同一用例支持显式SHANGAN_LIVE_CLOSED_LOOP=1调用本机既有Hermes。此次真实调用生成诊断、计划，用户确认和采用接口通过；直接启动选中的生产任务被正确拒绝：前置任务尚未验收完成。真实模型版完整闭环本轮未通过，不能把受控模型的通过数替代。未绕过依赖、未伪造前置任务完成。
