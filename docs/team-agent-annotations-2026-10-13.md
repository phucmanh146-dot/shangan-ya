## A 同学批注｜把“宏观要求”诊断成有证据的具体差距

### 保持的职责
A 仍负责比赛/科研要求、优秀作品、当前作品的读取与判断，回答“离目标具体还差什么”。

### 现在容易像 Demo 的地方
- 输出“加强调研、提高创新性、优化PPT逻辑”这类所有项目都能套的话。
- 搜到优秀作品后只做摘要，没有指出“哪一处值得借鉴、为什么适用于当前作品、应该改当前文件哪里”。
- 把搜索摘要或博主观点当成官方规则。

### 必须修改成
每个 gap 至少包含：
1. 当前目标与阶段。
2. 当前作品：文件版本、页/段/行/模块位置。
3. 当前证据：原文引用或代码/数据位置。
4. 目标判据：官方要求/团队已确认标准/参考案例，来源类别分开。
5. 具体差距：一句话能指出“哪里缺什么”。
6. 为什么这个差距影响当前目标。
7. 给 B 的动作候选，不直接写成宏观任务。
8. 没证据时明确 unknown。

### PPT 场景示例
错误：`PPT用户洞察不足，需要加强调研。`

正确：`PPT v3 第4页只有“年轻人关注肠道健康”的结论，没有样本数、来源和痛点排序；当前问卷CSV已有“购买场景/购买频率/核心痛点”三列。Gap：第4页无法证明用户痛点强度。下一步候选：先统计有效样本数，再提取前三高频痛点，并把每个结论绑定原始数据。`

### A 的放行标准
- 任抽3个 gap，队友都能回到真实原文/代码/数据位置。
- 同一模糊目标换一份不同作品，诊断结果明显不同，不输出统一模板。
- 错版本、虚构引用、缺材料各跑1例，系统能拒绝或保留 unknown。
- V2复核只看成果是否满足判据，不因为任务按钮点了“完成”就自动通过。

## B 同学批注｜把 gap 拆成“不问作者也能开始”的微行动

### 保持的职责
B 仍负责把 A 的真实 gap 变成非常细的行动步骤，并结合个人能力、时间、依赖和截止安排。

### 现在容易像 Demo 的地方
- 所有问题都变成“搜资料→分析→修改”。
- 写了很多步骤，但执行人还是不知道打开哪个文件、点哪里、输出什么。
- 一遇到不会就安排一整套学习路线，而不是只补当前动作需要的能力。

### 必须修改成
每张行动卡必须包含：
1. 输入版本。
2. 具体操作位置。
3. 第一动作（最好5分钟内可开始）。
4. 使用工具。
5. 具体动作，不用抽象动词。
6. 为什么这样做。
7. 预期改变。
8. 输出文件/表格/代码/页面。
9. 自检方法。
10. 失败后的下一步。
11. 能力依据：已验证/未知/未通过。
12. 预计时间与实际时间分开记录。

### PPT 场景示例
错误：`完善商业模式页。`

正确：
1. 打开 `方案_v3.pptx` 第8页。
2. 圈出当前“用户—价值—收益来源”三块文字。
3. 从 A 给出的2个优秀案例中，只提取“价值交付方式”和“收益来源”字段，不复制页面。
4. 用当前项目实际用户替换模板字段。
5. 生成 `商业模式_v4.pptx`。
6. 自检：陌生成员能否在30秒内回答“谁付费、为什么付费、项目怎么持续”。
7. 如果答不出来，不继续美化，退回补用户/收益证据。

### B 的放行标准
- 找另一名成员，不解释背景，只给行动卡；对方5分钟内能开始。
- 数据清洗、PPT、访谈、接口联调四类 gap 不能出现同一套三步模板。
- 至少记录一次真实失败路径和实际用时。
- A复核后，只重排 remaining issues，不推翻已完成/进行中/锁定内容。

## C / 队长批注｜不是“串三个 Agent”，而是保证项目一直向目标推进

### 保持的职责
队长仍负责三人总调度：知道当前项目做到哪里、下一步该交给谁、谁卡住、目标变化后哪些任务受影响。

### 现在容易像 Demo 的地方
- 页面上有 A/B/C 三块，就叫多 Agent。
- 三个人都生成内容，但没有真实状态、版本、失败恢复和复核门。
- 上传成果后直接完成，没有再次核验。

### 必须修改成
核心状态明确为：
`MATERIAL_READY → DIAGNOSING → PLAN_PREVIEW → EXECUTING → WAITING_REVIEW → REPLAN`

规则：
1. 材料不足：停在 A，不调用 B 生成通用计划。
2. 能力未知：先试做，不能直接进入正式制作。
3. B 计划：先预览，用户确认后才生效。
4. 上传成果：只能进入 `WAITING_REVIEW`，不能直接 done。
5. A 复核失败：只生成剩余问题。
6. 目标变化：只标记受影响任务失效，旧成果、实际用时、证据继续保留。
7. 进程重启/工具失败：从已保存状态恢复，不整套重新生成。
8. 三个 CC 窗口必须有真实 heartbeat；未上报只能标 `derived`，不能冒充队友在线。
9. Trace 至少串起来：输入材料 → A判断 → B行动 → 用户采用 → 实际V2 → A复核 → B局部调整。

### 队长放行标准
- 看板能回答：A/B/C各自在做什么、卡在哪里、最后一次真实上报是什么时候。
- 任意一个最终任务都能反查“为什么生成、用了什么证据、谁确认、对应哪个作品版本”。
- 断服务后恢复同一任务阶段；旧版本复核会被拒绝。
- 至少跑通一次真实比赛/科研案例完整闭环。

## 下一轮统一任务｜只做一条最强真人闭环

1. A：拿团队当前真实作品 V1，输出3个有原文/代码/数据出处的 gap。
2. B：基于3个 gap 生成3条明显不同的微行动路径。
3. 另一成员：不问作者，照卡实际修改，产出真实 V2，并记录卡点和实际耗时。
4. A：读取真实 V2，逐条件输出 pass/fail/unknown + remaining_issue。
5. B：只对 remaining_issue 重排。
6. C：保存完整 trace、版本、人工确认、失败与恢复记录，并让 A/B/C 真实窗口持续 heartbeat。

本轮结束前：不新增第4个 Agent，不为了炫技强制换 LangGraph，不为了“技术栈丰富”先上微调/向量库。先证明这个系统真的能把比赛/科研宏观目标拆到执行人无需猜的微观动作，并能根据实际成果继续推进。
