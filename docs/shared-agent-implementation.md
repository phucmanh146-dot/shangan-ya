## 使用方式

需要Python 3.12，先在虚拟环境安装：

```sh
python -m pip install -r learning-agent/requirements-engineering.txt
python learning-agent/platform_admin.py add-user 你的账号
python start_research.py
```

账号密码通过交互输入，不提供公共默认账号。默认监听127.0.0.1:9010，同时启动worker。原标准库科研流程保留为 `python start_research.py --legacy`。两种入口不得同时操作已切换的生产数据。

团队环境复制 `.env.engineering.example` 为 `.env.engineering`，配置真实私有服务与密钥。容器编排使用 `docker compose --env-file .env.engineering -f compose.engineering.yml ...`。production缺PostgreSQL、S3桶或明确前端origin会拒绝启动，不静默回退本地数据库。

本机和网页必须连接同一后端。Vercel前端需把同源 `/api/v1/*` 反向代理至常驻后端，保持HttpOnly会话cookie；本轮未新增实际Vercel部署。禁止把真实凭据写入仓库或前端。跨域部署需另行验证HTTPS、反向代理和cookie行为。

## 业务闭环

1. 登录，建立项目，保存目标/判据和本人负责的产物、理解、工具。
2. 所有者为真实协作者分配项目角色；复核者使用自己的账号登记任务。
3. 导入真实文件。更新原文件沿用artifact_id以增加版本。版本内容不覆盖。
4. 输入当前问题，后台返回run_id。页面显示节点、耗时和失败码。模型未配置时明确失败。
5. 运行结束只生成候选。所有者核对后确认诊断与计划预览，再另行采用计划。
6. 实际执行者开始、保存卡点、核对现场恢复；真人上传V2后提交。
7. 非执行者读取V2，逐条件选择原文位置、填写判断、明确人工确认。未通过保留unknown并退回，不虚构剩余微动作；通过后沿用原差距更新和剩余重排机制。

REST主入口为 `/api/v1`。所有项目访问检查服务端角色；写请求需会话CSRF及项目版本。复核/提交身份由登录账号确定。取消是协作式：正在执行的网络调用完成前可能继续占用资源，但取消后不会发布结果。

## 数据迁移

`migrate_shared.py --agent <旧Agent库> --workflow <旧科研库>` 默认只读源并生成清单；`--apply` 才写PostgreSQL目标。目标明确配置，整批写入在同一事务中，重复迁移识别manifest；ID冲突拒绝覆盖。同名项目不合并，旧科研状态存入独立映射项目的legacy_workflow。

尚需实际PostgreSQL迁移演练、行数及SHA256核对、附件搬迁和恢复验证；旧科研记录中的本地附件尚未自动转换为新材料库原件。未切换源服务为只读，也没有删除旧库。通过这些验证前不能宣布迁移完成。

## 验收与80分

新测试覆盖跨项目拒绝访问、CSRF、版本冲突、幂等、取消、租约抢占与旧worker拒写、检查点、LangGraph候选、原子确认、重复确认、模型缺配置失败、注销失效，以及Qdrant项目/版本隔离和维数错误。模拟模型和合成向量明确标记。

当前没有人工标注的30题检索集、3个真实模型案例、2条真人V2独立复核闭环。`evaluate_shared_rag.py` 只接收真实人工标注输入；未生成合成题冒充人工数据。未取得官方适用评分细则，不计算官方得分；当前不能确认达到内部80分。

尚未解决：真实PostgreSQL/S3/Redis集成，OCR成功实测，LIVE模型与embedding质量，桌面/移动端E2E，生产部署与会话验证，真实旧数据迁移及附件转换，官方评分证据归档，真人对照研究。新增实现不等于这些项目已通过。
