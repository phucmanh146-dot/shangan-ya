# 上岸鸭：按原始宗旨重新设计质量进阶闭环

## 一、产品宗旨与本轮纠偏

帮助愿意做科研、基础与资源不同的学生，理解什么算好，看清现有作品与目标的差距，在适合自己的指导下亲手改善真实成果，再逐步独立掌握方法。

本次“重新设计”针对整套产品，不是只替某个假想人物选题。没有方向、不会把方法用在作品上、做出来达不到标准，都是同一条质量进阶链的不同入口。三大边界继续有效：不代写、做陪伴、分步讲解。不把开始行动、点击完成、工程测试或模拟复核当成科研能力提升。

依据：用户原始说明，以及《科研陪伴Agent_最终宗旨与真正闭环验收_20261031》的最终产品目的。此前“科研迷茫起步”的规则选题页只能作为局部入口，不能代表整个产品。

## 二、核心闭环：共同理解目标→实物诊断→按人选路径→真人修改→同标准比较→能力迁移

| 环节 | Agent真正要做的事 | 学生留下什么 | 进入下一环节的条件 |
| --- | --- | --- | --- |
| 1. 共同理解目标 | 允许口语和含糊表达；结合当前作品复述“你想把什么改到什么程度”，用可比较的弱/强例子解释质量差异；一次只追问最影响下一步的问题。 | 本人确认的目标、受众、当前材料和限制 | 学生能纠正Agent的理解；本轮范围及质量判据G得到确认，未清楚就继续澄清，不强塞首步。 |
| 2. 对照实物找差距 | 读取真实V1和标准来源，把“已经有的优点、具体缺口、支持位置、未知”分别标出；区分目标不清、理解不清、方法不会应用、证据缺失、工具受阻、方向不适配。 | 差距表，每条能回到作品位置与G的一项 | 当前优先差距有依据；缺材料就登记依赖，不声称读完或断言整个项目没做过。 |
| 3. 按当前能力选择路径 | 用已有产物或最小试做判断当前技能。未知先试一行；已经会的跳过；卡在哪个概念/操作就只解释这一点；缺资源先求助或选等价可行路径。 | 一张本人确认的动作卡：改哪里、为什么、如何做、交什么、怎么验、失败怎么办 | 卡片能让执行者动手，并明确补哪一条差距；不能只有阅读、分析、完善。 |
| 4. 本人尝试与迭代指导 | 学生亲手执行，Agent依据实际中间产物纠偏；先指出错误发生在哪一步，再给小提示或示范方法，不直接代交科研结论。 | 中间稿、真实V2、差异、理由、求助与耗时 | 有实际产物；卡住进入恢复分支，保存已经做过什么，避免重复找方向。 |
| 5. 按原标准比较改前改后 | 非执行者对V1/V2使用同一G逐项比较，记录通过/未通过/未知及位置；Agent可辅助定位，不能自评后自动盖章。 | 内容复核记录及剩余差距 | 本轮对应缺口确实改善；未过只补对应项，未知不强判通过。 |
| 6. 检查方法能否迁移 | 请学生解释“为何这样改更好”，再在另一处相近真实材料上减少提示试做。 | 自己的解释、另一处试做、实际复核 | 有证据才登记当前技能已验证；未掌握回到具体方法，不能由一次改稿推断整体科研能力提高。 |

每轮只做一个最值得补的质量缺口。完成第6环节后，更新能力记录和剩余差距，进入下一轮；不是重新抛出一整套千篇一律的任务。

## 三、迷茫与卡住时，允许调路径，不随意调低标准

- **说不清想要什么：** 保留愿望，结合现有作品让学生比较具体差异，协商一个真实目标；不是立刻让他填完整研究计划。
- **知道目标、不知道怎么改：** 定位到一段、一页或一行，先判断缺概念、操作还是论证方法；给当前这一步的解释与试做。
- **做了但没有改善：** 回看V2和反馈，检查原诊断是否错、步骤是否超出能力、材料是否不足；改变帮助方式，不只换措辞重复建议。
- **确实方向不适合现有条件：** 给出原方向受阻的证据和可行替代，说明损失与收益；由学生确认新目标及新G，旧目标和记录保留。正常补救不自动顺延DDL，不偷偷降低判据。
- **缺材料或环境：** 记录缺项、求助对象及已尝试方法，转向可就绪的一项；不补造访谈、实验、订单或接口运行结果。
- **重复尝试无进展：** 停止同一动作重试，升级给导师/学长姐或具备相应能力的成员；记录需要对方回答的具体问题。

10分钟前进度询问、今日任务和窗口栏属于执行支持；它们询问“现在卡在哪、能交什么、要不要调整帮助”，不替代质量诊断和复核。

## 四、Agent架构与上下文循环

1. **目标澄清器：** 形成共同理解与本轮G，解释质量差异，保留本人更正。
2. **证据诊断器：** 读取V1及标准，给出有位置、有支持性说明的差距；未知保留未知。
3. **教学与行动规划器：** 根据当前差距、已验证技能、试做结果、时间与材料选择下一动作和当前解释。
4. **执行陪伴器：** 接收实际中间稿，识别错误位置、保存卡点与已试方法，组织补救或转交。
5. **质量复核与迁移记录器：** 辅助非执行者同标准比较，登记另一处迁移表现，只重排剩余差距。

这些是逻辑职责，不要求堆叠多个模型或多个框架。知识与方法只在当前任务需要时检索并标来源；术语、案例和模板服务于当前差距，不一次灌输全部知识。

每次调用必须带：项目与材料版本/位置、本轮目标与G、已确认事实与未知、技能证据、上次实际动作与结果、仍未通过的差距。每次返回必须写明：下一动作依据什么、改变哪个缺口、产生什么、如何核对、卡住如何恢复。任务重开先恢复这些信息，不把整段聊天无限重复塞入。

状态可用：待澄清→待确认判据→待核差距→待试做/待执行→执行中→待复核→待迁移→本轮通过。材料、方法、环境、方向受阻是可恢复分支。模型失败与人工候选分开标记，不能静默替换。

## 五、沿用原作品的闭环示例：湘秀未来

学生说：“我想把这个项目做好，但不知道怎么达到好作品的要求。”

先解释本轮只看“访谈如何支撑一项产品决策”，不承诺整个作品获奖；确认G：需求能回查原话与位置、与具体样品/设计决策有理由对应、权限和交付状态如实标注。

看原P14已有访谈统计，承认已有调研表述；尚缺原始附件就先求助，不能再判成完全没调研，也不能自动虚构需求。

- 未知是否会提取需求：用一份真实访谈做一行试做。
- 已证明会提取需求：跳过摘录练习，直接检查需求怎样支持产品决策。
- 有思路但论证不成立：只讲“原话→需求解释→决策理由”的这一条关系，请本人修一处。

本人交V2和理由后，非执行者用同一G比较改前改后。再换另一条实际需求，减少提示检查迁移。至此才能分别登记“这一处成果改善”和“当前方法已掌握”；缺访谈、真人V2、复核或迁移证据时相应门保持未过。

## 六、第一期实施优先级与验收边界

先把这条质量进阶链做实，再扩展八项目和55项作为不同领域的验证样本。八项目需要不同原文、方法和判据，服务的是同一产品宗旨，不是八套彼此割裂的任务清单。

优先补：多轮共同理解目标、G与原文差距绑定、基于试做的帮助分流、V1/V2内容比较、迁移记录与未过项重排。已有提醒、上传、保存历史等基础功能复用，不作为本轮价值成立的证据。

本文件是重设计规范，不宣称上述各层已实现或真实闭环已通过。既有工程演示仅证明流程接口可运行；真实材料支持、真人成果改善和能力迁移须分别留证。
