# 上岸鸭：省级获奖作品对照、三人测试批注与山东省 AI 大模型创新传播大赛转化方案
更新：2026-10-25  
仓库：`phucmanh146-dot/shangan-ya`  
适用主线：Issue #7「真实参考内容 → A 证据诊断 → B 微行动 → 真人 V2 → 独立复核 → 只重排剩余问题」

> 本文是队长工作文档与待执行验收清单。工程测试、模型内容质量、真实用户效果分开记录。内部对标“省一/国一质量”不等于官方评分表，也不承诺获奖。

## 1. 这轮到底要解决什么

不是继续堆功能，也不是把已有 Agent 换个名字报名。要把现有“从目标到成果”的执行闭环，用真实样本证明它能：
1. 读懂一份真实材料和对应目标；
2. 指出材料中具体哪里与目标有差距，附原文位置和证据；
3. 让另一位成员仅凭行动卡就能修改，不依赖口头解释；
4. 留下真实 V2，并由未参与该次修改的人按同一标准复核；
5. 测试失败、材料更新或临时占用后，保留已有成果，只调整未完成的问题。

当前主线仍是大学生竞赛、科研和创新实践的资料驱动执行 Agent。山东省 AI 大模型创新传播大赛需要另外做明确的传播场景适配，不能把原有学习规划功能直接当成传播作品。

## 2. 对标材料与边界

仓库已有 `docs/first-prize-delivery-v5.md`、`evidence/first-prize-v5/README.md` 和 `evidence/first-prize-v5/protocol.md`。已有公开作品研究包括 Coco AI、清华“医链智擎”及其他 Agent/排程产品。可复用的是方法：真实需求、真实输入、可交互工具、可核查产物、清楚的证据和效果验证；不能从新闻报道推断获奖作品未公开的完整源码、评分或具体效果。

现有工程证据显示：固定赛事预填值修复、受控排程、版本/交接保护有可复现检查；S01 报告、S02 CSV 是人工构造的模拟样本。它们不是 A/B 自动生成成绩，更不是用户收益证据。

## 3. 三人职责与测试样本分配

以下按此前总调度约定的 8 个样本分配。作品名称以现有记录为准；若材料包中的官方名称不同，执行前以原文件/官网校正，不能只凭口述更名。

| 负责人 | 样本 | 该成员要回答的问题 | 必交证据 |
|---|---|---|---|
| A：诊断与研究 | 嘉农芯生、滴水润疆、菌润乡土 | 真实目标是什么？原材料具体哪一处不达标？证据来自哪里？ | 输入文件清单及哈希、目标标准、精确定位、gap 编号、原文摘录、参考来源与定位、unknown 项 |
| B：行动与排程 | 文玩玉米、本草云联、湘匠织秀 | 面对 A 给出的 gap，另一人能否照卡完成？先做什么、交什么、如何自检？ | 逐条关联 gap 的 micro-action、预计/实际耗时、产物、验收点、失败下一步、排程前后差异 |
| 队长/C：集成与独立验收 | 数智助老、无界智泊；并负责 8 个样本的全局集成 | A/B 模块是否真实接通？实际 V2 是否改善？状态保护和复核是否成立？ | 调用日志、代码版本、模型 ID（不含密钥）、原版/新版、人工盲评、失败记录、最终验收结论 |

“嘉农芯生”“湘匠织秀”“无界智泊”为当前项目记录中的规范写法。若用户口述的“佳能新生/知秀/无界停车”指这些样本，应在样本清单里统一名称，避免分配到错误文件。A/B 是职责标签；未核实实际 GitHub 账号前，不要把职责标签当成账号身份。

### A 的批注（诊断任务）

**批注给 A：**
- 不要只交差距分析表模板；必须在 3 个指定样本上读取实际输入。
- 每个 gap 都要有 `gap_id`、当前作品版本、文件/章节/行号或其他可复查 locator、现状证据、目标条件、根因及优先级。
- 外部参考必须有来源链接和参考内容的精确位置；写清借鉴的是结构、方法还是证据，不得复制作品内容。
- 资料读不到、来源不支持、目标不清楚时，输出 `unknown/blocked` 和缺失项，不要让模型补造引用。
- 新版提交后，A 要对照原始验收条件实际读取 V2，逐条给 `pass/fail/unknown`，引用新版位置；只接收 Review JSON 不等于完成内容复核。

**A 验收门槛：** 三个样本各有可定位 gap；至少一个 V2 经 A 实际复核。原始请求、响应、来源和复核记录可追溯。未达到的项保留待办，不写“已完成”。

### B 的批注（行动规划任务）

**批注给 B：**
- 只能基于 A 的 gap 生成动作，不得自行猜测缺口或用通用三步模板顶替。
- 每一步至少填写：`input_version`、`gap_id`、`target_locator`、`action`、`reason`、`expected_change`、`output`、`self_check`、`failure_next`、`capability_basis`、`source_refs`、预计耗时。
- 第一步必须让执行者马上能动手；写清打开哪个文件、到哪个位置、改什么、交什么。不能只写“完善方案/继续学习/优化内容”。
- 如果 A 未提供可核实的 gap 或 micro_steps，任务应进入 `blocked/unscheduled`，返回缺失字段，而不是生成泛化计划。
- 记录估计耗时与真实耗时；遇到失败时更新具体动作，不覆盖已完成、已开始或待复核事项。

**B 验收门槛：** 每个已接收 gap 都有对应行动卡；找一名未参与编写的人，仅给行动卡和输入材料，不口头补充说明，观察是否能完成并产出目标文件。记录补问、卡点、实际耗时与提交版本。

### 队长/C 的批注（集成、模型、测试）

**队长本轮要亲自做：**
1. 固定本次测试的 commit、材料版本、目标判据和模型设置，防止“换了输入还沿用旧结论”。
2. 真实接通 A → B → 总控预览/采用 → 人工执行 → V2 → A 复核 → B 只重排剩余项。
3. 检查版本冲突、无效来源、模型失败、重启和临时占用场景；失败必须可见且可恢复。
4. 每个样本都留下通过/失败/未知结论，不用工程单测通过替代模型质量证明。
5. 对 A/B 交付做代码/材料双验收：指出具体文件、函数、测试结果和仍阻断的项；不替他们把未完成任务标绿。
6. 汇总 8 个样本的结果，决定保留、缩小或停止哪项创新；所有公开效果结论必须能回到原始记录。

## 5. 七步真实 AI 配置验收

每步都要保存结果。不得将固定演示内容、mock、人工参考答案或旧缓存冒充真实模型输出。

- [ ] **1. 检查模型设置**：服务商列表可读；核对官方 API 地址、接口协议和后端代理路径。公开网站不能把 localhost 作为远程 API 地址。
- [ ] **2. 读取真实模型列表**：在受信任的模型设置界面输入有效 Key，点击读取模型；保存模型 ID、响应状态和时间，不保存密钥。
- [ ] **3. 测试真实 API**：调用测试接口，要求 `verified=true` 且有成功响应；失败保留 HTTP 状态、脱敏错误和服务商，不得显示假成功。
- [ ] **4. 测试实际对话**：发送固定问题，保存请求/响应摘要、模型 ID、耗时和使用量（服务端可提供时）；核实不是本地固定字符串。
- [ ] **5. 测试真实资料**：上传小 PDF/Word/Markdown，要求指出一个确切段落并核对原文；记录解析失败、定位错误和模型误答。
- [ ] **6. 测试失败恢复**：用无效模型 ID、错误 Key 或暂时不可用端点测试；系统明确提示失败，不能静默切换模型或丢失任务进度。
- [ ] **7. 保存脱敏证据**：记录时间、commit、服务商、模型 ID、输入哈希、响应摘要、耗时、错误码、人工判断和结果文件路径。Key、Authorization 头、完整敏感请求不得提交到 GitHub。

**队长放行条件：** 以上 7 项都有可复现记录；至少一次真实对话和一次真实资料分析通过；A/B 闭环还要另行通过。只通过 API 测试不等于产品闭环通过。

## 6. 从上岸鸭转化为山东省 AI 大模型创新传播大赛作品

### 6.1 赛事要求（来自通知）

上传的《关于举办 2026 山东省首届大学生 AI 大模型创新传播大赛的通知》明确：
- 主题为“智赋齐鲁・数创营销”；
- 赛道一为 AI 视听内容创作；赛道二为 AI 传播优化应用；赛道三为 AI 传播工具创新；
- 赛道三要求围绕营销传播中的具体业务痛点或决策环节，开发具有明确应用场景、可交互验证的智能化工具原型；
- 所有赛道均须提交 AI 大模型应用说明，披露工具、使用环节和人机协作模式；
- 作品要立足山东本土场景，强调原创性、实质性创意加工和合法合规素材；
- 通知列出的作品提交期为 2026-10-15 至 2026-11-30；各赛道细则和最终安排以赛事官网为准。

### 6.2 建议的转化方向

**建议优先评估赛道三：面向山东本土企业/机构传播任务的“AI 传播内容证据诊断与迭代工具”。** 这是建议方案，不是已完成的产品或已确认的报名赛道。

用户输入一个真实的山东本土传播 brief、目标受众、产品/服务事实、既有文案/脚本/海报说明和合法参考材料。工具不只是“一键生成营销文案”，而是：
1. 识别目标、受众、平台、传播限制和需要核实的事实；
2. 将原文与目标要求逐条对照，标出具体位置、证据和未知项；
3. 生成绑定差距编号的修改卡：修改位置、原因、预期变化、输出、自检和失败处理；
4. 人工选择并修改内容，保存 V1/V2；
5. 依据预先确定的传播标准逐项复核，如事实可追溯、受众匹配、平台格式、信息完整性、行动号召清晰度和合规检查；
6. 根据未通过项局部调整，不覆盖已通过内容；
7. 输出版本对比、来源清单、人工修改记录、模型调用与评测结果。

### 6.3 哪些沿用、哪些必须改

| 原上岸鸭能力 | 转化处理 | 具体要求 |
|---|---|---|
| A 的资料诊断 | 保留机制，换传播材料 | 从“科研/竞赛差距”改为“传播 brief 与文案/脚本差距”，引用原文和真实业务事实 |
| B 的行动卡 | 保留机制，换成内容编辑动作 | 不能泛泛写“优化文案”；要定位句子/段落、明确改动、理由、预期变化和验收条件 |
| 队长总控、版本保护、复核 | 作为工具核心保留 | 展示 V1、修改记录、V2、逐项复核、剩余问题及失败恢复 |
| 学习路线、考研计划、习惯陪伴等 | 不放在比赛核心流程 | 可留在个人版，但不要冲淡传播工具的单一场景 |
| 微信/小红书/视频号等资料入口 | 只在合法可用范围内保留为输入适配器 | 不承诺读取所有私密内容；登录限制、版权、授权和不可读内容必须明确提示 |
| 自动发布、虚构传播数据、自动生成效果结论 | 不作为首版能力 | 不发布到外部平台；没有真实曝光、点击、转化数据就不声称传播效果提升 |
| 多 Agent 数量、花哨界面 | 不作为创新主张 | 创新必须由证据定位、可执行修订、版本复核和对照测试证明 |

### 6.4 必须先找的真实业务样本

不要假定某个山东企业已授权合作。先寻找可公开引用、许可清楚的本土品牌/公共服务/文化传播案例，或者征得真实需求方同意。每个案例要有 brief、目标受众、事实来源、原始内容、平台要求和可评估标准。缺少授权或关键事实时，标为模拟样本或 unknown，不冒充企业真实项目。

建议最小可行范围：**一个山东本土场景、一个内容类型、一个可交互工作流、三份可追溯案例、一个公平基线。** 例如先做“短视频传播脚本的证据与受众适配优化”，再考虑海报/长文。不能第一版同时承诺视频生成、全平台抓取、自动发布和完整营销自动化。

### 6.5 传播赛道验收指标

在测试前先定规则，测试后如实填数据：
- 事实准确性：已核查事实断言数、支持数、不支持数；
- 来源可追溯：可回到原文的引用数 / 应核查引用数；
- 标准满足度：通过的预设条件 / 全部条件；
- 人工修订：首次提交通过率、返工次数、人工改动量；
- 工作效率：主动操作分钟、等待分钟、模型调用与实际费用；
- 用户验证：真实用户完成任务数、失败/退出数及原始反馈。

对照至少包括：普通大模型直接生成；本工具完整流程。保持同一输入、同一模型或明确记录模型差异、同等调用预算和相同评判标准。若无改善，就报告并修订，不预写成功率。

### 6.6 AI 大模型应用说明应交什么

- 使用的模型/工具及版本；
- 每个环节中 AI 做什么、规则代码做什么、人做什么；
- 输入材料的来源、授权与脱敏方式；
- 提示词/工作流版本、模型调用记录和失败处理；
- 人工修改了哪些内容、为何修改；
- 如何验证事实、版权、肖像权、偏见与不良导向；
- 评测数据、失败案例、局限性与未实现功能。

## 8. 每次在 Issue #7 下汇报的格式

每位成员提交时只需按以下模板更新，避免长篇口头状态：

```text
负责人/分支：
样本与 gap_id：
改动文件/函数：
输入版本/来源：
实际运行命令或调用方式：
测试用例与预期：
```

- 是否允许进入下一阶段。

## 9. 阻断条件

以下任意一项存在，不能宣称“闭环完成”或“已达到省一水平”：
- 模型未真实连通，或固定回复被当成真实响应；
- A 的 gap 没有精确材料定位和可核对证据；
