## 使用规则

- 本文按已记录的真实样品解析报告整理，不把“解析通过”写成“创新诊断通过”，不把计划/模拟数据写成真实结果。
- 作品原件的本机路径和文件名尚未从远程设备重新核验；因此本页不伪造 PPT/Word 下载地址。待 Desktop Commander 设备恢复 Online 后，补入每个原件的仓库/可访问链接。
- A 负责证据定位与标准映射；B 负责按证据生成可独立执行的微行动卡；C/队长负责版本、执行、复核、剩余任务和证据链。
- 每个项目的行动必须绑定 V1 版本、页/段/代码位置、来源 locator；没有定位信息时标记 `unknown/blocked`，禁止套用通用三步。

## 统一的 A→B→C 执行卡字段

每个 gap / action 至少记录：

- `project_id`、当前作品路径/链接、`artifact_version` 或 hash；
- 当前作品 `current_locator`、`current_evidence`；
- 目标/官方规则来源及 `source_locator`，参考内容的 `reference_locator`；
- `extract_pattern`（只提取可迁移的方法/证据结构，不复制作品外观）；
- B 的 `input_version / target_locator / action / reason / expected_change / output / self_check / failure_next / capability_basis / source_refs`；
- 执行人、实际耗时、卡点、V2 文件与 hash；
- A 对新 V2 的逐项 `pass / fail / unknown`，B 仅重排 remaining issues，C 保存 trace。

## 验收标准

任意抽查一个项目，队友必须能从仓库中的记录直接打开对应原件，定位问题页/段和参考来源，按行动卡独立开始执行，并提交可核验 V2。缺原件链接、定位、证据、V2 或复核中的任何一环，都不能标记为闭环通过。
