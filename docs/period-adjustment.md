# 队长任务 C5：今日排满、周期完成与弹性调整

依据用户上传的《上岸鸭-产品原理与三人协作手册(8)》第 3、4、6、7、8 页。

## 分工识别

你负责 C1 公共基础、C2 调用总控、C3 执行验收、C4 困难救援、C5 变化版本、C6 集成交付。本轮聚焦 C5，并连接 C2/C3。

- B4：按截止倒推里程碑，计算周期容量；不足时给出缩范围、协作或延期方案。
- B5：用户选任务，排入真实空档，避免固定安排冲突。
- B6：接收中断、疲劳、新任务、超时、规则变化，保留成果与锁定安排，返回局部重排。
- 你的 C5：接收这些变化，触发计算，展示原计划、新计划和原因；确认后保存，支持撤销。

你不是把所有任务挪到明天，也不是无条件保证截止前完成。先检查整个周期有多少真实时间，再说明能安排多少、缺多少、哪些依赖还没满足。

## 本轮功能

总控页面新增周期调整表单：成员、起止日期、每日上限、缓冲、可分段与每段上限、周期空档、其他任务/突发占用、完全排满日期、用户勾选任务、剩余分钟、调整原因。

基础计算器 `period_planner.compute` 真实执行时间计算，供 B 后续替换或扩展；不调用模型，不冒充 B 已完成智能排程。只支持单负责人任务，跨成员共同任务交由 B 联合排程。

- 今天排满：该日不加任务，在周期内其他空档安排。
- 突发事件：从空档中扣除对应占用，保留仍符合约束的原时段。
- 不足：明确未排入分钟和依赖原因，提出缩范围、协作、允许时延期、补充真实空档等选择；不自动替用户修改目标。
- 任务时限：不安排到已知任务截止之后；未知截止明确暂按所填周期计算。
- 不可拆任务：要求连续足够的时段；可拆任务需用户确认。
- 进行中：要求填写剩余用时，不把实际用时简单当成完成量。
- 保护：不改任务成果；保留其他成员、未选任务、已完成/待验收和锁定安排。突发占用与保留安排冲突时明确报错。
- 前置未验收：保持阻塞；不把前置任务“排进日程”等同于已经完成。
- 先预览，后采用；采用后可以撤销到前一份计划，版本号继续递增。若采用后有新进度，拒绝直接撤销，防止抹掉新成果。

计算使用 Asia/Shanghai 时间。空档每行 `YYYY-MM-DD HH:MM HH:MM`，不跨午夜。每日上限包含周期内保留日程，缓冲从可分配额度中扣除；不录入的空档不擅自添加。当前为保留原安排优先的基础算法，不保证找到数学上的最优日程。

## 接口

POST `/api/agent/team/period-replan`：project_id、expected_version、expected_plan_version、reason、constraints。只保存预览。

constraints 包含 member_id、period_start/end、windows[]、busy[]、full_dates[]、daily_limit、buffer_minutes、chunk_minutes、allow_split、selected_task_ids、remaining_minutes。

返回的 proposal.plan 含 schedule_summary（所需、可用、未排分钟、每日容量、阻塞与选择）和 replanning_context。仍调用既有 `/apply` 采用。`/undo-plan` 接收 project_id 与 expected_version，在没有后续进度时恢复前一份计划。

B 可沿用相同 Plan 与 time_blocks 输出，通过既有 propose 接口提交高级排程；不修改 B 的分支。

## 验收

新增 11 项后端情景测试：今天排满转后续空档、突发占用与缓冲、截止、不可拆、保留未受影响时段、锁定冲突、前置阻塞、剩余估时、周期外原安排、重叠输入、预览/采用/撤销与进度保护。原 36 项加本轮 11 项，共 47 项通过。

浏览器脚本 `test_period_browser.cjs` 使用临时数据库和明确的示例任务，不修改真实用户计划。真实个人的截止、空档和剩余任务尚未录入，所以没有替用户编造个人日程或承诺完成日期。
