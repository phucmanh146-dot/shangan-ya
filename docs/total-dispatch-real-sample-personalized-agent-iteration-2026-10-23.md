# 总调度｜真实作品驱动的私人定制 Agent 测试、功能迭代与三人验收
更新日期：2026-10-23
总负责人：队长 C
主目标：冲击高质量国赛作品；本文件不承诺获奖，也不把计划、模拟测试或单元测试当作真实效果。

## 0. 先说结论：创新设计是否已经满足？
**设计方向有辨识度，但创新效果尚未被真实验证。** 当前方案最值得保留的差异是：
1. 根据用户手中真实作品和目标标准做差距诊断，不是生成通用学习路线。
2. 把差距变成可定位、可执行的 1–5 分钟首动作；由真人修改作品形成 V2，再按原判据独立复核。
3. 中断后接回准确项目、版本、文件位置、卡点和下一步；复核失败只重排剩余项。
4. 每次失败都进入可重复的测试集，修复后用相同输入回归。

这些目前是“创新假设/产品设计”，不是已经证实的竞赛优势。上传的《上岸鸭竞品拆解与过程干预方案（含大模型技术分析）》第 1、3、18–21 页明确记录：工程底座已有部分接口和受控测试，但没有完整真人 V1→V2→独立复核链；10 月 12 日记录里诊断 4 次成功 1 次、复核 3 次成功 0 次；真实模型配置、部署链接和真实用户数据仍有阻塞。因此不能宣称创新已成立，也不能说已经达到省一/国赛获奖水平。

## 2. 三人批注与分工

### A 同学｜材料接入、证据诊断与参考方法抽取
主责样本：嘉农芯生、滴水润疆、菌润乡土。
1. 登记真实原件链接、文件名、版本/hash、赛事年份/赛道和官方标准。缺一项就 BLOCKED，不要猜。
2. 对每个样本抽取至少 3 条 gap；每条必须指向当前作品的页/段/表格/代码 locator、原始证据、官方目标/参考来源及其 locator。
3. 将事实、推断、unknown 分开。参考获奖作品只提取结构、验证方法、证据链或呈现方式，不复制内容，不用搜索摘要代替正式标准。
4. 测解析覆盖率：文字、图片、表格、跨页、旧 DOC、ZIP、大文件；列出未解析页和漏失字段。
5. 每个失败记录复现步骤、预期/实际、根因、修改文件/函数、commit、修复前后同输入结果。
6. 交付：manifest、3+ 条证据化 gap、解析覆盖清单、人工基准、trace、缺陷单与回归结果。
验收门：B 不得对没有可靠 locator/source_refs 的 gap 生成生产行动卡。

### B 同学｜私人定制行动卡、盲执行与真实 V2
主责样本：文玩玉米、本草云联、湘匠织秀/湘秀未来。
1. 用真实 V1 + 明确目标标准运行 Agent，检查每个项目的第一步是否基于其具体材料，不能三个项目都生成“加强调研、优化方案、完善 PPT”。
2. 每条 action card 必须有 project_id / input_version / target_locator / action / reason / expected_change / output / self_check / failure_next / capability_basis / source_refs，并写 1–5 分钟首动作、依赖、预期与实际耗时。
3. 缺少 grounded micro_steps 时必须 blocked/unscheduled，不能回退通用三步。
4. 将行动卡交给非作者，不口头补充；记录是否 5 分钟内开始、实际产物、用时、求助次数和卡点原话。
5. 真实执行必须产出 V2 文件/版本/hash；不接受只截图或“已完成”文字代替作品。
6. 本草云联要区分已实现/原型/规划，模拟或非临床数据必须标记；湘匠织秀没有真实客户证据时，第一步应是需求访谈/授权核验，不可假造订单；文玩玉米需分清收入、成本、利润和单位口径。
7. 交付：行动卡、盲执行日志、V2、失败字段、修复 commit 和同输入回归。
验收门：非作者照卡能开始，且产物可被另一人按原标准复核；B 不得自我验收。

### C/队长｜集成、状态恢复、独立总验收与国赛证据
主责样本：数智助老/泉城护航、无界智泊；同时负责全局。
1. 重新核验 PR #21/#22、分支、main、部署版本、真实模型配置与工具 trace；分开写 merged / deployed / mock pass / live model pass / human loop pass。
2. 处理同名 team_recovery.py 冲突，先比较职责和调用方，再合并；不整文件覆盖、不因 PR 打开就当已集成。
3. 对数智助老核对“15 分钟响应”“效率提升 65%”的原始基线、样本、日志、口径；无证据标 unknown/目标值。
4. 对无界智泊分开记录本项目真实授权/试点证据、第三方案例和模拟路径；测试预约、冲突、结算、退款，不把模拟通过当真实业务效果。
5. 组织完整交接：A 的 evidence-based gap → B 的专属行动卡 → 非作者执行 → 真实 V2 → A/另一人独立复核 → B 只重排 fail/unknown → C 验证状态和 trace。
6. 测中断恢复、跨对话找项目、版本冲突、工具失败、重复无效策略、已完成项保护。两轮无效帮助后必须换法/求助/停止，不能无限循环。
7. 组织 5–8 位同学对照试用：同一真实任务、同标准、相近时间预算，对比普通助手与上岸鸭。记录证据可核对率、独立执行率、首个产物耗时、V2 判据通过率、恢复正确率、人工介入和成本。小样本只做探索性报告。
8. 交付：集成/部署证据、真实模型 trace、真人 V1/V2 证据包、独立复核表、试用数据、未解决阻塞与 go/revise/stop 决策。
验收门：C 不能仅凭 A/B 自评宣布成功；至少抽查一条端到端真人闭环。

## 3. 本轮优先顺序（先解决最影响国赛可信度的事）

### P0｜先证明链路真实可运行
1. 核对原件入口、runtime、分支和当前部署；记录当前版本/commit。
2. 修复/明确大文件、图片 PPT/PDF、旧 DOC、ZIP 的处理路径；按页/段切片和按需检索，不只是提高上传上限。
3. 配置真实模型并保存 trace；如果仍是 CONFIG_REQUIRED，标 BLOCKED。
4. 禁用 action_planner 的通用三步 fallback；缺证或缺 micro_steps 时 blocked/unscheduled。
5. 合并 PR #21/#22 的状态/恢复逻辑，解决同名文件冲突并跑集成测试。

### P1｜跑两条不同类型的真实私人定制闭环
先选“文玩玉米”与“数智助老”或“湘匠织秀”与“数智助老”中原件最齐、目标最清楚的两个。要求两个项目生成明显不同的第一步，并分别完成真实 V1→行动卡→盲执行→V2→独立复核。没有原件访问权的项目不能进入真实闭环统计。

### P2｜将失败变成产品改动
按失败根因修诊断器、检索/locator、action planner、上下文装配、状态寄存器、工具状态、复核门。每个修复用同一失败输入复测，再跑相关回归样本。禁止只改文案却不修实际行为。

### P3｜创新与用户效果对照
对五项机制分别记录一条成功、一条失败/边界案例：状态存档、双循环/停止条件、上下文按当前步骤装配、工具失败不伪成功、跨对话恢复准确项目。未测写 NOT_RUN。
真人试用后再决定每项创新假设 GO / REVISE / STOP，不得强行把所有设想都说成创新。

## 4. 统一状态和证据等级
- ENGINEERING_PASS：单元/集成测试通过，只证明程序规则。
- SIMULATED_MODEL_PASS：模拟数据/固定回复通过，只证明边界路径。
- LIVE_MODEL_PASS：真实模型与当前配置运行成功，保存输入/输出/工具 trace/引用。
- REAL_ARTIFACT_PASS：真实作品诊断与行动卡按冻结判据合格。
- HUMAN_LOOP_PASS：非作者照卡执行真实 V2，另一人按原标准独立复核通过。
- BLOCKED：缺配置、缺原件、缺权限、缺标准或依赖未满足。
- NOT_RUN：没有实际运行记录。
禁止跨级推断；mock/工程测试不能替代真实模型，真实模型成功也不能替代真人闭环。

## 6. 国赛质量判定
当前可支持的结论是“设计方向具有差异化潜力，但核心优势仍缺真人效果证据”。最终展示必须让评委看到：真实材料定位、项目专属动作、真人改出 V2、独立复核、中断后准确接续、失败后的可复现修复，以及真实用户对照数据。不能把参考作品的奖项或数据挪用到上岸鸭，不能把规划、mock 或单元测试说成真实业务成果。

外部方法依据：
- [Agentic AI 评测综述（Artificial Intelligence Review, 2026）](https://doi.org/10.1007/s10462-026-11571-0)：强调 benchmark 分数与真实部署之间的差距，评估要覆盖成本、鲁棒性、工作流集成与可复现性。
- [AgencyBench（ACL 2026）](https://aclanthology.org/2026.acl-long.337/)：以真实场景、具体交付物和评分 rubric 测多步 Agent 任务。
这些仅为评测方法参考，不代表上岸鸭已通过相关 benchmark。
