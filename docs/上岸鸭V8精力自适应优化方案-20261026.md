## 全量优化模块：按依赖顺序逐块实现

### 1. 精力排程闭环（第一优先级）

**输入**：用户主动自评的当前精力、时段偏好、固定日程、睡眠/疲劳自述（可选）、任务截止时间、任务认知负荷、熟练度、历史实际用时。

**排程**：
1. 先锁定上课、会议、通勤、就医等固定事项。
2. 保护用户设定的休息、吃饭、发呆、看剧和手机放松时间；这些时间不能被任务自动挤占。
3. 将需要深度思考的任务优先放在用户自己长期记录出的较高精力时段；低精力时段安排整理、收集、核对、回复等低负荷任务。
4. 根据“历史中位数 + 缓冲”估算时长，按截止日期、重要/紧急程度与依赖关系安排。
5. 超出容量时，显示哪些任务移入弹性时间、哪些顺延及原因；不擅自改截止日期、不把任务标为完成。
6. 卡壳或疲劳时提供“暂停当前任务 → 记录卡点 → 选择低负荷替代项 → 安排下一次回到原任务”的闭环，不强迫用户立即继续硬啃。

**验收**：固定事项不被覆盖；休息有独立时间块；计划超载时能明确顺延；重排前后保留原任务 ID、截止时间和状态；用户可以撤销/重新排程。

### 2. 任务时长估计与熟练度曲线（本轮开始）

任务类型与阶段应分开统计，例如视频制作拆为选题、资料核实、脚本、录制、素材整理、剪辑、字幕核验、封面发布。每条实际用时都保存类型、阶段、熟练度、估时、实际时长、是否卡壳、精力前后自评和时间戳。

统计采用中位数优先，避免极端值拉偏；同时展示样本数与数据来源。样本不足时提示“尚无可靠估计”，允许用户输入初值。比较曲线应使用同类型、同阶段、同熟练度的数据，并展示较上次减少/增加的分钟数与比例，不将耗时变化直接解释为能力或智力变化。

**验收**：没有真实记录时不出现伪造均值；至少 3 条同组记录后才推荐历史中位数；能导出原始记录；历史记录可修正；不自动覆盖用户初始估时。

### 3. 任务状态与卡壳干预

- 任务开始前询问“现在精力如何、是否第一次做、预期难点是什么”。
- 任务过程中允许标记“正常推进 / 被打断 / 卡壳 / 精力耗尽 / 临时事务”。
- 卡壳时给出一条可执行下一步，而不是要求用户无限继续；允许切换低负荷任务，并将原任务放进弹性时间。
- 重排理由可解释：截止日期、固定时间、当前精力、历史用时、依赖任务和用户手动锁定项。

**验收**：任何干预都不自动删除任务或改变硬截止日期；用户可选接受、编辑或拒绝建议。

### 4. AI 问答与任务资料关联

AI 问答的上下文应按需关联某条现有任务，携带任务目标、当前步骤、用户提供的资料和卡点。回答默认包含：先给可执行结论、步骤、验证方式、来源/读取状态；用户可以选择生成思维导图或讲解视频。视频生成需清楚标记 AI 生成内容与原始来源，不能把生成画面说成真实录屏。

资料类型独立展示，不把所有连接器堆在一个按钮里：
- 本地 Obsidian：必须通过本机桥接服务和授权读取；公网浏览器不能直接读取电脑硬盘。
- 飞书：通过已授权 API 或本机登录桥接；私有 Wiki 读取失败时显示失败原因。
- 网页 / B 站 / YouTube：显示 URL、解析状态、标题和可打开原文。
- Word / PDF / 图片 / 音视频：显示文件名、解析状态、提取文本和来源。
- 微信：仅在用户主动授权的本机桥接可用时读取；读取群目录和历史消息分开报告状态；用户确认后才提取为任务，不自动发消息。

**验收**：任何“已连接 / 已读取”状态都必须有真实请求结果；失败要给出原因和重试入口；AI 回答可以追溯到来源；任务写入必须用户确认。

### 5. 语音/录屏转任务

先将语音转写为文本，再抽取候选任务、期限、预计时长、关联项目和困难；抽取结果先展示确认卡，用户可修改后再写入原任务清单。录屏如包含聊天、界面或个人信息，应只处理用户明确选择的片段，并允许删除转写文本。

**验收**：不把不确定内容当事实；不猜截止时间；不自动发送微信；重复任务提示去重；用户确认前不写入任务。

### 6. 数据档案与个人化复盘

保留既有数据档案入口，增加可筛选的趋势：任务类型/阶段/熟练度、预计与实际时长、精力前后变化、卡壳原因、休息是否被保护、顺延原因。至少要显示样本量、时间范围和缺失值；小样本只作个人参考，不做医学结论。

### 7. Vibe Coding 作品质量参照

参考 [Vibe Coding 大赏](https://vibecodersawards.com/) 的作品展示思路，以及常见竞赛中强调的创意、真实可用性、完成度、表达清晰和 AI 原生协作过程。这里把它们当作产品自测维度，而非声称所有比赛采用同一官方评分规则。

| 维度 | 上岸鸭的验收标准 |
|---|---|
| 创意与差异化 | 真正解决“计划因疲劳/卡壳失效”的问题，而不是普通打卡清单 |
| 完成度 | 从输入任务到排程、执行、记录实际时长、校准估时完整跑通 |
| 实用性 | 用户可在 1 分钟内完成精力自评和重排；休息不会被吞掉 |
| 表达与可理解性 | 排程原因可解释，卡壳建议具体，数据不夸大 |
| AI 原生协作 | AI 帮助拆任务、检索授权资料、总结困难和生成讲解，但关键写入由用户确认 |
| 稳定性与隐私 | 原数据可保留、错误可恢复、连接状态真实、密钥不进前端或仓库 |

## 推荐实施顺序

1. 完成本轮熟练度估时与实际用时校准，并通过脚本语法和回归测试。
2. 将估时结果接入现有每日排程，统一“工作时长、缓冲时长、休息时长”三类时间。
3. 补齐卡壳/疲劳的状态机与一键重排；优先保留任务并安排弹性时间。
4. 将精力、任务阶段、熟练度、实际耗时接入数据档案趋势。
5. 统一 AI 任务上下文与来源卡片，补齐来源状态和用户确认。
6. 语音转写 → 任务草稿 → 用户确认 → 写入原任务。
7. 再做自动化推荐、视频讲解质量和更复杂的个人节律模型。

## 证据与边界

- 不存在一条适用于所有人的固定“高精力曲线”或精确的通用“黄金记忆曲线”。应以用户自评和个人历史数据逐步校准。
- 时间估计用个人真实记录、分组中位数和不确定性；不把网上“新手/老手平均用时”直接套到某个人身上。
- 精力状态是用户主动自评，不等于心理/医学诊断。不要在没有明确授权和可靠传感器的情况下声称监测到了心理状态。
- 本轮代码尚未在用户的 Windows 本机、真实登录账号和生产环境完成端到端测试；不得把分支代码描述为已部署或已验证的生产功能。
