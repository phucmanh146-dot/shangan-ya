## 2. 把“省一质量”翻译成通俗标准

| 检查项 | 通俗解释 | 证据长什么样 | 没过怎么办 |
|---|---|---|---|
| 真实问题 | 先说清楚谁遇到什么麻烦，不是先做一个看起来很厉害的页面 | 真实材料、目标用户、具体任务和原始版本 | 标 unknown，先找材料，不让AI编需求 |
| 创新差异 | 证明为什么不是直接问普通大模型就能解决 | 同一输入下的普通模型结果与上岸鸭结果对照 | 找出系统独有的证据定位、行动卡、复核等价值；没有差异就如实记录 |
| 证据质量 | 每个“这里有问题”都要指出原文哪一页、哪一段，参考资料也要给链接和位置 | 文件版本、页码/段落/代码行、来源链接、引用片段 | 没定位不算有效gap |
| 可执行性 | 另一个人照着卡片做，不用作者站旁边解释，也能交出东西 | 明确操作、修改位置、输出文件、自检方法 | “优化一下”“继续完善”退回重写 |
| 真实验证/复现 | 不只说能用，要真的运行、改出新版本，再让别人检查 | 命令、日志、V1/V2差异、独立复核、失败记录 | 只有截图或静态页面，保持未通过 |
| 稳定性与恢复 | 模型挂了、资料缺了、版本冲突时，系统要说清楚，不能假装成功 | 错误码、失败状态、恢复步骤、版本保护记录 | 有吞错/假成功就阻断 |
| 可复现与合规 | 换个人、换台电脑或重新运行，结果过程仍可核查；不泄露密钥、不乱用素材 | commit、输入版本、来源/授权、脱敏日志 | 补版本和授权证据，密钥不入库 |

## 3. A 同学：用通俗语言写的待办

A 负责先“找准问题”，不是直接替作品写一份泛泛的改进建议。

### A 每个样本要做的事
1. 找到这份作品真正的原件：PPT、报告、代码、视频或链接；写清文件名、版本、日期。
2. 写清楚这份作品原本要解决什么问题、给谁用、希望做到什么。
3. 一条一条指出具体问题：哪页/哪段/哪行不符合目标；不能只写“创新不足”。
4. 每个问题给一个编号，例如 `GAP-01`，贴上原文证据。
5. 找一个可靠的公开参考资料，说明它能借鉴的具体做法和网页/文档中的位置；只借鉴方法，不复制成品。
6. 如果原件或证据找不到，就写“待补材料/暂时无法判断”，不要让模型猜。
7. B 交回 V2 后，A 不看作者自夸的说明，直接按最初标准检查：通过、不通过、证据不足，并指出新版具体位置。

### A 的交付格式
- 原作品文件与版本：
- 目标/使用者：
- GAP编号：
- 原件具体位置：
- 原文证据：
- 参考来源与具体位置：
- 可以借鉴的方法：
- 不能直接照搬的内容：
- 建议如何验收：
- 状态：pass / fail / unknown / blocked

## 4. B 同学：用通俗语言写的待办

B 负责把 A 已经证明的问题变成“照着就能做”的小步骤，而不是自己猜一个大计划。

### B 每个样本要做的事
1. 等 A 给出有证据的 GAP 编号；没有 GAP 证据时先停下并标 blocked。
2. 每个 GAP 单独写行动卡，写清楚要改哪个文件/哪一页/哪一段。
3. 说清楚具体怎么改、为什么这样改、改完应该看到什么变化。
4. 写明交付物是什么，例如新版PPT、修改后的报告、可运行代码或测试记录。
5. 写明怎么自查：检查哪些事实、运行什么命令、对照什么标准。
6. 真正动手做出 V2，记录花了多久、遇到什么问题、哪些地方没做成。
7. 把 V1 和 V2 放在一起，让 A 独立复核；A 未通过的部分再调整，已通过的部分不要随便覆盖。

### B 的交付格式
- 对应 GAP：
- 要修改的文件/位置：
- 具体操作（一步一件事）：
- 为什么这样改：
- 预计能改善什么：
- 最终交付物：
- 自查方法：
- 失败时怎么办：
- 实际耗时/卡点：
- V1/V2位置：
- 状态：pass / fail / unknown / blocked

## 5. 队长 C：先做当前工程基线，再接入公开资料

队长先把版本与测试证据固定好，避免 A/B 在不同代码版本上工作。

- 记录分支、commit、工作区是否有未提交修改、样本输入版本。
- 当前已知远程工作副本中，`test_agent.py` 与 `test_team.py` 曾有36项测试通过；这只说明这两个模块通过，不代表真实模型或整条业务闭环通过。

- 模型配置此前显示 `configured=false`、`hasKey=false`、`verified=false`；真实模型连通、对话、文件分析、错误恢复仍需实测。
- 本轮远程设备状态显示 Offline，暂时不能声称已经在用户电脑上重新运行测试或修改本地文件；联网检索和仓库资料整理可以先完成。

## 6. 建议执行顺序

1. 队长固定代码版本并恢复可复现的 SHA/测试记录。
2. A 先交嘉农芯生的原件与一条完整 GAP 证据链，作为样板。
3. B 只根据该 GAP 写一张具体行动卡并做出真实 V2。
4. A 独立复核 V2，记录通过/不通过及原因。
5. 队长检查这条链是否完整，再把同一流程复制到其他七个样本。
6. 最后再把真实样本转为赛道三作品，按官方五项评分维度准备至少3个不同输入的真实运行案例。
