# 上岸鸭｜调研优先与闭环修复清单（2026-10-18）

依据：本仓库真实代码/测试、已上传《同类竞品》《避免同质化创新点》《竞品拆解与过程干预方案》。竞品结论来自上传资料，不把「公开资料未看到」误写为「竞品没有」。

## 先盯住的 5 个问题（按验收优先级）
1. **调研缺证据**：没有 5–8 位陌生同学同一真实任务的独立试做、失败原话和真实前后产物；先冻结调研问题与评分标准，不填虚构效果数字。
2. **首次 5 分钟启动未实测**：应提供参考样例 + 半填空 V0 + 一次 3 分钟试做；统计首次实际动手耗时和是否产出 V0。
3. **成果闭环尚无真人证据**：V1→原文定位诊断→可照做微动作→真人 V2→逐条复核→人工确认→只重排剩余 gap。模型“建议已输出”不算完成。
4. **中断接续待集成验证**：保存项目/版本/原文位置/下一微动作/返回条件；重启后回到原步骤。PR #21/#22 的 team_recovery.py 冲突由上传文档报告，尚未在当前本地分支看到合并实现，不能宣称已合并。
5. **实际模型可靠性不足**：上传材料提到诊断 4 次仅 1 次成功、复核 3 次无成功（历史记录，不等于本次复测）；需要按错误类型复测，不用夹具通过率替代真人效果。

## 竞品对照，少做重复功能
- 豆包爱学 / ChatGPT 学习模式：借鉴循序追问、换说法，但上岸鸭必须输出可核验的新作品。
- NotebookLM / 秘塔：借鉴资料解释和科普，讲完必须返回原文件位置和当下一个微动作；不以看完视频为完成。
- Goblin Tools：借鉴精细拆解，但每个动作必须带作品版本、具体位置、修改产物和自检方式。
- DeadlineOS / Agent MOSS：对齐“证据-可验证行动”和专家工作流，重点证明真实 V2 复核及中断恢复，不堆更多 Agent。

## 三条要现场验收的闭环
A. **调研闭环**：真实行为访谈→观察使用→记录失败/访谈原话→问题归类→改动→同条件再测。5–8 人初试，20 例评测集，分别标记样本规模和局限。
B. **成果闭环**：真实 V1 + 判据→带原文位置 gap→带来源的 5 分钟行动卡→真人提交 V2→逐条复核 + 人工确认→只重排未通过项。记录误放行/未知项。
C. **中断闭环**：点击听不进去/疲惫/遇阻→保存现场→提供可选帮助→返回同版本同位置继续一小步；版本变化必须提示核对。首次不依赖摄像头。

## 本轮本机代码修复
- `learning-agent/learning_agent_server.py`：修复 review_request 接口参数不匹配导致 HTTP GET 断连。
- `learning-agent/action_planner.py`：人工核对中的 production task 必须 blocked，并显示原因。
- `learning-agent/team_handoff.py`：不再将有前置依赖/外部证据阻塞的新任务一概改为 candidate。
- `learning-agent/team_orchestrator.py`：允许合法的新 blocked 任务进入预览，仍拒绝伪造完成/执行状态。
- `learning-agent/test_handoff.py`：补阻塞依赖和人工复核的回归测试。

## 调研记录字段与放行门槛
将每次试用单独记录到 `evidence/research-trial-template.csv` 的新副本，空值保持空值：匿名参与者、随机分组/基线、任务/判据、版本、关键时间、V0/V2、逐条件结果、返回同一步、误提醒、原话、评估员。
只有获得真实原始产物与可复查记录，才填写结论；5–8 人结果只说明本样本，不外推。
发布前必须通过：本地/浏览器回归 + 真实模型诊断/复核 + 至少一位非作者照卡产出 V2 + 重启接续 + 无原数据覆盖。
