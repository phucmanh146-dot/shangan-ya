# 上岸鸭：从目标走到一个真实小产物

这份工作台沿用八项目和原55项验收记录。它帮助不同基础的学生说清目标、对照当前材料、选一个可执行动作、保存卡点、上传本人修改，再请非执行者复核。提醒是辅助功能，产品目标是让学生逐步建立自己的研究方法。

## 本机使用

在本任务工作目录运行：

```text
python work/visual-workflow/server.py --workspace <任务工作目录绝对路径> --port 9010
```

仓库里的文件位于 `learning-agent/visual-workflow/`。本机数据和材料适配器依赖当前验收工作目录；迁到其他电脑需配置对应工作目录及八项目文件索引，不宣称任意克隆即可连接私有材料。

打开 `http://127.0.0.1:9010`。服务只监听本机。上下文、卡点和复核记录在任务目录 `work/workflow-state` 的SQLite内持久保存，上传小产物单独保存。不要把这些运行数据提交到GitHub。

## 已实现

- 八项目分别给出不同差距、首步和验收判据，原55项保留真实状态。
- 三个核心问题：想做到什么、现在有什么、卡在哪；可记录能力自述和已试方法。
- 先冻结判据再执行；改变目标或判据时保留旧记录并使旧提交失效。
- 缺方法、缺材料、环境报错和范围过大采用不同求助路径，不自动顺延截止。
- 上传一页/一个表（20MB以内），复核者可下载实际字节；禁止同一代号自己复核自己。
- 复核失败回到当前任务，只补未通过项；通过后保留上一轮提交和复核，开启下一步。
- 本机“读取材料，运行一次诊断”会用现有模型适配器真实调用，失败直接显示，人工草稿不会伪装成模型输出。
- 页面打开时每15秒检查截止，前10分钟询问进度；关闭页面没有后台推送保证。

## 云端预览边界

Vercel只发布HTML/CSS/JS与不含原作正文的任务种子。预览支持目标、判据、首步、卡点及浏览器本地保存。它不包含私有原作，不连接本机模型，不上传或模拟真人复核。完整材料下载、上传和真实模型按钮在本机服务使用。浏览器本地数据不会自动同步给队友。
