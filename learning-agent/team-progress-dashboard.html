高含金量 Agent 技术栈 · 当前差距

原则：不靠“多 Agent 数量”制造复杂度，而是把真实材料、工具调用、状态、证据、评测和失败恢复做实。

P0 · 现在必须补

  • 真实 V1→V2→复核→局部重排：至少一例由另一成员照卡独立完成。
  • Tool Contract：把 read_artifact / diagnose_gap / generate_micro_steps / review_artifact / replan_remaining 定义成清晰工具输入输出。
  • Trace：每次模型调用、工具调用、handoff、人工确认都可回放。
  • Evals：记录引文错误、漏检、误放行、首次照做成功率、返工次数，而不是写未经测量的提升百分比。
  • CC Heartbeat：三个真实执行窗口持续上报阶段和 blocker；当前接口已补，真实客户端接入后才算 live。

P1 · 主链稳定后补

  • MCP / Tool 标准化：GitHub、网页检索、桌面和文件工具用统一适配层，不在业务逻辑里硬编码。
  • 检索 provenance：官方规则、参考案例、建议分层，搜索摘要不能冒充已读正文。
  • 多用户 / 公网隔离：当前核心是本机回环服务；比赛若要求公开体验，再补账号、项目隔离和部署恢复。
  • Observability：成本、调用次数、失败类型、重试和人工介入次数进入看板。

P2 · 暂时别为了炫技堆

  • 没有大量历史知识检索前，不急着上向量数据库。
  • 没有明确模型瓶颈前，不急着做微调。
  • 当前自研状态机能满足主链时，不为了“技术名词”强制迁移 LangGraph；复杂度上来再迁移。
  • 不再增加无关 Agent 角色，先把 A诊断、B行动、C总调度的责任边界和证据闭环做深。

三人当前放行标准

A · 诊断/复核

不是“建议加强调研”，而是 文件版本 → 原文位置 → 当前证据 → 目标判据 → gap → unknown。V2 必须逐条件复核。

B · 行动/排程

不是“搜资料/分析/修改”三步模板，而是 位置、动作、原因、产物、自检、失败下一步、能力依据，让另一成员不问作者也能开始。

C · 总调度

不是简单串三个 Agent，而是按状态决定下一步；保留版本、人工确认、失败恢复和剩余问题，只改受影响部分。
